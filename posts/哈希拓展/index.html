常见面试题

3.1 哈希切割

3.1.1 问题一

给一个超过 100G 大小的 log file，log 中存着 IP 地址, 设计算法找到出现次数最多的 IP 地址？

🛜解决方法：

对于超过 100G 的日志文件，直接加载到内存是不可行的，既然大的不行，就把文件分割为小文件一个个进行

使用哈希函数计算将 IP 映射到不同的小文件中，确保相同 IP 进入同一个文件，对每个小文件，使用哈希表统计 IP 频率，合并所有小文件的统计结果，就能找出出现次数最多的 IP

3.1.2 问题二

与上题条件相同，如何找到 top K 的 IP ？

🛜解决方法：

既然相同 IP 一定进入同一个小文件，用 map 去统计每个文件中 IP 出现的次数即可

3.2 位图应用

3.2.1 问题一

给定 100 亿个整数，设计算法找到只出现一次的整数？

🛜解决方法：

对于 100 亿个整数（约 40GB 数据），直接加载到内存显然不可行。我们可以使用 位图 和 哈希分治 相结合的方法高效解决这个问题——双位图法

使用两个位图，每个整数对应两位：

  • 00：整数未出现
  • 01：整数出现 1 次
  • 10：整数出现 2 次及以上

假设计算出第一个数据映射第一个位置，且第一次出现，则上面的位图第一位设置为 0，下面位图的第一位设置为 1。其他情况依次类推

最后遍历位图对每一位进行 is_once 函数的判断，符合一次的存入哈希表即可

3.2.2 问题二

给两个文件，分别有 100 亿个整数，我们只有 1G 内存，如何找到两个文件交集？

🛜解决方法：

还是利用两个位图的方式解决，一个文件映射一个位图，对应的位置 & 按位与一下，两个位置都为 1，则这个位置是交集，注意存储的值应该放在 set 里去重

3.2.3 问题三

1 个文件有 100 亿个 int，1G 内存，设计算法找到出现次数不超过 2 次的所有整数

🛜解决方法：

和问题一的方法是一样的，只不过改一下表示方法而已

  • 00：整数未出现
  • 01：整数出现 1 次
  • 10：整数出现 2 次
  • 11：整数出现 3 次及以上

3.3 布隆过滤器应用

3.3.1 问题一

给两个文件，分别有 100亿个 query，我们只有 1G 内存，如何找到两个文件交集？分别给出精确算法和近似算法

🛜解决方法：

近似算法：

用文件 A 的所有 query 构建布隆过滤器，遍历文件 B 的每个 query，判断是否可能在 A 中，对布隆过滤器返回 “可能存在” 的 query，再在文件 A 中精确验证，但是这种方法并不百分百准确，可能存在误判

精确算法：

将 A、B 文件都分割为同样数量的小文件，都上好编号，因为经过相同哈希函数计算，所以 A 和 B 中相同的 query 必定分别进入 Ai 和 Bi 文件中，因此 A0 和 B0 比较，A1 和 B1 进行比较，以此类推即可

3.3.2 问题二

如何扩展 BloomFilter 使得它支持删除元素的操作?

🛜解决方法：

将标准布隆过滤器的每个二进制位扩展为一个小计数器（通常 4-8 位），当插入元素时增加计数器，删除时减少计数器。只有当计数器为 0 时，才表示该位置未被占用

五、源码解析和实践感悟

1. 位图（bitset）——用 1 bit 标记存在性

位图用一个 bit 表示一个元素的状态（存在/不存在），是空间效率最高的集合表示法。常用于去重、签到、布隆过滤器的底层。

2. 布隆过滤器——k 个哈希 + 一个位图

布隆过滤器是位图的扩展：用 k 个独立哈希函数映射到同一位图，所有位都为 1 才判定”可能存在”。核心参数：位图大小 m、哈希函数数 k、预期元素数 n。

3. 双位图统计出现次数——用 2 bit 表示 4 种状态

双位图法将每个元素的存储从 1 bit 扩展到 2 bits，可区分 4 种状态。首次出现 00→01，再次出现 01→10，第三次及以上 10→11。

实践经验

  1. 位图的内存计算公式：N 个元素的位图需要 ceil(N/8) 字节。对于 32 位整数范围（0~2^32-1），完整位图需要 512MB。这是大厂面试题”1G 内存处理 100 亿整数”的数学基础。
  2. 布隆过滤器的误判只发生在”存在”方向：返回 false 一定是真 false（无假阴性），返回 true 可能是假 true（有假阳性）。这个不对称性决定了适用场景：黑名单检查（漏判不可接受，误判可接受）、缓存穿透防护。
  3. 双重哈希技巧减少 hash 计算：k 个哈希函数不用真的实现 k 个独立哈希，而是用 h1(x) + i * h2(x) 生成 k 个伪独立哈希值。这在布隆过滤器和 Count-Min Sketch 中广泛使用。
  4. 哈希切割的精髓在于”确定性”：hash(IP) % N 保证相同 IP 必定落同一文件——不是概率性，是确定性的。这是分布式系统中分片（sharding）的基石。
  5. Counting Bloom Filter 的计数器位宽选择：4-bit 计数器最大计数值 15，适合大多数场景。超出 15 次后”粘滞”在 15（不再增长），删除时也不减——这是可接受的近似。若需要精确计数，考虑 Count-Min Sketch（也是概率数据结构）。
  6. 位图和其他数据结构的组合使用：位图做快速存在性检查（O(1)），若可能存在再用哈希表精确验证。这是”位图→哈希表”两阶段查找，广泛应用于数据库索引过滤和缓存设计中。

六、面试准备

面试问答

Q1: 位图的原理？什么时候用位图？
A: 用一个 bit 表示一个元素的存在状态，下标对应元素值。优点：极省内存（O(范围/8)字节），O(1) 存取。适用场景：(1) 元素范围有限且密集（如 0~10 亿）；(2) 只需判断存在性不需存储值；(3) 大数据去重、签到、布隆过滤器底层。不适用：元素稀疏分布极广（大量空间浪费）、需存储关联值。

Q2: 布隆过滤器的原理？误判率如何计算？
A: k 个哈希函数映射到 m 位位图，全部为 1 则”可能存在”。误判发生在：一个未插入的 key，其 k 个哈希位恰好都被其他 key 置为 1。误判率 p ≈ (1 - e^{-kn/m})^k，n 为已插入元素数。最优 k = (m/n) × ln2 时 p 最小。关键特性：无假阴性（不会漏），有假阳性（可能误判）。

Q3: 100 亿个整数（40GB）找只出现一次的数，1GB 内存怎么解？
A: 双位图法。每个整数用 2 bits：00=未出现，01=1次，10=2次，11=3次及以上。int 范围 2^32，双位图需 2 × 512MB = 1GB。遍历所有整数更新位图，最后遍历位图找出状态为 01 的所有位置。

Q4: 两个 100 亿整数的文件，1G 内存找交集？
A: 两个位图法。文件 A 映射到位图 A，文件 B 映射到位图 B。然后 A & B（按位与），结果位图中为 1 的位置就是交集。每个位图 512MB，两个正好 1GB。注意：交集结果需要去重存入 set（交集元素可能远超 1GB）。

Q5: 哈希切割（Hash Sharding）的核心原理？
A: hash(key) % N 将海量数据分散到 N 个小文件，保证相同 key 一定落入同一文件。之后每个小文件独立处理（内存放得下），最后合并结果。关键：N 的选择 = 总数据量 / 单文件可处理量。例如 100G 日志，1G 内存，N=100 即可。

Q6: 如何让布隆过滤器支持删除？
A: 将标准布隆过滤器的每个 bit 升级为 n-bit 计数器（Counting Bloom Filter）。插入时计数器+1，删除时-1，计数器为 0 表示该位无元素。缺点：(1) 内存开销 n 倍；(2) 计数器溢出（4-bit 最大 15，需”粘滞”处理）；(3) 删除可能存在并发安全问题。

Q7: 布隆过滤器在缓存穿透防护中怎么用？
A: 缓存穿透：大量查询不存在的 key，绕过缓存直接打 DB。布隆过滤器存储所有合法 key，查询时先过布隆：(1) 返回不存在→直接拒绝，不查 DB；(2) 返回可能存在→查缓存→查 DB。key 被删除时需更新布隆（Counting BF），新增 key 时插入布隆。

Q8: 100G 日志找 Top K IP——如何优化？
A: 哈希切割 + 小顶堆：先 hash(IP) % N 分文件，每个文件用 unordered_map<IP, count> 统计频率，用小顶堆维护当前 top K（堆大小=K，堆顶是最小值）。最后合并所有文件的 top K 结果。复杂度 O(N + M log K)，M 为不同 IP 总数。

陷阱与反问

陷阱 错误认知 正确理解
布隆过滤器说存在就一定存在 只能说”可能存在”，存在假阳性 布隆过滤器的否定权绝对可靠，肯定权不绝对可靠
位图只能存 0/1 两种状态 扩展为双位图（2 bits）可存 4 种状态 扩展到 n bits 可存 2^n 种状态，但内存也 n 倍增长
哈希切割的 N 越大越好 N 太大会导致小文件过多，打开文件数超系统限制 N 根据内存和数据量合理选择，通常 100-1000
Counting Bloom Filter 支持任意次数计数 计数器位宽有限（通常 4-bit），超上限会溢出 溢出后”粘滞”在最大值，只能近似
交集问题直接用 set 做就行 set 的每个元素需 ~32 字节，100 亿个需要 320GB 内存 位图用 bit 标记存在，512MB 可覆盖 42 亿范围
