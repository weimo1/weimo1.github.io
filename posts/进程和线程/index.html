进程和线程

进程、线程(重点)

进程是什么？

进程指的是一个正在运行的程序实例。程序是静态的，而进程是动态的。进程是程序段在某个数据段上的一次运行活动。比如同时打开三个了QQ程序，对应的就是三个QQ进程，程序段是一样的，而数据段不一样，因此运行的程序实例也就不一样。

进程是操作系统进行资源分配的基本单位。

进程包括了PCB进程控制块、数据段、程序段。其中PCB进程控制块是进程存在的唯一标识，对进程的创建撤销操作都是对PCB的操作。

线程是什么？

线程也称为轻量级进程，一个进程中包含多个线程，线程共享进程的资源。

线程是处理器调度的基本单位。

协程是什么？

协程可以视为用户态的轻量级线程。它允许在单个线程内实现并发操作，通过在特定的点暂停和恢复执行来达到类似多线程的效果，但不需要像线程那样进行复杂的上下文切换（涉及内核态和用户态的切换等）。

为什么有了进程还要有线程？

多个线程可以并发处理不同任务，并且可以充分利用多核cpu，并行处理。

进程虽然也可以并发，但是需要上下文切换，开销很大，线程切换的成本比进程切换的成本低很多。

进程与线程的区别总结：

  • 本质区别：进程是操作系统资源分配的基本单位，而线程是处理器任务调度和执行的基本单位。
  • 包含关系：一个进程至少有一个线程，线程是进程的一部分，所以线程也被称为轻权进程或者轻量级进程。
  • 资源开销：每个进程都有独立的地址空间，进程之间的切换会有较大的开销；线程可以看做轻量级的进程，同一个进程内的线程共享进程的地址空间，每个线程都有自己独立的运行栈和程序计数器，线程之间切换的开销小。
  • 影响关系：一个进程崩溃后，在保护模式下其他进程不会被影响，但是一个线程崩溃可能导致整个进程被操作系统杀掉，所以多进程要比多线程健壮。

什么是线程同步？

线程同步是指控制线程的执行顺序，避免多线程下共享资源冲突使用。

线程共享了进程哪些资源

线程私有资源

所属线程的栈区、程序计数器、栈指针以及函数运行使用的寄存器是线程私有的。以上这些信息有一个统一的名字，就是线程上下文，thread context。

共享资源

  • 代码区：保存的就是我们写的代码，更准确的是编译后的可执行机器指令。
  • 数据区：存放的就是所谓的全局变量
  • 堆区：堆区是程序员比较熟悉的，我们在 C/C++中用 malloc 或者 new 出来的数据就存放在这个区域，很显然，只要知道变量的地址，也就是指针，

线程同步的方式？

线程同步的方式：互斥锁、信号量机制、屏障。

  • 互斥锁，同一时刻只有一个线程可以访问共享资源。
  • 信号量，同一时刻会控制可以访问共享资源的线程数量。
  • 屏障，多个线程同时到达一个点，才会继续执行。

进程的五种状态？

创建态、就绪态、运行态、阻塞态、结束态。

获取到时间片从就绪态进入运行态；等待IO事件从运行态进入阻塞态。

线程的六种状态？

创建态、可运行态、等待态、计时等待态、阻塞态、结束态

进程间通信的方式?

  1. 匿名管道（Unnamed Pipes）：用于亲缘关系的进程间通信，如父子进程或兄弟进程。通常是单向的，用于简单的字节流传输
  2. 有名管道（Named Pipes）：可以在不相关的进程间进行通信，作为文件系统中一个特殊的文件（如磁盘文件）存在
  3. 信号（Signals）：进程间的异步通知机制，告知目标进程某个特定事件发生了。信号并不携带大量数据，更多用于控制流和简单通知
  4. 消息队列（Message Queues）：遵循先进先出，存放在内核中，只有内核重启或显式删除一个消息队列时该消息队列才会被真正删除，可实现消息的随机查询；允许复杂的数据结构传输
  5. 信号量：主要用于进程同步，确保共享资源的正确访问。信号量是计数器，通过原子操作（P/V或wait/signal操作）防止竞争条件
  6. 共享内存（Shared Memory）：允许两个或更多进程共享一块内存区域，它是最快的IPC方式之一
  7. 套接字（Sockets）：用于在计算机网络中不同主机上的进程之间的通信，尽管也可用于同一台机器上的进程间通信（称为Unix套接字）

进程切换的场景

  • 进程阻塞：当前进程在等待I/O操作，CPU可以切换到其他进程
  • 时间片耗尽：在时间片调度算法中，进程运行时间超过其他分配到时间片，操作系统会强制切换到下一个进程
  • 优先级调度：更高优先级的进程到来时，操作系统可能会中断当前进程，切换到高优先级进程
  • 同步机制：进程在等待某个资源（未获取锁）时会被刮起，操作系统切换到其他进程

进程的调度算法?

1.先到先服务调度算法：最先进入就绪队列的进程

2.短作业优先算法：估计运行时间最短的进程

3.时间片轮转算法：每个进程分配一个时间片

4.优先级调度算法：为进程分配优先级

5.多级反馈队列调度算法：综合了上述几种调度算法，既能让高优先级的得到响应又能快速完成短作业。

僵尸进程和孤儿进程?

僵尸进程：子进程终止了，但父进程没有释放子进程占用的资源，导致子进程的PCB依然存在系统中。

孤儿进程：父进程终止了，但子进程仍在运行。会将孤儿进程的父进程设置为init进程，由init进程来释放孤儿进程占用的资源。

如何看是否有僵尸进程，通过top命令，进程状态为Z的是僵尸进程。

五、源码解析和实践感悟

5.1 源码解析

PCB（进程控制块）——task_struct 的内存布局

task_struct 是进程存在的唯一标识——创建进程 = 分配 task_struct，销毁 = 释放 task_struct。僵尸进程就是：子进程已结束但父进程未 wait()，task_struct 无法释放。

进程调度——内核的 schedule() 核心

pick_next_task 调用 CFS 的 pick_next_task_fair()——从红黑树取 vruntime 最小的进程。上下文切换的代价：保存/恢复寄存器（几十 cycles）+ 切换页表（CR3）+ TLB 失效（几百 cycles）。

5.2 实践经验

  1. 进程 vs 线程的选择：IO 密集型用线程（共享地址空间，低开销），需要强隔离用进程（独立地址空间，一 crash 不影响其他）
  2. IPC 方式选择决策树：大块数据 → 共享内存，结构化消息 → 消息队列，父子进程简单通信 → 管道，跨机器 → socket
  3. 僵尸进程排查：ps aux | grep Z 找僵尸，strace -p 父进程PID 看是否卡在 wait()
  4. 孤儿进程的隐患：init(PID=1) 接管后自动回收——但如果 init 被 “坏” 进程替代则孤儿永不被回收
  5. 进程调度饥饿问题：CFS 保证公平但 SCHED_RR 实时进程可能抢走所有 CPU——chrt 命令查看进程调度策略
  6. fork 的 COW 不是万能优化：fork 后父子进程同时大量写入 → COW 退化为全复制，反而比直接复制更慢（每次写入都触发缺页异常）

六、面试准备

6.1 面试 Q&A

Q1: 进程和线程的本质区别？

进程是资源分配的基本单位（独立地址空间），线程是调度的基本单位（共享进程地址空间）。线程切换不需换 CR3——比进程切换快 5-10 倍。

Q2: 线程共享进程的哪些资源？哪些是私有的？

共享：代码段、数据段（全局变量）、堆、文件描述符。私有：栈、寄存器、程序计数器（PC）、线程本地存储（TLS）。

Q3: 进程通信（IPC）有哪些方式？各自的适用场景？

管道（父子进程简单数据）、消息队列（结构化消息，支持优先级）、共享内存（高频大数据，需自行同步）、信号量（资源计数/同步）、socket（跨网络通信）。最快：共享内存（零拷贝）。

Q4: 进程的 5 种状态及转换？

创建→就绪（获得资源）、就绪→运行（获得 CPU）、运行→阻塞（等 IO）、运行→就绪（时间片到）、运行→结束。阻塞→就绪（IO 完成）。

Q5: 僵尸进程和孤儿进程的区别？

僵尸：子进程结束，父进程未 wait()——task_struct 残留。孤儿：父进程先结束——init (PID=1) 收养并回收。僵尸占用 PID 和少量内存，孤儿自动回收无危害。

Q6: 进程调度算法有哪些？

FCFS（先来先服务）、SJF（最短作业优先）、RR（时间片轮转）、优先级调度、多级反馈队列（综合方案）。Linux CFS 是公平调度——选 vruntime 最小的进程。

Q7: fork() 和 vfork() 的区别？

fork() 父子独立地址空间（COW），并行执行。vfork() 子进程直接复用父进程地址空间且父进程阻塞直到子进程 exec/exit——省去 COW 页表拷贝，专为 fork+exec 优化。

Q8: 线程同步的几种方式？

互斥锁（mutex）：排他访问；信号量（semaphore）：控制并发数；条件变量（condvar）：等待条件触发；屏障（barrier）：所有线程到达同一点才继续。

6.2 常见陷阱与面试反问

  1. 陷阱：多线程 fork → 子进程只有调用线程，其他线程的锁永远不解锁。修复：fork 后用 pthread_atfork handler 或在子进程立即 exec。

  2. 陷阱：信号量误用为互斥量 → 信号量无所有者概念，其他线程可解锁你的锁。修复：互斥场景用 mutex。

  3. 反问：「协程和线程的区别？」希望听到：线程是 OS 调度（抢占式），协程是用户态调度（协作式）。协程切换不涉及内核，比线程快一个数量级。

  4. 反问：「什么时候用多进程而不是多线程？」希望听到：需要强隔离（浏览器 tab）、不同语言/运行时、CPU 密集型且不需要频繁通信。
