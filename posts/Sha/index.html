Sha

适用范围：项目基础库中的 SHA 系列哈希算法（SHA-1/SHA-256 等）实现

一、项目/模块概述

  • 模块定位：项目基础库中的 SHA 系列安全哈希算法实现，提供 SHA-1、SHA-256 等摘要计算能力。通常与 MD5 模块并列，构成哈希摘要工具链。
  • 技术栈与依赖：纯 C++ 标准库实现，无外部依赖
  • 模块边界：
    • 输入：任意长度字节序列
    • 输出：固定长度摘要（SHA-1: 160bit, SHA-256: 256bit）
    • 上下游：被需要数据完整性校验、数字签名（需结合非对称加密）的模块调用

二、架构设计（≥200字）

第一层：整体架构

SHA 系列算法统一遵循 Merkle-Damgård 构造：

  • 消息分块（512bit/块 对应 SHA-1/256，1024bit/块 对应 SHA-512）
  • 逐块压缩（每块与当前哈希状态混合）
  • 最终输出（最后一个块处理完毕后的状态即为摘要）

第二层：关键流程

  1. Padding（填充）：消息末尾添加 1 位 + 若干 0 位 + 64bit 原始消息长度，使填充后总长度为块大小的整数倍
  2. 逐块压缩：对每 512bit 块执行压缩函数（SHA-1: 80 轮，SHA-256: 64 轮），每轮包含位移、异或、与或非等位操作
  3. 输出：将最终状态按大端序输出为字节序列

第三层：关键设计决策

设计决策 SHA-1 SHA-256
输出长度 160bit 256bit
轮数 80 64
安全性 已破解（SHAttered 2017） 目前安全
使用场景 仅用于兼容性 推荐使用

补充：SHA-1 于 2017 年被 Google 的 SHAttered 攻击正式破解（构造了两个不同 PDF 文件具有相同 SHA-1 哈希）。NSA 设计 SHA-1 时声称需 2^80 次操作才能碰撞，但实际攻击只需 2^63 次。SHA-256 目前抵抗所有已知攻击，是 TLS、Git、Bitcoin 等核心基础设施的默认哈希选择。

四、工程实践（≥500字）

4.1 与项目中其他模块的集成方式

  • 与 MD5 模块并列，提供统一的哈希摘要接口——上层通过抽象基类或模板参数选择具体算法
  • 数据完整性校验：文件/网络数据包附带 SHA-256 摘要，接收方验证
  • Git 底层：Git 使用 SHA-1（正在迁移至 SHA-256）标识 commit/blob/tree 对象

4.2 生产环境考量

安全性

  • SHA-1 禁止用于新系统的安全场景——仅保留用于兼容旧协议
  • SHA-256 目前安全，但后量子时代可能需要 SHA-3（Keccak）或 SHAKE 系列
  • 用于密码存储时，不应直接 SHA 密码，而应使用 bcrypt/scrypt/argon2（带盐+慢哈希）

性能

  • SHA-256 比 SHA-1 慢约 1.5-2×（64 轮 vs 80 轮，但 SHA-1 单轮更简单）
  • 硬件加速：Intel SHA Extensions（Ice Lake+）提供 SHA-1/SHA-256 硬件指令
  • 对大文件应使用流式处理——分块读取+增量更新，而非一次性加载全文件

4.3 常见优化策略

  • 使用 SIMD 实现并行处理多个块的压缩（Intel SHA Extensions）
  • 预计算轮常量表，避免运行时计算
  • 对固定前缀的重复哈希（如 HMAC），缓存中间状态

五、源码解析和实践感悟（≥1000字）

5.1 SHA-256 的数学安全性

SHA-256 的 256bit 输出意味着暴力碰撞需要约 2^128 次操作（生日攻击）。这是宇宙级别的数字——即使动用全球所有计算资源，在宇宙寿命内也无法完成。SHA-256 的安全性建立在三个密码学属性上：抗原像攻击（单向）、抗第二原像攻击、抗碰撞。

5.2 难点与易错点

陷阱1：填充的长度编码字节序

陷阱2：SHA-1 的”安全”错觉

5.3 经验总结

  1. SHA-256 是当前最小推荐安全级别——SHA-1 已死，MD5 更不用说
  2. 哈希用途决定安全需求——数据去重用 SHA-256 没问题，密码存储必须用慢哈希
  3. 流式 API 是工程必需的——Init → Update(可多次) → Final 模式支持大文件和网络流
  4. 哈希算法迟早会被攻破——系统设计时应允许算法升级（如 Git 从 SHA-1 到 SHA-256 的迁移计划）

六、面试准备（≥10问法+5反问+5一句话，均带回答）

6.1 高频问法（≥10个）

Q1：SHA-1 和 SHA-256 的主要区别？
A：SHA-1 输出 160bit，80 轮压缩，已被破解。SHA-256 输出 256bit，64 轮压缩但单轮更复杂，目前安全。SHA-256 是 SHA-2 家族的一员。

Q2：SHA-256 的 Merkle-Damgård 构造原理？
A：消息经填充后分固定大小块，每块与前一块的压缩结果一起输入压缩函数，初始向量为固定常数，最终压缩结果即为哈希值。该构造的缺点是容易受到长度扩展攻击（length extension attack）。

Q3：为什么 Git 要迁移到 SHA-256？
A：因为 SHA-1 已可被碰撞攻击——攻击者可以构造两个不同的 commit 具有相同 SHA-1 值，破坏 Git 的内容寻址模型。Git 已从 2020 年开始支持 SHA-256 仓库。

Q4：HMAC 和普通 SHA 的区别？
A：HMAC = Hash-based MAC，通过在密钥与消息之间引入双重哈希（内外层）防止长度扩展攻击和密钥恢复。公式：HMAC(K,m) = H((K⊕opad) || H((K⊕ipad) || m))。

Q5：SHA 填充规则是什么？
A：消息末尾追加 1 个 1 位，然后追加足够多的 0 位，使填充后总长度 ≡ 块大小 - 64bit（SHA-256 中为 448 mod 512），最后附加 64bit 原始消息长度（大端序）。

Q6：MD5 vs SHA-1 vs SHA-256 的性能对比？
A：MD5 最快（64 轮简单操作），SHA-1 次之（80 轮），SHA-256 最慢（64 轮但每轮更复杂）。具体倍数：MD5 ≈ 1.0×, SHA-1 ≈ 1.5×, SHA-256 ≈ 2.5×。

Q7：什么是 SHA-3，和 SHA-2 有什么不同？
A：SHA-3 基于 Keccak 海绵构造（sponge construction），而非 Merkle-Damgård。海绵构造天然抵抗长度扩展攻击，且支持可变长度输出（SHAKE 模式）。SHA-3 是为 SHA-2 被攻破准备的备选方案。

Q8：SHA-256 的输出能否反向推导输入？
A：理论上不能——SHA-256 设计为抗原像攻击（单向函数），目前没有已知的有效方法从 256bit 摘要恢复任意长度原文。暴力搜索 2^256 种可能远超计算能力。

Q9：如何使用 C++ 标准库计算 SHA-256？
A：C++ 标准库尚无 SHA 实现。常用方案：OpenSSL（EVP_MD_CTX）、Crypto++、自己实现。项目中通常封装为流式 API（Init/Update/Final）。

Q10：为什么比特币使用双 SHA-256？
A：挖矿需要计算 SHA256(SHA256(block_header))。双重哈希的原因：1) 防止长度扩展攻击；2) 增加计算工作量而不改变输出格式；3) 历史原因（中本聪的设计选择）。

6.2 反问点/陷阱点（≥5个）

  • 贵团队的 Git 仓库是否已开启 SHA-256 迁移？如何看待这个迁移的时间线？

  • 在你们的后端服务中，哪些场景仍在使用 SHA-1？是否有淘汰计划？

  • 陷阱问题1：”SHA-256 加密的数据能解密吗？”——不能，SHA 是哈希（摘要），不是加密。加密是可逆的，哈希不可逆。这是最常见的概念混淆。

  • 陷阱问题2：”用 SHA-256 存储密码安全吗？”——不安全。SHA-256 设计目标就是快，攻击者可以每秒尝试数十亿次暴力破解。密码存储必须用 bcrypt/scrypt/argon2 等慢哈希+盐。

  • 陷阱问题3：”SHA-256 摘要可以截断用于校验吗？”——某些场景可以（如 Git 允许短 SHA），但安全场景不行——截断后的碰撞概率指数级上升。

6.3 一句话答案（≥5个）

  • 该模块的核心设计理念是：Merkle-Damgård 构造——分块压缩、链接状态、最终输出。

  • SHA-256 最重要的安全属性是：抗原像攻击、抗碰撞，当前无已知有效攻击。

  • 避免的常见错误是：将哈希当加密使用、用快速哈希存储密码、在新系统中使用 SHA-1。

  • 与 MD5 模块的关系是：同一接口体系，不同安全级别——MD5 用于非安全场景，SHA-256 用于安全场景。

  • 这个设计的最大优点是数学上的严格安全保障；最大代价是相比 MD5 和 SHA-1 约 1.5-2.5× 的性能开销。

  • 当被问到”SHA-256 能破解吗？”——回答：”目前不能。暴力破解需要 2^128 次操作（生日攻击），这在物理上不可行。但密码学没有绝对——未来量子计算（Grover 算法）可将搜索降到 2^128→2^85，仍不现实但更接近可行。”
