# 模版元编程与函数式

> 适用范围：C++模板函数、模板参数（类型/整数）、编译期计算、constexpr、SFINAE、变参模板、折叠表达式

## 一、核心概念

- **定义**：模板元编程(TMP)是利用C++模板系统在编译期执行计算的技术。模板不是代码，而是代码的"蓝图"——编译器在实例化时根据模板生成具体类型的代码
- **关键词**：模板实例化、编译期常量、SFINAE、变参模板、折叠表达式、constexpr、两阶段编译、依赖名
- **适用场景/边界**：
  - 编写类型无关的通用容器/算法（std::vector, std::sort）
  - 编译期计算（阶乘、斐波那契、类型列表操作）
  - 类型萃取与静态断言（std::is_integral_v, static_assert）
  - 高性能计算（避免虚函数、分支预测失败）
  - 边界：过度使用导致编译慢、二进制膨胀、错误信息难以阅读

## 二、详细解析（≥200字）

### 2.1 基本工作原理（三层递进）

**第一层：模板是代码生成器**。`template <class T>` 声明一个类型参数 T，编译器在调用点根据实参类型生成一份具体代码。这是编译期多态（静态多态），零运行时开销。

**第二层：两阶段编译**。阶段1（模板定义时）检查非依赖名——不依赖模板参数的语法直接检查；阶段2（实例化时）检查依赖名——依赖模板参数的语法在 T 确定后才检查。这解释了为什么模板代码必须放在头文件：编译单元需要看到完整定义才能实例化。

**第三层：SFINAE 与编译期分支**。替换失败不是错误(Substitution Failure Is Not An Error)：当模板参数替换导致语法无效时，编译器从候选集中移除该重载而非报错。配合 `std::enable_if`、`if constexpr`(C++17)、`concepts`(C++20) 实现编译期条件选择。

### 2.2 模板 vs 面向对象的多态

为什么面向对象在HPC(高性能计算)不如函数式和元编程香了？

传统面向对象思想下，令 Int, Float, Double 继承 Numeric 接口类，`multiply(int)` 作为虚函数。问题：
1. 虚函数调用有间接跳转开销
2. 需要为每个类型重复定义，每个运算符都声明纯虚函数
3. 不同参数类型的排列组合（如 `3.14f * 3`）违背开闭原则

模板方案：`template <class T> T twice(T t) { return t * 2; }`——编译器自动为每种类型生成特化版本，零运行时开销。

### 2.3 编译期常量的核心价值

`template <int N>` 传入的 N 是编译期常量。每个不同 N 编译器单独生成一份代码，可做针对性优化：
- `show_times<0>()` 可优化为空函数
- `if constexpr (debug)` 在 false 分支完全不生成代码
- 与 `func(int N)`（运行期常量）的关键区别：前者让编译器有更多优化空间

代价：过度使用导致二进制膨胀、编译变慢（Boost 编译慢即源于大量模板）。

## 三、动手实践（代码案例)

## 1 template

### 1.1 为什么需要模板函数 (template)

答: 避免重复写代码。

比如，利用重载实现“将一个数乘以2”这个功能，需要:

```
int twice(int t) {
    return t * 2;
}

float twice(float t) {
    return t * 2;
}

double twice(double t) {
    return t * 2;
}

int main() {
    std::cout << twice(21) << std::endl;
    std::cout << twice(3.14f) << std::endl;
    std::cout << twice(2.718) << std::endl;
}
```

为什么面向对象在HPC(高性能计算)不如函数式和元编程香了？

这个例子要是按传统的面向对象思想，可能是这样:

* 令 Int, Float, Double 继承 Numeric 接口类并实现，其中`multiply(int)`作为虚函数。然后定义:

```
Numeric *twice(Numeric *t) {
    return t->multiply(2);
}
```

且不说这样的性能问题，你忍得住寂寞去重复定义好几个，然后每个运算符都要声明一个纯虚函数吗？

而且,`Float`的乘法应该是`multiply(float)`, 你也去定义好几个重载吗？

定义为`multiply(Numeric *)`的话依然会违背你们的`开闭原则`:

* 比如`3.14f * 3`, 两端是不同的类型, 怎么处理所有可能类型的排列组合？

不如放弃类和方法的概念，欣然接受全局函数和重载。

### 1.2 模板函数: 定义

使用`template <class T>`其中 T 可以变成任意类型。

调用时`twice<int>`即可将 T 替换为 int。

```
template <class T>
T twice(T t) {
    return t * 2;
}

int main() {
    std::cout << twice<int>(21) << std::endl;
    std::cout << twice<float>(3.14f) << std::endl;
    std::cout << twice<double>(2.718) << std::endl;
}
```

C++

注意有的教材上写做: `template <typename T>`是完全等价的，只是个人喜好不同。

### 1.3 模板函数: 自动推导参数类型

那这样需要手动写`<int>`, `<float>`用起来还不如重载方便了？

别担心，C++ 规定:

* 当模板类型参数 T 作为函数参数时，则可以省略该模板参数。自动根据调用者的参数判断。

```
template <class T>
T twice(T t) {
    return t * 2;
}

int main() {
    std::cout << twice(21) << std::endl;
    std::cout << twice(3.14f) << std::endl;
    std::cout << twice(2.718) << std::endl;
}
```

### 1.4 模板函数: 特化的重载

有时候，一个统一的实现（比如 t \* 2）满足不了某些特殊情况。比如`std::string`就不能用乘法来重复，这时候我们需要用 t + t 来替代，怎么办呢？

没关系，只需添加一个`twice(std::string)`即可，他会自动和已有的模板`twice<T>(T)`之间相互重载。

```
template <class T>
T twice(T t) {
    return t * 2;
}

std::string twice(std::string t) {
    return t + t;
}

int main() {
    std::cout << twice(21) << std::endl;
    std::cout << twice(3.14f) << std::endl;
    std::cout << twice(2.718) << std::endl;
    std::cout << twice("hello") << std::endl;
}
```

但是这样也有一个问题，那就是如果我用`twice(“hello”)`这样去调用，他不会自动隐式转换到`std::string`并调用那个特化函数，而是会去调用模板函数`twice<char *>(“hello”)`, 从而出错。

可能的解决方案: SFINAE。

### 1.5 模板函数: 默认参数类型

但是如果模板类型参数 T 没有出现在函数的参数中，那么编译器就无法推断，就不得不手动指定了。

但是，可以通过:

```
template <class T = int>
```

表示调用者没有指定时，T 默认为 int。

```
template <class T = int>
T two() {
    return 2;
}

int main() {
    std::cout << two<int>() << std::endl;
    std::cout << two<float>() << std::endl;
    std::cout << two<double>() << std::endl;
    std::cout << two() << std::endl;  // 等价于 two<int>()
}
```

### 1.6 模板参数: 整数也可以作为参数

```
template <class T>
```

可以声明类型 T 作为模板尖括号里的参数。除了类型，任意整数也可以作为模板参数:

```
template <int N>
```

来声明一个整数 N 作为模板参数。

不过模板参数只支持整数类型（包括 enum）。

浮点类型、指针类型，不能声明为模板参数。自定义类型也不可以，比如:

```
template <float F, glm::vec3 V>  // 错误！
```

示例:

```
template <int N>
void show_times(std::string msg) {
    for (int i = 0; i < N; i++) {
        std::cout << msg << std::endl;
    }
}

int main() {
    show_times<1>("one");
    show_times<3>("three");
    show_times<4>("four");
}
```

### 1.7 模板参数: 多个模板参数

`int N`和`class T`可以一起使用。

你只需要指定其中一部分参数即可，会自动根据参数类型(`T msg`)、默认值(`int N = 1`)，推断尖括号里没有指定的那些参数。

```
template <int N = 1, class T>
void show_times(T msg) {
    for (int i = 0; i < N; i++) {
        std::cout << msg << std::endl;
    }
}

int main() {
    show_times("one"); // 打印 1 个 "one"
    show_times<3>(42); // 打印 3 个 42
    show_times<4>('%');// 打印 4 个 '%'
}
```

### 1.8 模板参数: 参数部分特化

1. `func(T t)`完全让参数类型取决于调用者。
2. `func(vector<T> t)`这样则可以限定仅仅为`vector`类型的参数。

这里用了`const &`避免不必要的的拷贝。

```
template <class T>
T sum(std::vector<T> const &arr) {
    T res = 0;
    for (int i = 0; i < arr.size(); i++) {
        res += arr[i];
    }
    return res;
}

int main() {
    std::vector<int> a = {4, 3, 2, 1};
    std::cout << sum(a) << std::endl;
    std::vector<float> b = {3.14f, 2.718f};
    std::cout << sum(b) << std::endl;
}
```

不过，这种部分特化也不支持隐式转换。

### 1.9 为什么要支持整数作为模板参数: 因为是编译期常量

* 你可能会想，模板只需要支持`class T`不就行了？

+ 反正`int N`可以作为函数的参数传入，模板还不支持浮点。

```
template <int N>
void func();
// 和
void func(int N);
```

一个是模板参数，一个是函数参数，有什么区别？有很大区别！

`template <int N>`传入的 N，是一个编译期常量，每个不同的 N，编译器都会单独生成一份代码，从而可以对他做单独的优化。

而`func(int N)`，则变成运行期常量，编译器无法自动优化，只能运行时根据被调用参数 N 的不同。

比如`show_times<0>()`编译器就可以自动优化为一个空函数。因此模板元编程对高性能编程很重要。

通常来说，模板的内部实现需要被暴露出来，除非使用特殊的手段，否则，定义和实现都必须放在头文件里。

但也正因如此，如果过度使用模板，会导致生成的二进制文件大小剧增，编译变得很慢等。(boost 编译慢的原因找到了...因为他们用了大量的模板。)

## 2 constexpr

### 2.1 模板的应用: 编译期优化案例

在右边这个案例中，我们声明了一个`sumto`函数，作用是求出从 1 到 n 所有数字的和。

用一个`debug`参数控制是否输出调试信息。

```
int sumto(int n, bool debug) {
    int res = 0;
    for (int i = 1; i <= n; i++) {
        res += i;
        if (debug)
            std::cout << i << "-th: " << res << std::endl;
    }
    return res;
}

int main() {
    std::cout << sumto(4, true) << std::endl;
    std::cout << sumto(4, false) << std::endl;
    return 0;
}
```

但是这样`debug`是运行时判断，这样即使是`debug`为`false`也会浪费 CPU 时间。

* 因此可以把`debug`改成模板参数，这样就是编译期常量。编译器会生成两份函数`sumto<true>`和`sumto<false>`。前者保留了调试用的打印语句，后者则完全为性能优化而可以去掉打印语句。

后者其实在编译器看来就是 `if (false) std::cout << ...` 这样显然是会被他自动优化掉的。(但是如果是远古的垃圾编译器可能不会, 因此:)

### 2.2 模板的应用: 编译期分支

更进一步，可以用`C++17`的`if constexpr`语法([编译期if表达式](https://hengxin666.github.io/HXLoLi/docs/%E7%A8%8B%E5%BA%8F%E8%AF%AD%E8%A8%80/C++/tmp%E4%B8%B6C++%E4%B8%B6memo/C++%E6%96%B0%E7%89%B9%E6%80%A7/C++17%E5%B8%B8%E7%94%A8%E6%96%B0%E7%89%B9%E6%80%A7/%E7%BC%96%E8%AF%91%E6%9C%9Fif%E8%A1%A8%E8%BE%BE%E5%BC%8F/))，保证是编译期确定的分支:

```
template <bool debug>
int sumto(int n) {
    int res = 0;
    for (int i = 1; i <= n; i++) {
        res += i;
        if constexpr (debug) {
            std::cout << i << "-th: " << res << std::endl;
        }
    }
    return res;
}

int main() {
    std::cout << sumto<true>(4) << std::endl;
    std::cout << sumto<false>(4) << std::endl;
    return 0;
}
```

### 2.4 模板的难题: 编译期常函数

编译期 constexpr 的表达式，一般是无法调用其他函数的:

|  |
| --- |
| ##container## |
|  |

解决: 如果能保证`isnegative`里都可以在编译期求值，将他前面也标上`constexpr`即可:

```
template <bool debug>
int sumto(int n) {
    int res = 0;
    for (int i = 1; i <= n; i++) {
        res += i;
        if constexpr (debug) {
            std::cout << i << "-th: " << res << std::endl;
        }
    }
    return res;
}

constexpr bool isnegative(int n) {
    return n < 0;
}

int main() {
    constexpr bool debug = isnegative(-2014);
    std::cout << sumto<debug>(4) << std::endl;
    return 0;
}
```

注意: `constexpr`函数不能调用`non-constexpr`函数。而且`constexpr`函数必须是内联(`inline`)的，不能分离声明和定义在另一个文件里。标准库的很多函数如`std::min`也是`constexpr`函数，可以放心大胆在模板尖括号内使用。

Tip

一般来说，我会建议模板不要分离声明和定义，直接写在头文件里即可。如果分离还要罗列出所有模板参数的排列组合，违背了`开闭原则`。

这是因为编译器对模板的编译是惰性的，即只有当前`.cpp`文件用到了这个模板，该模板里的函数才会被定义。而我们的`sumto.cpp`中没有用到`sumto<>`函数的任何一份定义，所以`main.cpp`里只看到`sumto<>`函数的两份声明，从而出错。

解决:

* 在看得见`sumto<>`定义的`sumto.cpp`里，增加两个显式编译模板的声明:

```
template <bool debug>
int sumto(int n) {
    int res = 0;
    for (int i = 1; i <= n; i++) {
        res += i;
        if constexpr (debug)
            std::cout << i << "-th: " << res << std::endl;
    }
    return res;
}

template int sumto<true>(int n);
template int sumto<false>(int n);
```

### 2.6 模板的惰性: 延迟编译

要证明模板的惰性，只需看这个例子:

```
template <class T = void>
void func_that_never_pass_compile() {
    "字符串" = 2333;
}

int main() {
    return 0;
}
```

要是编译器哪怕细看了一眼: 字符串怎么可能被写入呢？肯定是会出错的。

但是却没有出错，这是因为模板没有被调用，所以不会被实际编译！

而只有当`main`调用了这个函数，才会被编译，才会报错！

用一个假模板实现延迟编译的技术，可以加快编译的速度，用于`代理模式`等。

### 2.7 模板函数: 一个例子

```
template <class T>
void print(std::vector<T> const &a) {
    std::cout << "{";
    for (size_t i = 0; i < a.size(); i++) {
        std::cout << a[i];
        if (i != a.size() - 1)
            std::cout << ", ";
    }
    std::cout << "}" << std::endl;
}

int main() {
    std::vector<int> a = {1, 4, 2, 8, 5, 7};
    print(a);
    std::vector<double> b = {3.14, 2.718, 0.618};
    print(b);
    return 0;
}
```

## 四、进阶应用（≥500字）

### 4.1 编译期优化实战：debug 参数模板化

将 `bool debug` 从函数参数变为模板参数 `template <bool debug>`，编译器生成两份独立函数：
- `sumto<true>`：保留 cout 调试语句
- `sumto<false>`：编译器优化后完全消除 if(false) 分支，零性能开销

C++17 的 `if constexpr(debug)` 语法进一步保证编译期分支确定性，不会在 false 分支引入未实例化的依赖名错误。

### 4.2 模板惰性编译的应用

```c++
template <class T = void>
void func_that_never_pass_compile() {
    "字符串" = 2333;  // 明显错误的代码
}
// 只要不调用，就不会编译——证明模板的惰性
```

利用模板惰性可以实现**延迟编译**技术，用于代理模式、条件编译等。

### 4.3 constexpr 函数的约束与演进

- **C++11**：constexpr 函数只能包含单个 return 语句
- **C++14**：放宽为可含多条语句、循环、条件分支
- **C++17**：支持 lambda 标记为 constexpr
- **C++20**：支持 `constexpr new`、`constexpr vector`、`constexpr string`

关键约束：constexpr 函数不能调用 non-constexpr 函数；必须内联(inline)；不能分离声明与定义。标准库的大部分算法和容器在 C++20 已全面 constexpr 化。

### 4.4 模板分离编译的解决方案

模板通常放在头文件中以支持任意类型实例化。若需分离编译，使用**显式实例化声明**：

```c++
// sumto.cpp 中显式实例化所有需要的版本
template int sumto<true>(int n);
template int sumto<false>(int n);
```

但这违背开闭原则——每新增一种参数组合都要修改 .cpp 文件。权衡：头文件定义（灵活性）vs 显式实例化（编译速度/隐藏实现）。

### 4.5 与其他主题的关联

- **折叠表达式**（C++17）：变参模板的语法糖，`(args + ...)` 一行替代递归解包，编译器展开为零开销
- **std::enable_if / SFINAE**：编译期条件选择，在类型萃取中大量应用
- **C++20 Concepts**：替代 SFINAE，提供约束模板参数的声明式语法，错误信息可读性好 10 倍
- **类型萃取(type_traits)**：`std::is_integral_v<T>`、`std::remove_reference_t<T>` 等是模板元编程的基础设施
- **if constexpr**：替代传统的标签分发(tag dispatch)和 enable_if 重载，代码更清晰直观

### 4.6 常见优化策略

- **编译期计算替代运行时计算**：`constexpr` 阶乘/斐波那契在编译期完成
- **折叠表达式替代递归展开**：减少模板实例化深度，编译更快
- **Concepts 约束模板参数**：减少 SFINAE 回退链，加速重载决议
- **避免过度模板化**：非性能敏感代码优先运行时方案（可读性 > 编译期优化）
- **显式实例化**：在多编译单元项目中减少重复实例化开销


## 五、源码解析和实践感悟

### 5.1 模板实例化的两阶段编译

```c++
template<typename T>
void foo(T t) {
    t.undeclared();    // Phase 1：非依赖名，立即检查 → 报错！
    t.push_back(42);   // Phase 2：依赖名，实例化时检查
}
// 阶段1：模板定义时检查不依赖T的语法
// 阶段2：实例化时检查依赖T的部分，实现延迟编译
```

### 5.2 SFINAE 的核心原理

```c++
template<typename T>
auto f(T t) -> decltype(t.foo(), void()) {  // 如果 T::foo 不存在
    t.foo();                                 // substitution failure
}                                            // → 从候选集移除，非编译错误

template<typename T>
void f(T t) { /* fallback */ }  // 回退版本

struct A { void foo() {} };
struct B {};
f(A());  // 调用第一个
f(B());  // 第一个 substitution failure → 调用 fallback
```

### 5.3 std::enable_if 的实现

```c++
template<bool B, typename T = void>
struct enable_if {};

template<typename T>
struct enable_if<true, T> { using type = T; };

// 用法：
template<typename T,
         typename = std::enable_if_t<std::is_integral_v<T>>>
void process(T t) { /* 仅整数可调用 */ }
```

### 5.4 变参模板与折叠表达式实现

```c++
// C++11 递归解包
template<typename T>
T sum(T t) { return t; }
template<typename T, typename... Args>
T sum(T t, Args... args) { return t + sum(args...); }

// C++17 折叠表达式（编译器展开，零递归开销）
template<typename... Args>
auto sum(Args... args) { return (args + ...); }
// 展开为：a + b + c + d
```

### 5.5 实践经验

1. **模板代码放头文件**：模板非真正编译单元，而是"模式"。分离编译需显式实例化声明。
2. **概念（Concepts）替代 SFINAE**：C++20 的 `requires` 约束比 enable_if 可读性好 10 倍，错误信息友好。
3. **if constexpr 替代标签分发**：`if constexpr (is_integral_v<T>)` 比 `enable_if` 重载清晰。
4. **编译爆炸问题**：变参模板每个组合实例化一次，过多的排列可能导致编译时间指数增长。
5. **decltype 尾置返回**：`auto f() -> decltype(...)` 可在推导前使用参数名，比前置 decltype 更灵活。
6. **模板元编程适度使用**：非性能敏感代码优先运行时方案（可读性 > 编译期优化）。


## 六、面试准备

### Q&A（11题）

**Q1: 模板的两阶段编译是什么？**
A: 阶段1（定义时）检查非依赖名；阶段2（实例化时）检查依赖名。delayed compilation。

**Q2: SFINAE 的原理？**
A: Substitution Failure Is Not An Error：模板参数替换失败时不报错，而是从候选集合中移除该重载。

**Q3: enable_if 如何实现？**
A: 偏特化 `enable_if<true, T>` 有 type 成员，`enable_if<false, T>` 无 type，触发 SFINAE。

**Q4: 变参模板的实现方式？**
A: C++11 递归解包（递归基例 + 递归调用）；C++17 折叠表达式 `(... op args)` 一行搞定。

**Q5: 折叠表达式有哪些形式？**
A: 右折叠 (args op ...)、左折叠 (... op args)、二元左右折叠 (args op ... op init)。支持所有二元运算符。

**Q6: 模板特化 vs 偏特化？**
A: 全特化 `template<> class Foo<int>` 覆盖所有参数；偏特化 `template<T> class Foo<T*>` 覆盖部分模式。

**Q7: 模板元编程 vs constexpr 的选择？**
A: C++11/14 用模板递归；C++14/17 起优先 constexpr（可读性好）；类型操作（type_traits）仍需模板。

**Q8: Forwarding Reference（万能引用）是什么？**
A: `template<typename T> void f(T&& t)` 中的 T&& 是万能引用（未加 const 的右值引用语法）。最佳搭配 std::forward<T>。

**Q9: 为什么模板不能分离编译？**
A: 模板在调用点才实例化，编译单元边界导致未实例化的代码不可见。解决方案：头文件完整定义 或 显式实例化。

**Q10: C++20 Concepts 解决的问题？**
A: 替代 SFINAE 和 enable_if，提供清晰的类型约束语法，错误信息人类可读，支持 requires 子句和 concept 定义。

**Q11: 什么是 dependent name？**
A: 依赖模板参数的名字。需要加 typename（对类型）或 template（对模板）消除歧义。`typename T::value_type`。

### 陷阱与反问（5个）

1. **陷阱**：模板友元函数不是真正的函数模板。**反问**："如何定义模板类的模板友元函数？"
2. **陷阱**：`std::forward<T>` 只能用于万能引用（T&&），用于其他场景是误导。
3. **陷阱**：template 关键字用于依赖名模板调用：`obj.template foo<T>()`。**反问**："没有 template 关键字会怎样？"
4. **陷阱**：`std::remove_reference<T>::type` 需要加 typename：编译器默认将 `::type` 视为静态成员。
5. **陷阱**：模板函数和普通函数的重载优先级：普通函数优先于模板函数（更特化者优先）。

### 一句话答案（8个）

1. 模板两阶段编译：非依赖名立即检查，依赖名延迟检查。
2. SFINAE：替换失败从候选集移除，不是编译错误。
3. 折叠表达式 (args + ...) 替代递归解包。
4. T&& + 模板 = 万能引用，需 std::forward。
5. enable_if 通过偏特化隐藏 type 实现。
6. typename 消除依赖类型歧义，template 消除依赖模板歧义。
7. 模板分离编译用显式实例化 template class Foo<int>。
8. C++20 Concepts = requires 子句 + 概念定义，可读性好。
