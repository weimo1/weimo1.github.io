# 密码加密实现

> 适用范围：密码加密流程实现、加盐哈希代码、bcrypt/Argon2 集成、ECC 椭圆曲线加密

## 一、项目/模块概述

- **模块定位**：密码加密是 IM 系统的安全基础，本文聚焦密码加密的具体实现细节，涵盖加盐哈希、密钥延申、ECC 椭圆曲线的工程落地。
- **技术栈与依赖**：OpenSSL（SHA-256/ECC）、bcrypt/Argon2 库、CSPRNG（安全随机数生成器）。
- **模块边界**：本文聚焦加密算法的代码实现，系统架构和安全策略见《密码加密方案》。

## 二、架构设计

### 完整密码处理流程

```
注册流程：
  用户输入密码 → 生成随机 salt → hash(salt + password) → 存储 salt + hash

登录流程：
  用户输入密码 → 取出该用户 salt → hash(salt + 输入密码)
             → 比对存储的 hash → 一致则通过

重置流程：
  验证身份（邮箱/短信）→ 用户输入新密码 → 重新生成 salt + hash → 覆盖旧值
```

### 分层安全模型

| 层级 | 实现方式 | 防护目标 |
|------|----------|----------|
| 存储层 | 加盐哈希 + bcrypt/Argon2 | 防彩虹表、防暴力破解 |
| 传输层 | HTTPS (TLS) + ECC 密钥交换 | 防中间人窃听 |
| 应用层 | 密码强度校验 + 登录限流 | 防弱密码、防爆破 |

## 三、核心实现

### 3.1 加盐哈希原理

```
传统哈希问题：SHA-256(password) → 彩虹表可反查常见密码哈希值

加盐哈希：SHA-256(salt + password)
- 每个用户独立随机 salt（32 字节 CSPRNG）
- 相同密码 → 不同哈希值 → 彩虹表失效
- 需为每个 salt 独立爆破 → 计算量 = 密码空间 × 用户数
```

### 3.2 密钥延申（Key Derivation）

暴力破解的核心指标是"哈希计算速度"。SHA-256 设计目标是"快"，反而不利于密码存储。

| 算法 | salt | 可调 cost | 抗GPU/ASIC | 推荐度 |
|------|------|-----------|-------------|--------|
| SHA-256 | 手动 | 无 | 弱 | ⭐⭐ |
| bcrypt | 内置 | rounds (2^n) | 中 | ⭐⭐⭐ |
| Argon2id | 内置 | 内存+迭代+并行度 | 强 | ⭐⭐⭐⭐⭐ |

### 3.3 ECC 椭圆曲线

```
ECC vs RSA：
- 256位 ECC ≈ 3072位 RSA 安全强度
- 密钥更短 → 计算更快、带宽更小
- 适合移动端和 IoT 设备

常用曲线：secp256r1 (NIST P-256)、Curve25519
```

## 四、工程实践

- **密码哈希算法选择**：bcrypt（成熟稳定，rounds=10~12）或 Argon2id（抗 GPU/ASIC 最强）。SHA-256 仅适合 HMAC 场景。
- **salt 要求**：每个用户独立、CSPRNG 生成（`/dev/urandom` 或 `RAND_bytes`）、32 字节。
- **cost factor 调优**：以服务端单次验证耗时 200~500ms 为目标。bcrypt rounds = 12 大约需要 250ms。
- **HTTPS 强制**：所有认证接口必须走 TLS 1.2+，防止明文传输。
- **密码强度策略**：最小 8 位、至少含大写+小写+数字+特殊字符中的 3 类、禁止常见密码 Top1000。
- **登录限流**：同一 IP 连续失败 5 次 → 锁定 15 分钟；同一账号连续失败 3 次 → 验证码。

## 五、源码解析

### 5.1 bcrypt 集成

```cpp
#include <bcrypt/BCrypt.hpp>

// 注册：生成哈希
std::string hashPassword(const std::string& password) {
    // bcrypt 自动生成 salt 并嵌入结果
    // 返回格式：$2a$12$<22-char-salt><31-char-hash>
    // rounds = 2^12 = 4096 次迭代
    return BCrypt::generateHash(password, 12);
}

// 登录：验证密码
bool verifyPassword(const std::string& password, const std::string& hash) {
    return BCrypt::validatePassword(password, hash);
}
```

### 5.2 OpenSSL SHA-256 手动加盐

```cpp
#include <openssl/sha.h>
#include <openssl/rand.h>

std::string toHex(const unsigned char* data, size_t len) {
    std::ostringstream oss;
    for (size_t i = 0; i < len; ++i)
        oss << std::hex << std::setw(2) << std::setfill('0') << (int)data[i];
    return oss.str();
}

struct PasswordRecord {
    std::string salt; // 32 bytes hex → 64 chars
    std::string hash; // SHA-256 → 64 chars
};

PasswordRecord createPasswordRecord(const std::string& password) {
    PasswordRecord record;

    // 1. 生成 32 字节随机 salt
    unsigned char salt[32];
    RAND_bytes(salt, sizeof(salt));
    record.salt = toHex(salt, sizeof(salt));

    // 2. SHA-256(salt + password)
    std::string combined = record.salt + password;
    unsigned char hash[SHA256_DIGEST_LENGTH];
    SHA256(reinterpret_cast<const unsigned char*>(combined.c_str()),
           combined.size(), hash);
    record.hash = toHex(hash, sizeof(hash));

    return record;
}

bool verifyPassword(const std::string& password,
                    const std::string& salt,
                    const std::string& storedHash) {
    std::string combined = salt + password;
    unsigned char hash[SHA256_DIGEST_LENGTH];
    SHA256(reinterpret_cast<const unsigned char*>(combined.c_str()),
           combined.size(), hash);
    return toHex(hash, SHA256_DIGEST_LENGTH) == storedHash;
}
```

### 5.3 ECC 密钥交换（简化示例）

```cpp
#include <openssl/ec.h>
#include <openssl/ecdh.h>

// 生成 ECC 密钥对
EVP_PKEY* generateECCKey() {
    EVP_PKEY_CTX* ctx = EVP_PKEY_CTX_new_id(EVP_PKEY_EC, nullptr);
    EVP_PKEY_keygen_init(ctx);
    EVP_PKEY_CTX_set_ec_paramgen_curve_nid(ctx, NID_X9_62_prime256v1); // P-256
    EVP_PKEY* key = nullptr;
    EVP_PKEY_keygen(ctx, &key);
    EVP_PKEY_CTX_free(ctx);
    return key;
}

// ECDH 密钥交换 → 共享密钥用于 AES 加密
std::vector<uint8_t> deriveSharedSecret(EVP_PKEY* privateKey,
                                         EVP_PKEY* peerPublicKey) {
    EVP_PKEY_CTX* ctx = EVP_PKEY_CTX_new(privateKey, nullptr);
    EVP_PKEY_derive_init(ctx);
    EVP_PKEY_derive_set_peer(ctx, peerPublicKey);

    size_t secretLen = 0;
    EVP_PKEY_derive(ctx, nullptr, &secretLen);

    std::vector<uint8_t> secret(secretLen);
    EVP_PKEY_derive(ctx, secret.data(), &secretLen);
    EVP_PKEY_CTX_free(ctx);
    return secret;
}
```

## 六、面试准备

### 6.1 高频问法

**Q1：为什么加盐？salt 的作用是什么？**
防止彩虹表攻击。相同密码不同用户产生不同哈希，攻击者无法批量反查。salt 不是秘密（可以明文存储），作用是让彩虹表失效。

**Q2：为什么用 bcrypt 而不是 SHA-256？**
bcrypt 设计目标是"慢"（内置 rounds 迭代），暴力破解代价大。SHA-256 设计目标是"快"，GPU 可每秒计算数十亿次 SHA-256。

**Q3：bcrypt 的 cost factor 如何选择？**
以服务端单次验证耗时 200~500ms 为目标。rounds = 2^cost，cost=12 → 4096 次迭代（约 250ms）。需根据服务器 CPU 压测调整。

**Q4：Argon2 比 bcrypt 好在哪？**
Argon2 可配置内存消耗（如 64MB），对抗 GPU/ASIC 并行攻击。bcrypt 固定 4KB 内存，专用硬件可大量并行爆破。Argon2 是 2015 年密码哈希竞赛冠军。

**Q5：忘记密码怎么办？能恢复原文吗？**
不能。哈希是单向函数，无法从 hash 反推原文。只能通过验证邮箱/手机 → 重置为新密码。

**Q6：ECC 和 RSA 对比？**
256 位 ECC ≈ 3072 位 RSA 安全强度。ECC 密钥更短、计算更快、适合移动端。RSA 加解密快但密钥生成慢，ECC 密钥生成快。

**Q7：salt 应该怎么生成？有什么要求？**
CSPRNG（加密安全伪随机数生成器）生成，每用户独立，长度 ≥ 16 字节（推荐 32）。不能用 `rand()` 或 `time(NULL)` —— 它们不是密码学安全的。

**Q8：彩虹表是什么？怎么防御？**
预先计算的"常见密码 → 哈希值"映射表。防御：① 加盐（为每个 salt 建表不现实）；② 密钥延申（减慢计算速度）；③ 密码强度要求（避免常见密码）。

**Q9：数据库泄露后密码有多危险？**
密码明文 → 立即全部暴露（最危险）。仅哈希 → 彩虹表可秒查常见密码。加盐哈希 + bcrypt → 攻击者需为每个用户暴力破解，cost=12 约每秒 4 次尝试。

**Q10：前端加密和后端加密哪个更重要？**
后端存储加密是底线（防止数据库泄露）。前端加密（如先做一次 SHA-256）能防止 HTTPS 中间人攻击，但不能替代后端加密——前端哈希若泄露等同于密码。

### 6.2 反问点

- 你们用的是什么密码哈希算法？bcrypt 还是 Argon2？
- cost factor 设置多少？有没有做过性能测试？
- 登录限流策略是什么？失败几次锁定多久？
- 数据库中的密码 hash 能否被内部人员访问？审计日志是否记录？

### 6.3 一句话答案

- 加盐 = salt + password → hash，让彩虹表失效
- bcrypt > SHA-256 = 设计为"慢"而非"快"
- Argon2 > bcrypt = 可配置内存消耗抗 GPU/ASIC
- 忘记密码 = 不可恢复，只能重置
- ECC 256 位 ≈ RSA 3072 位
- salt 用 CSPRNG，每用户独立 32 字节
- 彩虹表防御 = 加盐 + 密钥延申 + 强密码策略
