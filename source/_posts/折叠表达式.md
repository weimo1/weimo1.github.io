# 折叠表达式

> 适用范围：C++17 折叠表达式（Fold Expression）及完美转发（`std::forward`）机制。

参考：<https://zhuanlan.zhihu.com/p/718967999>

## 一、核心概念

- **定义**：折叠表达式是 C++17 引入的语法，用 `(pack op ...)` 形式对参数包进行展开和运算，替代了递归模板解包模式。完美转发 = `std::forward` + 万能引用 + 引用折叠，三者合一实现参数的左值/右值属性不变传递。
- **关键词**：折叠表达式（Fold Expression）、参数包展开、完美转发、`std::forward`、万能引用（Universal Reference）、引用折叠（Reference Collapsing）
- **适用场景/边界**：
  - 折叠表达式：变参模板的参数包运算、批量操作、逗号副作用执行
  - 完美转发：STL 容器（如 `emplace_back`）、工厂函数、代理转发函数
  - 折叠表达式只展开参数包，不能做复杂模式匹配

## 二、详细解析（≥200字）

### 相关技术概览

- **条件编译** `if constexpr`：这个关键字用于在编译时判断是否满足条件
- **类型萃取** `std::is_invocable_v`：这是一个用于判断类型 `T` 是否可调用的特性
- **完美转发** `std::forward`：确保参数的完美转发，保留其左值或右值性质
- **可变长参数模板**：支持可变数量的参数包，语法用 `T ... args` 表示
- **折叠表达式**：使用了C++17中的折叠表达式，它会对参数从左到右进行求值。简化了可变长参数模板的使用，提供了一种简洁而直观的方式来对参数包进行展开和操作，从而避免了递归或显式循环的繁琐
- **绑定参数生成函数对象** `std::bind`：可绑定参数args到一个函数f，并返回一个可调用对象

### 完美转发原理

完美转发是一个比较简单，却又比较复杂的东西。
- 简单之处在于理解**动机**：C++为什么需要完美转发？
- 复杂之处在于理解**原理**：完美转发基于万能引用，引用折叠以及 `std::forward` 模板函数。

### 动机：C++为什么需要完美转发？

我们从一个简单的例子出发。假设有这么一种情况，用户一般使用 testForward 函数，testForward 什么也不做，只是简单的转调用到 print 函数。

```c++
template<typename T>
void print(T & t){
    std::cout << "Lvalue ref" << std::endl;
}

template<typename T>
void print(T && t){
    std::cout << "Rvalue ref" << std::endl;
}

template<typename T>
void testForward(T && v){ 
    print(v);//v此时已经是个左值了,永远调用左值版本的print
    print(std::forward<T>(v)); //本文的重点
    print(std::move(v)); //永远调用右值版本的print

    std::cout << "======================" << std::endl;
}

int main(int argc, char * argv[])
{
    int x = 1;
    testForward(x); //实参为左值
    testForward(std::move(x)); //实参为右值
}
```

上面的程序的运行结果：

```
Lvalue ref
Lvalue ref
Rvalue ref
======================
Lvalue ref
Rvalue ref
Rvalue ref
======================
```

用户希望 `testForward(x);` 最终调用的是左值版本的 print，而 `testForward(std::move(x));` 最终调用的是右值版本的 print。

**可惜的是，在 testForward 中，虽然参数 v 是右值类型的，但此时 v 在内存中已经有了位置，所以 v 其实是个左值！**

所以，`print(v)` 永远调用左值版本的 print，与用户的本意不符。`print(std::move(v));` 永远调用右值版本的 print。只有 `print(std::forward<T>(v));` 才符合用户的本意。

本质问题在于，左值右值在函数调用时，都转化成了左值，使得函数转调用时无法判断左值和右值。

在STL中，随处可见这种问题。比如C++11引入的 `emplace_back`，它接受左值也接受右值作为参数，接着转调用了空间配置器的 construct 函数，而 construct 又转调用了 `placement new`，`placement new` 根据参数是左值还是右值，决定调用拷贝构造函数还是移动构造函数。

这里要保证从 `emplace_back` 到 `placement new`，参数的左值和右值属性保持不变。

### 原理：完美转发

`std::forward` 不是独自运作的，完美转发 = `std::forward` + 万能引用 + 引用折叠。三者合一才能实现完美转发的效果。

`std::forward` 的正确运作的前提，是引用折叠机制，为 `T &&` 类型的万能引用中的模板参数 T 赋了一个恰到好处的值。我们用 T 去指明 `std::forward` 的模板参数，从而使得 `std::forward` 返回的是正确的类型。

- **关键数据结构**：`std::forward<T>(arg)`、`T&&`（万能引用）
- **关键公式**：左值传入时 T=int& → forward 返回 int&；右值传入时 T=int → forward 返回 int&&

## 三、动手实践（代码案例）

### 3.1 折叠表达式：编译器展开

```c++
// C++17 折叠表达式替代递归模板解包
template<typename... Args>
auto sum(Args... args) {
    return (args + ...);  // 左折叠: ((a1 + a2) + a3) + a4
}

// 编译器展开等价于:
template<> auto sum<int,int,int,int>(int a1, int a2, int a3, int a4) {
    return ((a1 + a2) + a3) + a4;
}

// 四种折叠形式:
// (pack op ...)       一元左折叠
// (... op pack)       一元右折叠
// (pack op ... op init)二元左折叠
// (init op ... op pack)二元右折叠
```

### 3.2 逗号折叠的应用

```c++
// 逗号运算符折叠: 可用于逐元素执行操作
template<typename... Args>
void print_all(Args&&... args) {
    (std::cout << ... << args);  // 二元左折叠: 输出所有元素
    // 等价于: ((cout << a1) << a2) << a3
}
// 注: 二元折叠必须提供初始值，所以 cout<<...<<args 需要 (cout << ... << args)
```

### 3.3 折叠表达式与 if constexpr 配合

```c++
template<typename... Args>
auto last(Args... args) {
    // 配合 if constexpr 实现递归终止
    if constexpr (sizeof...(args) == 1)
        return (args, ...);  // 返回最后一个参数
    else
        return last(args...);  // 递归
}
```

### 3.4 testForward(x)：左值传入

先考虑 `testForward(x);` 这一行代码。

**Step 1 实例化 testForward**

根据万能引用的实例化规则：

```c++
T = int &
void testForward(int & && v){
    print(std::forward<T>(v));
}
```

又根据引用折叠，等价于：

```c++
T = int &
void testForward(int & v){
    print(std::forward<int &>(v));
}
```

**Step 2 实例化 std::forward**

注：C++ Primer：forward 必须通过显式模板实参来调用，不能依赖函数模板参数推导。

```c++
// libstdc++ 中的实现
template<typename _Tp>
constexpr _Tp&&
forward(typename std::remove_reference<_Tp>::type& __t) noexcept
{ return static_cast<_Tp&&>(__t); }
```

代入 `T = int &`：

```c++
constexpr int & && //折叠
forward(typename std::remove_reference<int &>::type& __t) noexcept
 { return static_cast<int & &&>(__t); } //折叠
```

发生 2 次引用折叠后等价于：

```c++
constexpr int & //折叠
forward(int & __t) noexcept
 { return static_cast<int &>(__t); } //折叠
```

所以最终 `std::forward<int &>(v)` 的作用就是将参数强制转型成 `int &`，即左值。所以调用左值版本的 print。

### 3.5 testForward(std::move(x))：右值传入

**Step 1 实例化 testForward**

`testForward(std::move(x))` 也就是 `testForward(static_cast<int &&>(x))`。根据万能引用的实例化规则：

```c++
T = int 
void testForward(int && v){
    print(std::forward<int>(v));
}
```

万能引用绑定到右值上时，不会发生引用折叠。

**Step 2 实例化 std::forward**

代入 `T = int`：

```c++
constexpr int && 
forward(typename std::remove_reference<int>::type& __t) noexcept
 { return static_cast<int &&>(__t); }
```

等价于：

```c++
constexpr int &&
forward(int & __t) noexcept
 { return static_cast<int &&>(__t); }
```

所以最终 `std::forward<int>(v)` 的作用就是将参数强制转型成 `int &&`，即右值。所以调用右值版本的 print。

## 四、进阶应用（≥500字）

### 写在后面

在GCC源码中，`std::forward` 还有第二个版本，分析方法与本文一致。

右值的概念其实很微妙，一旦某个右值，有了名字，也就在内存中有了位置，它就变成了1个左值。但它又是一个很有用的概念，**允许程序员更加细粒度的处理对象拷贝时的内存分配问题，提高了对临时对象和不需要的对象的利用率**，极大提高程序的效率。

完美转发基于万能引用，引用折叠以及 `std::forward` 模板函数。据我所知，STL出现 `std::forward`，一定出现万能引用。其实这也很好理解，完美转发机制，是为了将左值和右值统一处理，节约代码量，而只有万能引用会出现同时接受左值和右值的情况，所以完美转发只存在于万能引用中。

### 与其他主题的关联

- **emplace_back**：容器操作中完美转发的典型应用
- **make_unique/make_shared**：工厂函数中完美转发参数给构造函数
- **引用折叠规则**：`T& &` → `T&`，`T& &&` → `T&`，`T&& &` → `T&`，`T&& &&` → `T&&`

### 折叠表达式经验

- **二元折叠必须有初始值**：`(pack + ...)` 是一元，`(0 + ... + pack)` 是二元，一元空包对 + 非法
- **空包处理**：一元折叠对 &&→true、||→false、,→void() 是合法的；对 +/* 等是不合法的
- **右折叠优先用二元**：`(args - ...)` 和 `(... - args)` 语义不同；有初始值的二元折叠更安全
- **逗号折叠用于副作用**：`(f(args), ...)` 对每个元素调用 f，适合批量操作
- **折叠表达式简化了 SFINAE**：不再需要递归模板和终止特化，代码量减少 70%+
- **与变参模板配合**：`sizeof...(args)` 可在折叠表达式外获取参数个数

## 六、面试准备

### Q&A（10题）

**Q1: 什么是折叠表达式？**
A: C++17 引入的语法，用 `(pack op ...)` 形式对参数包进行展开和运算，替代递归模板

**Q2: 一元折叠和二元折叠的区别？**
A: 一元不提供初始值（`(pack + ...)`），二元提供初始值（`(init + ... + pack)`）。对大部分运算符一元空包不合法

**Q3: 左折叠和右折叠有什么区别？**
A: 左折叠 `(pack op ...)` 从左到右结合；右折叠 `(... op pack)` 从右到左结合。对结合律成立的运算符无差别

**Q4: 哪些运算符支持一元折叠的空包？**
A: `&&`→true、`||`→false、`,`→void()。其他运算符（如 +）的一元折叠空包不合法

**Q5: 逗号折叠的典型用途？**
A: 批量执行副作用操作：`(print(args), ...)` 或 `(vec.push_back(args), ...)`

**Q6: 折叠表达式如何打印所有参数？**
A: `(std::cout << ... << args)` 是二元左折叠，输出所有参数。`((std::cout << args << " "), ...)` 逗号折叠加分隔

**Q7: C++17 之前如何实现参数包求和？**
A: 递归模板 + 终止特化，需要多写 5-8 行代码

**Q8: 折叠表达式能与 if constexpr 配合吗？**
A: 能，折叠表达式负责展开，if constexpr 负责条件分支

**Q9: sizeof...(args) 在折叠表达式中有什么用？**
A: 获取参数包大小，用于边界判断或条件选择

**Q10: 为什么二元折叠比一元折叠更安全？**
A: 二元折叠有初始值，空包时有明确结果，不会触发编译错误

### 陷阱与反问（5个）

1. **陷阱**：`(args - ...)` 和 `(... - args)` 结果不同——左折叠是 `((a-b)-c)`，右折叠是 `(a-(b-c))`
2. **反问**：折叠表达式能替代所有递归模板吗？→ 不能，复杂模式匹配仍然需要递归模板
3. **陷阱**：对 += 运算符折叠→ `(args += ...)` 每个元素都会被自加
4. **反问**：有了折叠表达式还需要变参模板吗？→ 需要，折叠只是展开方式，变参模板是接收方式
5. **陷阱**：折叠表达式内的逗号有特殊语义——`(args, ...)` 和 `(f(args...))` 效果不同

### 一句话答案（8个）

1. **折叠表达式语法**：`(pack op ...)`，C++17 核心特性
2. **四种形式**：一元左/右折叠，二元左/右折叠
3. **汇编输出**：折叠表达式展开后与手写展开等价
4. **空包处理**：&&/||/, 有默认值，其他一元不合法
5. **替代递归**：减少代码 70%，编译更快
6. **结合性**：左折叠从左到右，右折叠从右到左
7. **if constexpr 配合**：折叠负责展开，if constexpr 负责条件
8. **std::apply**：结合 tuple + 折叠表达式实现参数转发
