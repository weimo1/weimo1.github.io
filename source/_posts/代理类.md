# 代理类

> 适用范围：C++ 代理类（Proxy Class）和委托（Delegate）设计模式。

## 一、核心概念

- **定义**：在 C++ 中，**代理类（Proxy Class）** 和 **委托（Delegate）** 是两种常用的设计模式，用于解耦代码、增强灵活性和控制对象行为。
- **关键词**：代理模式（Proxy）、委托（Delegate）、`std::function`、延迟初始化、访问控制、回调机制
- **适用场景/边界**：
  - 代理类：延迟加载、访问控制、远程代理、日志拦截
  - 委托：GUI 事件处理、异步任务回调、算法策略切换、插件系统

## 二、详细解析（≥200字）

### 原理拆解（三层递进）

**第一层：基本工作原理**

代理类作为另一个类（目标类）的**中间层**，控制对目标对象的访问或扩展其功能。委托允许对象将特定任务**委派**给其他对象或函数。

**第二层：关键步骤详解**

代理类的关键机制：
1. 代理类持有目标类的实例或指针
2. 代理类实现与目标类相同的接口
3. 在接口方法中插入额外逻辑（延迟创建、权限检查、日志等）
4. 将实际工作转发给目标对象

委托的关键机制——C++ 中可通过以下方式实现：
- **函数指针**：简单但类型安全性低
- **成员函数指针**：绑定到特定对象的成员函数
- `std::function`：类型安全的通用可调用对象包装器
- **信号槽机制**：如 Qt 的信号槽

**第三层：底层机制**

代理模式内部本质是一个"间接层"：通过组合而非继承来持有目标对象，在方法调用前后注入横切关注点。委托通过 `std::function` 实现时利用类型擦除技术——`std::function` 内部使用虚函数表存储可调用对象的类型信息。

- **关键数据结构**：代理持有目标指针/引用；委托持有 `std::function` 或函数指针
- **关键公式**：代理 = 接口一致 + 组合目标 + 拦截逻辑；委托 = 可调用对象包装 + 延迟/转发调用

### 代理模式 vs 装饰器模式

| 特性 | 代理模式 | 装饰器模式 |
| --- | --- | --- |
| **目的** | 控制访问，可能隐藏目标对象 | 动态添加职责，透明扩展功能 |
| **对象关系** | 代理与目标接口相同 | 装饰器与目标接口相同，但包含目标引用 |
| **生命周期** | 可能管理目标对象的生命周期 | 通常不管理目标对象的生命周期 |

### 委托模式 vs 观察者模式

| 特性 | 委托模式 | 观察者模式 |
| --- | --- | --- |
| **通信方向** | 单向（委托方调用被委托方） | 单向（主题通知多个观察者） |
| **关系** | 一对一或一对多 | 一对多 |
| **灵活性** | 高（可动态切换委托对象） | 高（支持多个观察者） |

## 三、动手实践（代码案例）

### 3.1 代理类：延迟初始化代理

```c++
class Image {
public:
    virtual void display() = 0;
};

class RealImage : public Image {
public:
    RealImage(const std::string& filename) {
        std::cout << "加载图片: " << filename << "\n";
    }
    void display() override {
        std::cout << "显示图片\n";
    }
};

class ProxyImage : public Image {
    std::string filename;
    RealImage* real_image = nullptr;
public:
    ProxyImage(const std::string& filename) : filename(filename) {}
    void display() override {
        if (!real_image) {
            real_image = new RealImage(filename);  // 延迟初始化
        }
        real_image->display();
    }
    ~ProxyImage() { delete real_image; }
};

// 使用代理
int main() {
    ProxyImage proxy("photo.jpg");
    proxy.display();  // 首次调用时加载图片
    proxy.display();  // 直接显示（已加载）
}
```

### 3.2 委托：使用 `std::function` 实现

```c++
#include <functional>
#include <iostream>

class Button {
public:
    using Callback = std::function<void()>;
    void setCallback(Callback cb) { callback = cb; }
    void click() {
        if (callback) callback();
    }
private:
    Callback callback;
};

class Dialog {
public:
    void showMessage() {
        std::cout << "按钮被点击，显示对话框\n";
    }
};

int main() {
    Button button;
    Dialog dialog;

    // 将成员函数绑定为委托
    button.setCallback([&dialog] { dialog.showMessage(); });
    button.click();  // 输出 "按钮被点击，显示对话框"
}
```

### 3.3 委托：成员函数指针

```c++
class Processor {
public:
    using Operation = void (Processor::*)(int);
    void setOperation(Operation op) { operation = op; }
    void execute(int data) {
        (this->*operation)(data);
    }
private:
    Operation operation;
    void multiply(int x) { std::cout << "结果: " << x * 2 << "\n"; }
    void add(int x) { std::cout << "结果: " << x + 10 << "\n"; }
};

int main() {
    Processor proc;
    proc.setOperation(&Processor::multiply);
    proc.execute(5);  // 输出 "结果: 10"
    proc.setOperation(&Processor::add);
    proc.execute(5);  // 输出 "结果: 15"
}
```

### 3.4 代理与委托结合

```c++
// 代理类：控制对网络服务的访问
class NetworkService {
public:
    virtual void request(const std::string& url) = 0;
};

class RealNetworkService : public NetworkService {
public:
    void request(const std::string& url) override {
        std::cout << "访问网络资源: " << url << "\n";
    }
};

class NetworkProxy : public NetworkService {
    RealNetworkService* service = nullptr;
    std::function<void()> accessCheck;  // 委托：权限检查
public:
    NetworkProxy(std::function<void()> check) : accessCheck(check) {}
    void request(const std::string& url) override {
        accessCheck();  // 委托权限检查
        if (!service) {
            service = new RealNetworkService();
        }
        service->request(url);
    }
    ~NetworkProxy() { delete service; }
};

// 使用
int main() {
    auto checkPermission = [] {
        std::cout << "执行权限检查...\n";
        // 实际逻辑可能验证用户权限
    };

    NetworkProxy proxy(checkPermission);
    proxy.request("https://example.com");
}
```

## 四、进阶应用（≥500字）

### 应用场景总结

| 模式 | 典型场景 |
| --- | --- |
| **代理类** | 延迟加载图片/文件、数据库连接池、权限控制、日志拦截 |
| **委托** | GUI 事件处理、异步任务回调、算法策略切换（如排序策略）、插件系统 |

### 与其他主题的关联

- **智能指针与代理**：`std::shared_ptr` / `std::unique_ptr` 本身是"资源代理"的一种形式，控制原始指针的访问和生命周期
- **Pimpl（Pointer to Implementation）**：是一种编译防火墙代理——通过代理隐藏实现细节
- **装饰器模式**：与代理模式接口一致，但代理控制访问，装饰器增强功能
- **适配器模式**：适配器转换接口，代理保持接口不变

### 工程中的真实用法

1. **数据库连接池代理**：
   ```c++
   class ConnectionProxy : public Connection {
       ConnectionPool& pool;
       Connection* real_conn;
   public:
       Connection* acquire() { real_conn = pool.borrow(); return this; }
       void release() { pool.return_(real_conn); }
       // 所有方法先检查 real_conn 是否为 nullptr
   };
   ```

2. **智能指针作为资源代理**：`std::unique_ptr` 独占所有权代理，`std::shared_ptr` 共享所有权代理

3. **远程代理（RPC Stub）**：gRPC 生成的 Stub 类是服务端的本地代理

4. **Qt 信号槽委托**：`connect(sender, &Sender::signal, receiver, &Receiver::slot)` 实现了回调委托

### 常见优化策略

- **优先使用智能指针**：管理目标对象的生命周期（如 `std::unique_ptr`）
- **接口一致性**：代理类应与目标类实现相同接口，保证透明性
- **优先用 `std::function`**：替代原始函数指针，提升类型安全性和灵活性
- **避免悬垂引用**：若委托持有对象引用，需确保对象生命周期长于委托
- **简化绑定**：C++11 的 Lambda 表达式和 `std::bind` 可简化委托设置
- **性能优化**：在延迟初始化代理中避免重复检查（如双重检查锁定）

## 五、源码解析和实践感悟（≥1000字）

### 关键实现路径

**代理类的虚函数表结构**：

```c++
// 代理类通过组合持有目标对象，而非继承
class ProxyImage : public Image {
    RealImage* real_image;  // 组合，非继承
    
    void display() override {
        // 步骤1: 检查是否需要初始化
        if (!real_image) {
            // 步骤2: 延迟创建真实对象
            real_image = new RealImage(filename);
        }
        // 步骤3: 委托给真实对象
        real_image->display();
    }
};

// 简化 vtable 结构:
// ProxyImage vtable:
// [0] ProxyImage::display  -- 拦截方法
// RealImage vtable:
// [0] RealImage::display   -- 真实实现
```

**`std::function` 内部委托机制的简化实现**：

```c++
// 委托的本质：类型擦除的可调用对象包装
template<typename Signature>
class function;

template<typename Ret, typename... Args>
class function<Ret(Args...)> {
    struct callable_base {
        virtual Ret invoke(Args...) = 0;
        virtual callable_base* clone() = 0;
        virtual ~callable_base() = default;
    };
    
    template<typename F>
    struct callable_impl : callable_base {
        F func;
        // F 可以是: 函数指针 / 仿函数 / lambda / bind 结果 / 成员函数指针
        Ret invoke(Args... args) override { return func(args...); }
        callable_base* clone() override { return new callable_impl(func); }
    };
    
    callable_base* ptr;
};
```

**成员函数指针的内部表示**：

```c++
// 成员函数指针不是普通指针！
// 在多重继承下，包含 this 偏移信息
struct MemberFuncPtr {
    void* func_addr;    // 实际函数地址
    ptrdiff_t this_adj; // this 指针偏移（多重继承需要）
};

// 调用成员函数指针等价于:
// (obj_ptr + ptr->this_adj)->*(ptr->func_addr)(args...)
```

### 代理类最佳实践

1. **优先使用智能指针**：管理目标对象的生命周期（如 `std::unique_ptr`）
2. **接口一致性**：代理类应与目标类实现相同接口，保证透明性
3. **性能优化**：在延迟初始化代理中避免重复检查（如双重检查锁定）

### 委托最佳实践

1. **优先用 `std::function`**：替代原始函数指针，提升类型安全性和灵活性
2. **避免悬垂引用**：若委托持有对象引用，需确保对象生命周期长于委托
3. **简化绑定**：C++11 的 Lambda 表达式和 `std::bind` 可简化委托设置

### 难点与易错点

1. **代理的生命周期管理**
   ```c++
   // 危险：代理析构时目标已被销毁
   RealImage img("file.jpg");
   ProxyImage proxy(img);  // proxy 持有 img 引用
   // img 先析构 → proxy.display() 访问已销毁对象
   ```

2. **委托中的悬垂引用**
   ```c++
   std::function<void()> createDelegate() {
       Dialog dialog;  // 局部对象
       return [&dialog] { dialog.showMessage(); };  // 危险！
   }  // dialog 已析构，delegate 中的引用悬空
   ```

3. **成员函数指针的 this 调整**
   ```c++
   struct A { int a; };
   struct B { int b; };
   struct C : A, B {};
   // &C::b 的内存表示:
   // { func_addr = ..., this_adj = sizeof(A) }  // this 需要偏移到 B 子对象
   ```

4. **代理与虚函数交互**
   ```c++
   class Base { virtual void f(); };
   class Proxy : public Base {
       Base* target;
       void f() override { target->f(); }
   };
   // 如果 target 实际类型是 Derived，Proxy::f() 正确调用 Derived::f()
   // 因为是通过 Base* 的虚函数调用
   ```

### 经验总结（补充）

1. **代理是"控制"、委托是"传递"**：代理在转发前后添加逻辑，委托纯粹将任务交给他人
2. **组合优于继承**：代理/委托都是通过组合实现扩展，遵循开闭原则
3. **`std::function` 是委托利器**：C++11 起应作为委托的首选实现方式
4. **两者均可显著提升代码的可维护性和扩展性，合理结合使用能构建高效、安全的系统**

## 六、面试准备

### 6.1 高频问法（≥10个）

基础理解：

**Q1：代理模式的核心思想是什么？有哪些常见类型？**

A：代理模式通过在目标对象前放置一个中间层（代理类）来控制访问。常见类型：延迟初始化代理（Lazy Proxy）、访问控制代理（Protection Proxy）、远程代理（Remote Proxy）、日志代理（Logging Proxy）、缓存代理（Cache Proxy）。

**Q2：C++ 中如何实现委托？**

A：四种方式：1) 函数指针（简单但不安全）2) 成员函数指针（绑定到特定对象）3) `std::function`（最推荐，类型安全）4) 信号槽机制（如 Qt）。`std::function` 可以包装函数、lambda、仿函数、bind 结果等一切可调用对象。

**Q3：代理模式和装饰器模式的区别？**

A：代理模式目的是控制访问（可能隐藏目标），装饰器模式目的是动态增强功能（透明扩展）。代理可能自行管理目标生命周期，装饰器通常不管理。两者接口通常与目标相同。

原理深入：

**Q4：`std::function` 的内部实现原理？**

A：使用类型擦除技术。内部有虚基类定义 `invoke`/`clone`/`destroy` 接口，模板子类存储具体可调用对象。构造函数接受任意类型并创建对应的子类对象。调用时通过虚函数分发。通常包含小对象优化（SBO）。

**Q5：成员函数指针和普通函数指针有什么区别？**

A：成员函数指针不是一个简单地址——它包含实际函数地址和 this 指针偏移量（用于多重继承）。调用成员函数指针需要同时提供对象指针：`(obj.*ptr)(args)`。sizeof 通常为 16 字节（64位平台）。

**Q6：代理模式如何影响性能？**

A：增加一次额外的函数调用（虚函数调用如果接口有虚函数）。延迟初始化代理首次调用有创建开销但后续调用无额外开销。日志代理每次调用都有日志开销。一般情况下性能影响可忽略。

实践应用：

**Q7：实际项目中代理类的应用场景？**

A：数据库连接池（代理控制连接的获取和归还）、智能指针（代理管理原始指针生命周期）、Pimpl 惯用法（编译防火墙代理）、网络代理（本地 Stub 代表远程服务）、lazy_initializer 包装器。

**Q8：`std::bind` 和 lambda 表达式在委托中如何选择？**

A：优先用 lambda——类型明确、可内联优化、没有 `std::bind` 的嵌套占位符混乱。`std::bind` 仅在需要延迟求值和完美转发时偶尔有用。C++14 的泛型 lambda 进一步削弱了 `std::bind` 的必要性。

**Q9：委托模式如何避免循环引用？**

A：使用 `std::weak_ptr` 持有被委托者引用：`std::function<void()> cb = [weak = std::weak_ptr<T>(shared)] { if (auto sp = weak.lock()) sp->method(); };`

**Q10：代理类中如何实现线程安全的延迟初始化？**

A：使用双重检查锁定（Double-Checked Locking）+ `std::atomic` 或直接用 `std::call_once`：
```c++
class LazyProxy {
    std::unique_ptr<Real> real;
    std::once_flag flag;
public:
    Real& get() {
        std::call_once(flag, [&] { real = std::make_unique<Real>(); });
        return *real;
    }
};
```

### 6.2 反问点/陷阱点（≥5个）

针对面试官的深度问题：

- 在贵项目中，代理模式主要用于哪些横切关注点？是否用了 AOP 框架来系统化管理代理？
- `std::function` 的小对象优化大小在贵平台上是多少？是否有过自定义 SBO 的尝试？
- 团队在事件驱动系统中如何管理委托的生命周期？是否有专门的 Dispatcher 模式？

常见的陷阱问题：

- **陷阱 1**：代理持有裸指针但目标对象已被销毁→ 访问悬垂指针导致 UB → 应使用智能指针或明确生命周期
- **陷阱 2**：成员函数指针在多重继承下的 this 调整 → 直接 `memcpy` 成员函数指针是危险的
- **陷阱 3**：`std::function` 包装了不可拷贝的 lambda（捕获 unique_ptr）→ 拷贝 `std::function` 编译失败

### 6.3 一句话答案（≥5个）

快速记忆要点：

1. 代理的核心：通过中间层控制对目标对象的访问
2. 委托的核心：将任务委派给其他可调用对象
3. `std::function` 是 C++ 委托的最佳实现方式
4. 代理 = 接口一致 + 组合目标 + 拦截逻辑
5. 委托 = 可调用对象包装 + 类型擦除 + 延迟/转发调用

情景模拟答案：

- 被问到"什么是代理类"→ "代理类是实现与目标类相同接口的中间层，用于控制访问、延迟创建、权限检查等场景"
- 被问到"委托和回调有什么区别"→ "委托是回调的一种实现方式，C++ 中用 `std::function` 实现委托最灵活安全"
- 被问到"代理和适配器有什么区别"→ "代理保持接口不变但改变行为，适配器改变接口以匹配其他接口"
