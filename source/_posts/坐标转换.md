## 一、核心概念

- 定义：坐标转换是将顶点从模型自身的局部空间，经过世界空间、观察空间、裁剪空间，最终映射到屏幕空间的完整变换链路。核心是 MVP 矩阵（Model-View-Projection）及其逆变换。
- 关键词：MVP 矩阵、齐次坐标、透视除法、NDC、视锥体、全屏三角形、Guard-band Clipping
- 适用场景/边界：所有渲染管线的顶点处理阶段；Shader 中任何需要空间转换的场景（光照计算、后处理、深度重建）

## 二、详细解析（≥200字）

### 原理拆解（三层递进）

**第一层：五大坐标空间**

```
局部空间(Local) → 世界空间(World) → 观察空间(View) → 裁剪空间(Clip) → 屏幕空间(Screen)
     Model矩阵          View矩阵         Projection矩阵     透视除法+视口变换
```

| 空间 | 含义 | 变换矩阵 |
|------|------|----------|
| 局部空间 | 物体自身坐标系，建模时的原点 | — |
| 世界空间 | 场景全局坐标系 | Model |
| 观察空间 | 以摄像机为原点的坐标系 | View |
| 裁剪空间 | 投影后的齐次坐标，范围为 [-w, w] | Projection |
| NDC | 透视除法后，范围 [-1, 1] | — |
| 屏幕空间 | 像素坐标 | Viewport |

**第二层：正向 MVP 与逆向 MVP**

正向 MVP（渲染管线）：`P_clip = Projection × View × Model × P_local`

逆向 MVP（射线生成）：`Ray_world = inverse(Projection) × inverse(View) × P_clip`

```glsl
// 标准顶点着色器中的正向 MVP
void main() {
    gl_Position = projection * view * model * vec4(a_position, 1.0);
    // 等价于：
    // vec4 world_pos = model * vec4(a_position, 1.0);
    // vec4 view_pos  = view * world_pos;
    // vec4 clip_pos  = projection * view_pos;
}
```

逆向 MVP 用于从屏幕坐标反推世界空间射线（Ray Tracing/屏幕空间效果的基础）：

```glsl
// 输入：屏幕中心点 → 反推世界空间方向
vec4 vertex = vec4(0.0, 0.0, 0.0, 1.0);  // 裁剪空间中心
mat4 view_from_clip = inverse(projection);
mat4 model_from_view = inverse(view);
vec4 view_space = view_from_clip * vertex;
vec4 view_dir = vec4(view_space.xyz, 0.0);
vec4 world_dir = model_from_view * view_dir;
```

**第三层：透视除法和齐次坐标**

投影矩阵将观察空间的 z 值编码到 w 分量中：`w_clip = -z_view`（OpenGL 约定）。透视除法 `(x/w, y/w, z/w)` 实现近大远小——离相机越远的点，w 越大，除以后坐标越小。这是 GPU 硬件固定功能，在顶点着色器输出后自动执行。

### 关键公式

视锥体构建（从 FOV 和宽高比计算射线方向）：

```glsl
float vlen = tan(cameraFOV / 2.0);
float hlen = vlen * cameraAspect;
vec3 forward = normalize(cameraCenter - cameraEye);
rd = normalize(forward +
    cameraRight * (uv.x - 0.5) * hlen * 2.0 +
    cameraUp    * (uv.y - 0.5) * vlen * 2.0);
```

## 三、动手实践（代码案例）

### 3.1 GetCamera — 从 UV 坐标生成相机射线

```glsl
uniform vec3 cameraEye;
uniform vec3 cameraCenter;
uniform vec3 cameraUp;
uniform vec3 cameraRight;
uniform float cameraFOV;    // 弧度
uniform float cameraAspect;

void GetCamera(vec2 uv, vec3 res, out vec3 ro, out vec3 rd)
{
    ro = cameraEye;
    vec2 uv_centered = uv - 0.5;  // [-0.5, 0.5]

    float vlen = tan(cameraFOV / 2.0);
    float hlen = vlen * cameraAspect;

    vec3 forward = normalize(cameraCenter - cameraEye);
    rd = normalize(
        forward +
        cameraRight * (uv_centered.x * hlen * 2.0) +
        cameraUp    * (uv_centered.y * vlen * 2.0)
    );
}

vec2 GetUV(vec3 rd, vec3 res)
{
    return rd.xy / (rd.z / CAM_Z) / vec2(res.x / res.y, 1.0) + 0.5;
}
```

### 3.2 全屏三角形顶点着色器

```hlsl
VertexOutput ScreenTriangleVertexShader(uint vertexId : SV_VertexID, uint instanceId : SV_InstanceID)
{
    VertexOutput output = (VertexOutput)0;

    uv = vertexId == 2 ? float2( 3.0f,-1.0f) : uv;
```

## 四、进阶应用（≥500字）

### 与其他主题的关联

- **延迟渲染**：GBuffer 解码世界坐标时，用深度值 + 逆 MVP 重建世界位置，避免在 GBuffer 中存储完整 3D 坐标
- **后处理**：全屏三角形是现代后处理的标准做法，Blit Pass、Tone Mapping、Bloom 都基于此
- **光线追踪**：从屏幕像素生成世界空间射线，本质是逆 MVP + 视锥体参数

### 全屏三角形 vs 全屏四边形

后处理传统做法是渲染一个屏幕大小的四边形（2 个三角形），现代做法改用 1 个超大三角形（Full Scene Triangle）：

| 指标 | Full Scene Quad (2△) | Full Scene Triangle (1△) |
|------|----------------------|--------------------------|
| 顶点数 | 4→6 | 3 |
| Tile Overdraw | 对角线处重复光栅化 | 无重叠 |
| L1/L2 缓存命中率 | ~87% | ~95% |
| 相对性能 | 100% | ~108% |

**Tile Overdraw 原理**：现代 GPU 以 Tile（至少 4×4 像素组）为单位光栅化。两个三角形对角线交界处会产生重叠 Tile，同一像素执行两次 fragment shader。单个三角形没有对角线，无此问题。

**缓存命中率**：两个三角形缺乏空间连续性，光栅化从左下角切换到右上角时缓存预测中断。单个三角形的光栅化顺序连续，纹理采样时的空间局部性更好。

### Guard-band Clipping

GPU 处理全屏三角形时不会真的裁剪成多个小三角形，因为现代 GPU 使用 Guard-band clipping：

- ViewPort（白色蓝框）外有一个"保护带"（红色区域）
- 只有完全超出保护带的三角形才被裁剪
- 全屏三角形虽超出 ViewPort 但仍在保护带内，保持为一个三角形

### 从深度图重建世界坐标

全屏三角形下需要用相似三角形重新推导：

- 近平面 BCDE 四个角坐标可通过 FOV + 宽高比计算
- 对于屏幕上任意像素，通过其 UV 在近平面四角间插值得到近平面交点
- 乘以 `depth * farPlaneDir` 得到世界坐标

## 五、源码解析和实践感悟（≥1000字）

### 关键实现路径

**投影矩阵的逆矩阵推导（补充）**

透视投影矩阵（OpenGL 右手坐标系）：

```
P = | 2n/(r-l)    0       (r+l)/(r-l)     0     |
    |    0     2n/(t-b)   (t+b)/(t-b)     0     |
    |    0        0      -(f+n)/(f-n)  -2fn/(f-n)|
    |    0        0          -1            0     |
```

其中 n=近平面, f=远平面, l/r/t/b=近平面边界。

逆矩阵：
```
P⁻¹ = | (r-l)/(2n)   0          0        (r+l)/(2n) |
      |    0      (t-b)/(2n)     0        (t+b)/(2n) |
      |    0          0          0          -1       |
      |    0          0     -(f-n)/(2fn)  (f+n)/(2fn)|
```

关键洞察：P⁻¹ 的第 4 列不是 (0,0,0,1)，意味着逆投影会改变 w 分量。从 NDC 坐标 `(x_ndc, y_ndc, z_ndc, 1)` 逆推时，得到的 `w_view` 不再是 1，需要通过除法恢复正确的观察空间坐标。

### 难点与易错点

**陷阱1：法线变换不能用 MVP**

法线是方向向量（w=0），且需要保持垂直于表面。非均匀缩放会破坏垂直性。正确做法是用 Model 矩阵的逆转置：
```glsl
mat3 normalMatrix = transpose(inverse(mat3(model)));
vec3 worldNormal = normalMatrix * a_normal;
```
如果 Model 矩阵只有旋转和均匀缩放，可以简化为 `mat3(model)`。

**陷阱2：深度重建时的精度问题**

从深度缓冲反推世界坐标时，`z_ndc` 先映射回 `z_view`，再乘以远平面方向。但 `z_view` 对近平面的变化非常敏感——近平面附近 1mm 的深度误差可能对应远处几米的误差。工程上常用 Reverse-Z（近平面=1.0, 远平面=0.0）来平衡精度分布。

**陷阱3：全屏三角形的 UV 推导**

全屏三角形只有 3 个顶点，没有显式的 UV 坐标。需要在 shader 中用 `SV_Position` 或 `gl_FragCoord` 反推 UV。注意 Vulkan 的 NDC Y 轴向上（与 OpenGL 相反），`gl_FragCoord.y` 需要翻转。

### 经验总结

1. **MVP 是管线的骨架**：理解 MVP 的每一层的物理意义比记住公式更重要——Model 回答"物体在哪"，View 回答"相机怎么看"，Projection 回答"如何投影到屏幕"
2. **全屏三角形是现代后处理的标配**：UE5、Unity HDRP 的后处理链都默认使用 Full Scene Triangle，少一个对角线 = 少 8% 的 fragment 开销
3. **深度重建优于存世界坐标**：在 GBuffer 中存深度值（1 float）再用逆 MVP 重建世界坐标，比直接存世界坐标（3 float）节省 2/3 带宽，且精度可控（选 Reverse-Z）
4. **Guard-band 是个好设计**：它避免了屏幕边缘三角形的拆分开销，是硬件层面的"免费午餐"

## 六、面试准备

### 6.1 高频问法（≥8个）

**基础理解：**

Q1：MVP 三个矩阵分别做了什么？

A：Model 将物体从局部空间变换到世界空间（位移+旋转+缩放）；View 将世界空间变换到以相机为原点的观察空间；Projection 将观察空间投影到裁剪空间（透视/正交），最终经透视除法和视口变换到屏幕。

Q2：为什么用 4×4 齐次坐标而不是 3×3？

A：3×3 只能表示线性变换，不能表示平移。齐次坐标将平移写入第 4 列，且 w 分量支持透视除法。

Q3：全屏三角形比全屏四边形好在哪？

A：两点：1) 少一个对角线，避免 Tile Overdraw（重叠 tile 的重复 fragment 计算），性能约 +8%；2) 光栅化顺序连续，L1/L2 缓存命中率从 87% 提升到 95%。

**原理深入：**

Q4：透视除法的数学原理是什么？

A：投影矩阵将观察空间的 z 编码到 w 分量：`w_clip = -z_view`。透视除法 `(x/w, y/w, z/w)` 使远物体坐标缩小，实现近大远小。这是 GPU 硬件固定功能，顶点着色器输出后自动执行。

Q5：如何从深度图重建世界坐标？

A：1) 从深度缓冲采样 depth，映射回 NDC 的 z；2) 用逆投影矩阵将 NDC 坐标变换回观察空间；3) 乘以观察空间中的远平面方向（由 FOV + 宽高比 + UV 算出）；4) 用逆 View 矩阵变换到世界空间。

**实践应用：**

Q6：法线变换为什么用逆转置矩阵？

A：非均匀缩放会破坏法线的垂直性。对法线 n 做变换 `(M⁻¹)ᵀ n` 可以保证变换后的法线仍垂直于变换后的表面。如果 M 只有旋转和均匀缩放，可以简化为 `M` 本身。

Q7：不同图形 API 的 NDC 差异如何适配？

A：OpenGL NDC：z∈[-1,1]，Y 轴向上；Vulkan NDC：z∈[0,1]，Y 轴向下；DirectX NDC：z∈[0,1]，Y 轴向上。适配方法：投影矩阵调整 z 映射范围；shader 中 `gl_FragCoord.y` 翻转。

Q8：Guard-band clipping 是什么？为什么重要？

A：GPU 在 ViewPort 外设置一个"保护带"，只有完全超出保护带的三角形才被裁剪。这避免了屏幕边缘三角形被拆分的开销，使全屏三角形优化得以生效。

### 6.2 反问点/陷阱点（≥5个）

- 您在实际项目中有遇到因为 NDC 差异导致的跨平台渲染 bug 吗？通常怎么统一处理？
- 贵公司的后处理链用 Full Scene Triangle 还是 Quad？有没有 Profile 过两者差距？
- Reverse-Z 在移动端 GPU 上也同样有效吗？Adreno/Mali 的深度精度分布和桌面 GPU 有什么不同？

**常见陷阱：**

- 陷阱1：忘记了 `gl_Position.w` 在透视除法前的含义——w 必须是 `-z_view`（OpenGL）或 `z_view`（Vulkan），否则透视除法后坐标错误。
- 陷阱2：深度重建时直接用 `z_ndc` 而没做线性化——NDC 的 z 是非线性的（1/z 分布），需要先转换回线性深度。
- 陷阱3：全屏三角形在 OpenGL 中用 `gl_VertexID`，在 Vulkan/DX12 中用 `SV_VertexID`，但默认行为可能不同——Vulkan 需要启用 `VK_KHR_shader_draw_parameters` 或使用 push constant 传入 vertex ID。

### 6.3 一句话答案（≥5个）

- MVP 是从物体到屏幕的唯一必经之路：Model→World, View→Camera, Projection→Screen。
- 透视除法的本质：用 w 分量存储深度信息，除法实现近大远小。
- 全屏三角形好于四边形的根本原因：没有对角线，避免了 Tile Overlap 和缓存中断。
- 深度重建的性价比：存 1 个 float 的深度 + 重建计算 << 存 3 个 float 的世界坐标。
- Reverse-Z 的价值：将 z 精度从近平面集中改为远平面均匀分布，解决远处 z-fighting。

**情景模拟：**

- 被问到"法线变换注意事项"→ "非均匀缩放时法线要用逆转置矩阵变换，否则法线不再垂直于表面，光照计算全错。"
- 被问到"如何生成屏幕空间射线"→ "从像素的 NDC 坐标出发，用逆 Projection 到 View Space，再用逆 View 到 World Space，方向 = WorldPos - CameraPos。"

## 附录（模板外原内容收纳）

### 坐标空间详解

局部空间是指物体所在的坐标空间。在建模软件中创建的立方体原点可能位于 (0,0,0)，所有顶点都相对于物体自身。

世界空间使用模型矩阵将物体从局部坐标变换到世界坐标，支持位移、缩放、旋转。

观察空间通过观察矩阵将世界坐标变换到以摄像机为原点的空间，是从摄像机视角观察到的空间。

裁剪空间通过投影矩阵将观察坐标变换到裁剪坐标。所有在指定范围外的坐标被裁剪。投影矩阵创建的观察箱称为平截头体（Frustum）。

屏幕空间通过视口变换将 NDC 坐标映射到实际屏幕像素坐标。
