# 进程和线程

> 适用范围：操作系统核心概念——进程、线程、协程的定义、区别与通信机制。

## 一、项目/模块概述

- **模块定位**：操作系统基础概念梳理——进程（资源分配单位）、线程（调度执行单位）、协程（用户态并发单位）的定义、区别、同步与通信方式。
- **技术栈与依赖**：操作系统内核（Linux/Windows）、POSIX 线程库、CPU 调度器。
- **模块边界**：从概念定义到工程实践——进程间通信（IPC）、线程同步机制、调度算法、异常状态处理。

## 二、架构设计（≥200字）

### 设计拆解（三层递进）

**第一层：进程、线程、协程的定义与关系**

- **进程**：一个正在运行的程序实例。程序是静态的，而进程是动态的。进程是程序段在某个数据段上的一次运行活动。比如同时打开三个 QQ 程序，对应的就是三个 QQ 进程，程序段是一样的，而数据段不一样。进程包括了 PCB 进程控制块、数据段、程序段。其中 PCB 进程控制块是进程存在的唯一标识，对进程的创建撤销操作都是对 PCB 的操作。**进程是操作系统进行资源分配的基本单位。**
- **线程**：也称为轻量级进程，一个进程中包含多个线程，线程共享进程的资源。**线程是处理器调度的基本单位。**
- **协程**：可以视为用户态的轻量级线程。它允许在单个线程内实现并发操作，通过在特定的点暂停和恢复执行来达到类似多线程的效果，但不需要像线程那样进行复杂的上下文切换（涉及内核态和用户态的切换等）。

**第二层：为什么有了进程还要有线程？**

多个线程可以并发处理不同任务，并且可以充分利用多核 CPU，并行处理。进程虽然也可以并发，但是需要上下文切换，开销很大，线程切换的成本比进程切换的成本低很多。

**第三层：关键设计决策——资源分配 vs 调度执行的分离**

| 维度 | 进程 | 线程 |
|------|------|------|
| 本质区别 | 操作系统资源分配的基本单位 | 处理器任务调度和执行的基本单位 |
| 包含关系 | 一个进程至少有一个线程，线程是进程的一部分 | 线程也称为轻权进程或轻量级进程 |
| 资源开销 | 每个进程有独立地址空间，切换开销大 | 共享进程地址空间，切换开销小 |
| 影响关系 | 进程崩溃不影响其他进程（保护模式） | 线程崩溃可能导致整个进程被 OS 杀掉 |
| 健壮性 | 多进程 > 多线程 | 多线程 < 多进程 |

### 线程共享与私有资源

**线程私有资源**：所属线程的栈区、程序计数器、栈指针以及函数运行使用的寄存器是线程私有的。以上这些信息有一个统一的名字，就是线程上下文，thread context。

**共享资源**：
- **代码区**：保存编译后的可执行机器指令
- **数据区**：存放全局变量
- **堆区**：用 malloc 或 new 出来的数据，只要知道变量的地址（指针）即可访问

## 三、核心实现（代码走读）

### 线程同步

**什么是线程同步？** 线程同步是指控制线程的执行顺序，避免多线程下共享资源冲突使用。

**线程同步的方式：**

1. **互斥锁**：同一时刻只有一个线程可以访问共享资源
2. **信号量**：同一时刻控制可以访问共享资源的线程数量
3. **屏障**：多个线程同时到达一个点，才会继续执行

### 进程的五种状态

创建态、就绪态、运行态、阻塞态、结束态。

- 获取到时间片：从就绪态 → 运行态
- 等待 IO 事件：从运行态 → 阻塞态

### 线程的六种状态

创建态、可运行态、等待态、计时等待态、阻塞态、结束态

### 进程间通信的方式（7种）

1. **匿名管道（Unnamed Pipes）**：用于亲缘关系的进程间通信，如父子进程或兄弟进程。通常是单向的，用于简单的字节流传输
2. **有名管道（Named Pipes）**：可以在不相关的进程间进行通信，作为文件系统中一个特殊的文件（如磁盘文件）存在
3. **信号（Signals）**：进程间的异步通知机制，告知目标进程某个特定事件发生了。信号并不携带大量数据，更多用于控制流和简单通知
4. **消息队列（Message Queues）**：遵循先进先出，存放在内核中，只有内核重启或显式删除一个消息队列时该消息队列才会被真正删除，可实现消息的随机查询；允许复杂的数据结构传输
5. **信号量**：主要用于进程同步，确保共享资源的正确访问。信号量是计数器，通过原子操作（P/V 或 wait/signal 操作）防止竞争条件
6. **共享内存（Shared Memory）**：允许两个或更多进程共享一块内存区域，它是最快的 IPC 方式之一
7. **套接字（Sockets）**：用于在计算机网络中不同主机上的进程之间的通信，尽管也可用于同一台机器上的进程间通信（称为 Unix 套接字）

### 进程切换的场景

- **进程阻塞**：当前进程在等待 I/O 操作，CPU 可以切换到其他进程
- **时间片耗尽**：在时间片调度算法中，进程运行时间超过分配到的时间片，操作系统会强制切换到下一个进程
- **优先级调度**：更高优先级的进程到来时，操作系统可能会中断当前进程，切换到高优先级进程
- **同步机制**：进程在等待某个资源（未获取锁）时会被挂起，操作系统切换到其他进程

### 进程的调度算法

1. **先到先服务调度算法**：最先进入就绪队列的进程
2. **短作业优先算法**：估计运行时间最短的进程
3. **时间片轮转算法**：每个进程分配一个时间片
4. **优先级调度算法**：为进程分配优先级
5. **多级反馈队列调度算法**：综合了上述几种调度算法，既能让高优先级的得到响应又能快速完成短作业

## 四、工程实践（≥500字）

### 僵尸进程和孤儿进程

- **僵尸进程**：子进程终止了，但父进程没有释放子进程占用的资源，导致子进程的 PCB 依然存在系统中。通过 `top` 命令查看，进程状态为 Z 的是僵尸进程。
- **孤儿进程**：父进程终止了，但子进程仍在运行。会将孤儿进程的父进程设置为 init 进程，由 init 进程来释放孤儿进程占用的资源。

### 常见优化策略

**进程 vs 线程——场景选择**

| 场景 | 推荐 | 理由 |
|------|------|------|
| 高并发 Web 服务器 | 线程池/协程 | 上下文切换开销小，共享内存方便 |
| Chrome 浏览器标签页 | 多进程 | 一个标签页崩溃不影响其他 |
| 数据库连接池 | 线程 | 共享连接对象，减少内存占用 |
| 微服务部署 | 多进程（容器） | 隔离性好，独立扩缩容 |
| Nginx | 多进程 | 利用多核 + 进程间独立，稳定性高 |

**线程同步策略选择**

| 策略 | 适用场景 | 开销 |
|------|----------|------|
| 互斥锁 | 临界区保护 | 中等（可能阻塞） |
| 读写锁 | 读多写少 | 低（读并发） |
| 自旋锁 | 临界区极短 | 低（但浪费 CPU） |
| 无锁（CAS） | 简单数据结构 | 最低 |
| 信号量 | 资源计数控制 | 中等 |
| 条件变量 | 等待特定条件 | 中等（配合 mutex） |

**IPC 选择指南**

| IPC 方式 | 速度 | 适用场景 |
|----------|------|----------|
| 共享内存 | 最快 | 大数据量频繁交换 |
| 管道 | 中等 | 父子进程简单通信 |
| 消息队列 | 中等 | 结构化数据传递 |
| 信号量 | N/A | 进程同步（非数据传输） |
| 信号 | 快 | 简单通知/控制 |
| 套接字 | 慢 | 跨主机/通用性强 |

### 生产环境考量

- **进程监控**：使用 supervisor/systemd 管理进程生命周期，自动重启崩溃进程
- **僵尸进程清理**：父进程必须调用 `wait()`/`waitpid()` 回收子进程；或使用 `SIGCHLD` 信号处理；或设置 `signal(SIGCHLD, SIG_IGN)`
- **孤儿进程处理**：由 init 进程（PID=1）接管回收
- **线程泄漏检测**：确保 `pthread_join` 或 `detach` 调用，使用 valgrind/AddressSanitizer
- **死锁预防**：统一加锁顺序、使用 `try_lock` + 超时、RAII 风格锁管理（`std::lock_guard`）

## 五、源码解析和实践感悟（≥1000字）

### 关键实现路径

**进程控制块（PCB）的核心**

PCB 是内核中代表进程的数据结构，包含：
- 进程状态（运行/就绪/阻塞等）
- 程序计数器（下一条指令地址）
- CPU 寄存器快照
- CPU 调度信息（优先级、调度队列指针）
- 内存管理信息（页表、段表）
- IO 状态信息（打开的文件描述符表）
- 记账信息（CPU 使用时间、时钟数）

**线程上下文切换的实际开销**

一次线程切换的典型开销（Linux x86_64）：
- 保存/恢复寄存器：~20 条 mov 指令
- TLB 刷新：切换进程时清空 TLB（线程切换不需要）
- 缓存冷启动：切换到不同进程时，L1/L2/L3 缓存命中率骤降
- 总计：同进程线程切换约 1-2μs，跨进程切换约 3-10μs

### 难点与易错点

**难点 1：僵尸进程的危害与排查**

僵尸进程本身不占用内存（大部分资源已释放），但占用 PID。Linux PID 上限默认 32768，如果僵尸进程积累过多，将无法创建新进程。排查命令：`ps aux | grep Z`，找到父进程后使其调用 `waitpid()` 或直接 kill 父进程。

**难点 2：线程栈大小设置**

Linux 默认线程栈 8MB（`ulimit -s`），高并发场景下 10000 个线程仅栈就占用 80GB 虚拟内存。实际使用中可以通过 `pthread_attr_setstacksize` 设置更小的栈（如 256KB），但必须确保递归深度和局部变量不会溢出。

**难点 3：fork 与多线程的交互**

多线程程序中 `fork()` 后，子进程只有调用 `fork()` 的那一个线程。这意味着其他线程持有的锁在子进程中永远无法释放。解决方案：`fork()` 后立即 `exec()`，或使用 `pthread_atfork()` 注册回调在 fork 前后处理锁。

**难点 4：协程的栈管理**

有栈协程（如 Go 的 goroutine）的栈初始很小（几 KB），可以动态增长；无栈协程（如 C++20 coroutine、JavaScript async/await）依赖编译器将状态保存到堆上。前者切换快但内存管理复杂，后者分配灵活但有堆分配开销。

### 经验总结

1. **能用线程就不自己管理进程**：进程管理更重，IPC 更复杂。大多数服务端程序使用「多进程 + 每进程多线程」的混合模型
2. **线程同步优先使用高级抽象**：`std::mutex` + `std::lock_guard` > `pthread_mutex_t`，`std::condition_variable` > `pthread_cond_t`
3. **协程是并发不是并行**：协程运行在同一线程内，无法利用多核。需要真正的并行时还是要使用多线程或多进程
4. **IPC 首选共享内存**：如果只是同一机器上的进程间通信，共享内存 + 信号量/互斥锁是最高效的方案
5. **监控是运维的基础**：至少监控进程数量、僵尸进程数量、线程数量、上下文切换率

## 六、面试准备

### 6.1 高频问法（≥10个）

**基础理解：**

Q1：进程和线程的区别是什么？

A：进程是操作系统资源分配的基本单位，线程是 CPU 调度的基本单位。进程有独立地址空间，线程共享进程地址空间。进程切换开销大（需要切换页表、TLB 刷新等），线程切换开销小（只需切换寄存器和栈）。

Q2：什么是协程？与线程的区别？

A：协程是用户态的轻量级"线程"，由用户程序而非操作系统调度。线程切换涉及内核态/用户态切换，协程切换只在用户态，开销更低（纳秒级 vs 微秒级）。但协程无法利用多核，需要配合多线程实现真正并行。

Q3：什么是线程同步？有哪些方式？

A：线程同步是控制多个线程对共享资源的访问顺序。三种方式：1) 互斥锁（mutex）——同一时刻一个线程访问 2) 信号量（semaphore）——控制同时访问的线程数量 3) 屏障（barrier）——多个线程到达同一点后继续。

**原理深入：**

Q4：进程的 5 种状态是什么？如何转换？

A：创建态 → 就绪态（初始化完成）→ 运行态（获得时间片）→ 阻塞态（等待 IO/资源）→ 就绪态（IO 完成）→ 运行态 → 结束态。

Q5：7 种进程间通信方式各自的优缺点？

A：匿名管道（简单但仅亲缘进程）、有名管道（可跨进程但有文件系统开销）、信号（快但数据量极小）、消息队列（结构化数据但内核持久化开销）、信号量（仅同步非数据传递）、共享内存（最快但需同步机制）、套接字（跨主机但协议栈开销大）。

Q6：线程共享进程的哪些资源？哪些是私有的？

A：共享：代码区、数据区（全局变量）、堆区、打开的文件描述符表。私有：栈区、程序计数器、寄存器（统称线程上下文）。

**实践应用：**

Q7：僵尸进程和孤儿进程的区别？如何处理？

A：僵尸：子进程已退出但父进程未回收 PCB，占用 PID。解决：父进程调用 `wait()`/`waitpid()`。孤儿：父进程先于子进程退出，子进程由 init 接管回收。

Q8：多线程程序中 fork() 有什么风险？

A：子进程只复制调用 fork 的线程，其他线程持有的锁在子进程中变成"死锁"状态。解决方案：`fork()` 后立即 `exec()` 或使用 `pthread_atfork()`。

Q9：高并发服务器应该用多进程还是多线程？

A：Nginx 用多进程（稳定性优先），Redis 用单线程（简单性优先），现代 Go/Java 服务用多线程+协程（性能优先）。取决于隔离性要求和共享数据量。

Q10：多级反馈队列调度算法的核心思想是什么？

A：结合多种调度算法的优势：高优先级队列时间片短（保证响应速度），低优先级队列时间片长（减少切换开销）。新进程先入高优先级，用完时间片降级；IO 密集型进程能快速回到高优先级。

### 6.2 反问点/陷阱点（≥5个）

**针对面试官的深度问题：**

- 贵公司服务端程序中的线程模型是怎样的？是否采用了协程（如 C++20 coroutine）？
- 在多进程架构中，你们如何管理进程的生命周期和健康检查？

**常见陷阱问题：**

- 陷阱 1："多线程一定比单线程快吗？"——不一定。线程切换有开销，且共享数据的锁竞争可能使多线程更慢。IO 密集型任务多线程有优势，CPU 密集型任务线程数超过核心数反而变慢。
- 陷阱 2："进程通信一定比线程通信慢吗？"——共享内存方式的 IPC 速度和线程间共享内存几乎一样。慢的是数据拷贝方式（管道、消息队列）。
- 陷阱 3："kill -9 能杀死僵尸进程吗？"——不能。僵尸进程已经死亡，kill 对其无效。只能通过父进程 waitpid() 或 kill 父进程来清理。

### 6.3 一句话答案（≥5个）

- 进程的核心是：资源分配单位，拥有独立地址空间，通过 PCB 标识和管理。
- 线程的核心是：CPU 调度单位，共享进程资源，切换开销小。
- 协程的核心是：用户态切换的"轻量线程"，开销纳秒级但非真正并行。
- 避免的常见错误是：多线程程序中直接 fork()（导致子进程死锁）、忘记回收子进程（产生僵尸进程）。
- 进程间通信的最快方式是：共享内存 + 信号量/互斥锁同步。
- 当被问到"如何选择进程还是线程"时回答："需要高隔离性 → 多进程；需要高效数据共享 → 多线程；两者都不够 → 多进程 + 每进程多线程。"
