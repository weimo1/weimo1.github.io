# 宏

长用宏定义：

## 1、用宏参数创建字符串：#[运算符](https://zhida.zhihu.com/search?content_id=202409437&content_type=Article&match_order=1&q=%E8%BF%90%E7%AE%97%E7%AC%A6&zhida_source=entity)

下面是一个类函数宏：

```
#define PSQR(x) printf("The square of x is %d.\n",((x)*(x)))
```

假设这样使用宏：

```
PSQR(8);
```

输出为：

```
"The square of x is 64."
```

注意[双引号字符串](https://zhida.zhihu.com/search?content_id=202409437&content_type=Article&match_order=1&q=%E5%8F%8C%E5%BC%95%E5%8F%B7%E5%AD%97%E7%AC%A6%E4%B8%B2&zhida_source=entity)中的x被视为普通文本，而不是一个可被替换的记号。

C允许在字符串中包含[宏参数](https://zhida.zhihu.com/search?content_id=202409437&content_type=Article&match_order=2&q=%E5%AE%8F%E5%8F%82%E6%95%B0&zhida_source=entity)。**在类函数宏的替换体中，#号作为一个**[**预处理**](https://zhida.zhihu.com/search?content_id=202409437&content_type=Article&match_order=1&q=%E9%A2%84%E5%A4%84%E7%90%86&zhida_source=entity)**运算符，可以把记号转换成字符串**。例如，如果x是一个宏形参，那么#x就是转换为字符串"x"的形参名。这个过程成为[字符串化](https://zhida.zhihu.com/search?content_id=202409437&content_type=Article&match_order=1&q=%E5%AD%97%E7%AC%A6%E4%B8%B2%E5%8C%96&zhida_source=entity)（stringizing）。

演示用例如下：

```
/* subst.c -- substitute in string */
#include <stdio.h>
#define PSQR(x) printf("The square of " #x " is %d.\n",((x)*(x)))

int main(void)
{
    int y = 5;
    
    PSQR(y);
    PSQR(2 + 4);
    
    return 0;
}
```

该程序的输出如下：

```
The square of y is 25.
The square of 2 + 4 is 36.
```

调用第1个宏时，用"y"替换#x。调用第2个宏时，用"2 + 4"替换#x。ANSI C字符串的串联特性将这些字符串与printf()语句的其他字符串组合，生成最终的字符串。例如，第一次调用变成：

```
printf("The square of " "y" " is %d.\n",((y)*(y)));
```

然后，字符串串联功能将这3个相邻的字符串组合成一个字符串：

```
"The square of y is 25."
```

## 2、预处理器黏合剂：##运算符

与#运算符类似，##运算符可用于类宏函数的替换部分。而且，##还可用于对象宏的替换部分。**##运算符把两个记号组合成一个记号**。例如：可以这样做：

```
#define XNAME(n) x ## n
```

然后，宏XNAME(4)将展开为x4。

演示用例如下：

```
// glue.c -- use the ## operator
#include <stdio.h>
#define XNAME(n) x ## n
#define PRINT_XN(n) printf("x" #n " = %d\n", x ## n);

int main(void)
{
    int XNAME(1) = 14;  // becomes int x1 = 14;
    int XNAME(2) = 20;  // becomes int x2 = 20;
    int x3 = 30;
    PRINT_XN(1);        // becomes printf("x1 = %d\n", x1);
    PRINT_XN(2);        // becomes printf("x2 = %d\n", x2);
    PRINT_XN(3);        // becomes printf("x3 = %d\n", x3);
    return 0;
}
```

该程序的输出如下：

```
x1 = 14
x2 = 20
x3 = 30
```

注意：PRINT\_XN(n)宏用#运算符组合字符串，##运算符把记号组合成一个新的标识符。

## 3、[变参宏](https://zhida.zhihu.com/search?content_id=202409437&content_type=Article&match_order=1&q=%E5%8F%98%E5%8F%82%E5%AE%8F&zhida_source=entity)：...和\_\_VA\_ARGS\_\_

一些函数（如printf()）接受数量可变的参数。stdvar.h[头文件](https://zhida.zhihu.com/search?content_id=202409437&content_type=Article&match_order=1&q=%E5%A4%B4%E6%96%87%E4%BB%B6&zhida_source=entity)提供了工具，让用户自定义带可变参数的函数。C99/C11也对宏提供了这样的工具。

通过把宏[参数列表](https://zhida.zhihu.com/search?content_id=202409437&content_type=Article&match_order=1&q=%E5%8F%82%E6%95%B0%E5%88%97%E8%A1%A8&zhida_source=entity)中最后的参数写成省略号（即，3个点...）来实现这一功能。这样，**预处理宏\_\_VA\_ARGS\_\_可用在替换部分中，表示省略号代表什么**。例如，下面的定义：

```
#define PR(...) printf(__VA_ARGS__)
```

假设稍后调用该宏：

```
PR("Howdy");
PR("Weight = %d, shipping = $%.2f\n", wt, sp);
```

对于第1次调用，\_\_VA\_ARGS\_\_展开为1个参数："Howdy"。

对于第2次调用，\_\_VA\_ARGS\_\_展开为3个参数："Weight = %d, shipping = $%.2f\n"、wt、sp。

因此，展开后的代码是：

```
printf("Howdy");
printf("Weight = %d, shipping = $%.2f\n", wt, sp);
```

演示用例如下：

```
// variadic.c -- variadic macros
#include <stdio.h>
#include <math.h>
#define PR(X, ...) printf("Message " #X ": " __VA_ARGS__)

int main(void)
{
    double x = 48;
    double y;
    
    y = sqrt(x);
    PR(1, "x = %g\n", x);
    PR(2, "x = %.2f, y = %.4f\n", x, y);
    
    return 0;
}
```

该程序的输出如下：

```
Message 1: x = 48
Message 2: x = 48.00, y = 6.9282
```

第1个宏调用，X的值为1，所以#X变为"1"。展开后为：

```
printf("Message " "1" ":" "x = %g\n", x);
```

然后，串联4个字符串，把调用简化为：

```
printf("Message 1: x = %g\n", x);
```

记住，省略号只能代替最后的宏参数：

```
#define WRONG(X, ..., Y) #X #__VA_ARGS__ #Y //错误用法，不可以这样做
```

## 4、加强版变参宏：##\_\_VA\_ARGS\_\_

##\_\_VA\_ARGS\_\_ 宏前面加上##的作用在于，**当**[**可变参数**](https://zhida.zhihu.com/search?content_id=202409437&content_type=Article&match_order=2&q=%E5%8F%AF%E5%8F%98%E5%8F%82%E6%95%B0&zhida_source=entity)**的个数为0时，这里的##起到把前面多余的","去掉的作用**，否则会编译出错。使用如下：

```
#define edebug(format, ...) fprintf (stderr, format, ##__VA_ARGS__)
```

如果可变参数被忽略或为空，## 操作将使[预处理器](https://zhida.zhihu.com/search?content_id=202409437&content_type=Article&match_order=2&q=%E9%A2%84%E5%A4%84%E7%90%86%E5%99%A8&zhida_source=entity)（preprocessor）去除掉它前面的那个逗号。

如果你在宏调用时，确实提供了一些可变参数，它会把这些可变参数放到逗号的后面。

演示用例如下：

```
#include <stdio.h>
#define LOGFUNC2(fmt,...) (printf(fmt" line:%d - %s/%s   \n",##__VA_ARGS__,__LINE__,__TIME__,__DATE__));

int main()
{
    //可变参数
    LOGFUNC2("i am C++ :%d name:%s age:%d",112,"C语言教程",18);// ok

    //字符串常量
    LOGFUNC2("i am C++ ");// ok
}
```

该程序的输出如下：

```
i am C++ :112 name:C语言教程 age:18 line:8 - 02:27:52/May 14 2022   
i am C++  line:11 - 02:27:52/May 14 2022
```

## 一、核心概念

- **定义**：宏是 C/C++ 预处理器的文本替换机制，在编译前由预处理器完成展开，不参与类型检查和语义分析
- **关键词**：`#define`、字符串化（`#`）、令牌粘贴（`##`）、变参宏（`__VA_ARGS__`）、条件编译（`#ifdef`）、`do-while(0)`惯用法
- **适用场景/边界**：条件编译（跨平台）、断言与日志（`__FILE__`/`__LINE__`）、编译期常量（C 语言场景）、X-Macro 代码生成；边界：不做类型检查、不可调试、易引发副作用

## 二、详细解析（≥200字）

- **原理拆解（三层递进）**：
  - **第一层——预处理工作流**：C/C++ 编译分为预处理 → 编译 → 汇编 → 链接四阶段。宏在预处理阶段完成：头文件展开（`#include`）→ 宏定义替换（`#define`）→ 条件编译（`#if/#ifdef`）→ 生成纯净 translation unit
  - **第二层——宏展开规则**：宏参数按字面替换（非求值）；`#` 运算符将参数转为字符串字面量；`##` 将两个相邻令牌拼接为一个；宏体中的参数被完整替换后不再递归展开自身
  - **第三层——底层陷阱**：宏是纯文本替换，不遵守 C++ 作用域和运算符优先级。`#define SQUARE(x) x*x` 中 `SQUARE(a+b)` 展开为 `a+b*a+b`（优先级错误）；`#define MAX(a,b) ((a)>(b)?(a):(b))` 中 `MAX(x++,y++)` 导致参数多次求值
- **关键数据结构/接口**：预处理器维护符号表（宏名→替换文本），每个 `#define` 持续生效直到 `#undef` 或文件结束
- **关键公式**：`#x`→字符串化（`#42`→`"42"`）；`a##b`→拼接（`foo##bar`→`foobar`）；`##__VA_ARGS__`→空参数时吞掉前置逗号

## 三、动手实践（代码案例）

```c++
#include <iostream>

// 1. 字符串化运算符 #
#define TO_STRING(x) #x
#define LOG_VAR(x) std::cout << #x " = " << x << std::endl

// 2. 令牌粘贴运算符 ##
#define CONCAT(a, b) a##b

// 3. 变参宏（C++11）
#define LOG(fmt, ...) fprintf(stderr, "[%s:%d] " fmt "\n", __FILE__, __LINE__, ##__VA_ARGS__)

// 4. 多语句宏安全写法（do-while(0)）
#define SWAP(a, b) do { auto _tmp = (a); (a) = (b); (b) = _tmp; } while(0)

int main() {
    std::cout << TO_STRING(hello world) << std::endl;  // "hello world"
    
    int count = 42;
    LOG_VAR(count);  // 输出: count = 42
    
    int CONCAT(my, _var) = 100;  // int my_var = 100;
    std::cout << my_var << std::endl;  // 100
    
    LOG("count = %d, pi = %.2f", count, 3.14);
    // [main.cpp:24] count = 42, pi = 3.14
    
    int a = 1, b = 2;
    SWAP(a, b);
    // a = 2, b = 1
    
    return 0;
}
```

- **预期**：熟练掌握 `#`/`##`/`__VA_ARGS__`/`do-while(0)` 四大利器
- **补充**：C++20 引入 `__VA_OPT__(,)` 替代 `##__VA_ARGS__`，语义更清晰

## 四、进阶应用（≥500字）

- **与其他主题的关联**：与模板形成互补——宏负责条件编译、模板负责类型安全代码生成；与 C++20 `std::source_location` 共同实现日志系统；与编译期计算（constexpr）有重叠但不可互相替代
- **工程中的真实用法**：
  - **断言系统**：`#define ASSERT(cond) do { if(!(cond)) { fprintf(stderr, "ASSERT %s:%d: %s\n", __FILE__, __LINE__, #cond); abort(); } } while(0)`——同时利用 `__FILE__`/`__LINE__` 定位和 `#cond` 字符串化
  - **跨平台抽象**：`#ifdef _WIN32`/`__linux__`/`__APPLE__` 条件编译不同平台 API，是编译器无关的标配方案
  - **X-Macro 技术**：用宏生成重复代码——定义 `#define COLOR_TABLE X(RED) X(GREEN) X(BLUE)`，用两次 `#define X` 和 `#undef X` 分别生成枚举和字符串名，避免机械重复
  - **编译期开关**：`#define ENABLE_DEBUG 1` 配合 `#if ENABLE_DEBUG` 零成本排除调试代码
- **常见优化策略**：
  - **算法层面**：用 `constexpr`/`const` 替代 `#define` 常量（类型安全、可调试）；用 `inline` 函数模板替代函数式宏（副作用保护、可重载）
  - **模板方法**：`template<typename T> inline T max(T a, T b) { return a < b ? b : a; }` 完全替代 `#define MAX(a,b)`，类型安全且无副作用
  - **现代替代**：C++17 `if constexpr` 替代大量条件编译宏（但无法替代跨平台 API 选择）；C++20 `std::source_location` 替代 `__FILE__`/`__LINE__`
  - **具体技巧**：`#pragma once` vs include guard——`#pragma once` 非标准但所有编译器支持，更简洁，两者常并用防御；用 `__has_include`（C++17）检测头文件存在性；用 `static_assert` + 宏做编译期诊断

## 五、源码解析和实践感悟

### 1. 预处理器的工作流程

```c++
// 预处理阶段在编译之前:
// 1. 文本替换（宏展开）→ 2. 条件编译 → 3. 头文件展开 → 输入的 translation unit
// 宏不做类型检查，只是字符串级别的替换

#define MAX(a,b) ((a)>(b)?(a):(b))
// MAX(x++, y++) → ((x++)>(y++)?(x++):(y++))  ← 多次副作用！
```

### 2. 宏展开陷阱与防御

```c++
// 参数包围括号
#define SQUARE(x) (x)*(x)  // 问题: SQUARE(a+b) → (a+b)*(a+b) OK
// 但: 1/SQUARE(2) → 1/(2)*(2) = 1 而非 1/4
// 正确: #define SQUARE(x) ((x)*(x))

// 副作用问题:
#define MIN(a,b) ((a)<(b)?(a):(b))
// MIN(x++, y++) → x++ 或 y++ 被执行两次
```

### 3. 宏与模板的对比

```c++
// 宏: 文本替换，无类型，调试困难
// 模板: 类型安全的代码生成，可调试
// 宏的优势: 字符串化(#), 令牌粘贴(##), 条件编译(#if), 源位置(__FILE__/__LINE__)
```

### 实践经验
1. **优先用 constexpr/模板替代宏**：`#define PI 3.14` → `constexpr double PI = 3.14`
2. **宏参数加括号**：`#define MUL(x,y) ((x)*(y))` 每条都用括号保护
3. **多语句宏用 do-while(0)**：`#define SWAP(a,b) do{auto t=a;a=b;b=t;}while(0)`
4. **__VA_ARGS__ 变参宏**：C++20 可用 `__VA_OPT__` 处理参数为空的情况
5. **条件编译用于跨平台**：`#ifdef _WIN32 ... #else ... #endif`

## 六、面试准备

### Q&A（10题）

**Q1: 宏和模板的区别？**
A: 宏是预处理器文本替换（无类型检查），模板是编译器类型安全的代码生成（有完整类型检查）

**Q2: 为什么宏参数要用括号包围？**
A: 防止运算符优先级导致意外结合，如 `SQUARE(a+b)` 不加括号变成 `a+b*a+b`

**Q3: # 和 ## 运算符的作用？**
A: # 将参数字符串化（`"x"`），## 将两个令牌粘贴为一个（`CONCAT(a,b)`→`ab`）

**Q4: 多语句宏的安全写法？**
A: `do { stmt1; stmt2; } while(0)` 确保在任何控制流中表现为单个语句

**Q5: #ifdef 和 if constexpr 的区别？**
A: #ifdef 在预处理阶段决定代码是否存在；if constexpr 在模板实例化阶段编译期选择分支

**Q6: 宏的副作用问题？**
A: `MAX(x++, y++)` 中 x 或 y 被自增两次——因为宏参数在展开中被多处使用

**Q7: __FILE__ 和 __LINE__ 是什么？**
A: 预定义宏，展开为当前文件名和行号，用于日志和断言

**Q8: #pragma once 和 include guard 的区别？**
A: #pragma once 非标准但更简洁，绝大多数编译器支持；include guard 是标准方案

**Q9: 如何定义变参宏？**
A: `#define LOG(fmt, ...) printf(fmt, __VA_ARGS__)`；C++20 可用 `__VA_OPT__(,)`

**Q10: 宏能递归吗？**
A: 不能，预处理器不支持递归宏展开

### 陷阱与反问（5个）
1. **陷阱**：`#define begin {` 和 `#define end }`→破坏 IDE 分析和代码可读性
2. **反问**：C++ 有了模板还需要宏吗？→ 需要！条件编译、断言、日志、跨平台仍然是宏的天下
3. **陷阱**：宏定义中的分号→`#define FOO() do{...}while(0);` 末尾分号会破坏 if-else
4. **反问**：X-Macro 技术是什么？→ 用宏生成重复代码的高级技巧
5. **陷阱**：`#define FOO(x) #x`→`FOLL(42)` 展开为 `"42"` 而非整数 42

### 一句话答案（8个）
1. **宏**：预处理器阶段的文本替换
2. **#运算符**：参数转字符串
3. **##运算符**：令牌粘贴
4. **do-while(0)**：多语句宏的安全写法
5. **__VA_ARGS__**：C++11 变参宏
6. **#ifdef**：条件编译，决定代码是否参与编译
7. **include guard**：`#ifndef X_H_` 防止头文件重复包含
8. **constexpr 替代**：类型安全的编译期常量
