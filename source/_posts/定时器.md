# 定时器

> 适用范围：高性能定时器系统设计、优先队列/时间轮/红黑树三种方案对比、muduo TimerQueue 源码分析、shared_ptr 延迟取消技巧

## 一、项目/模块概述

- **模块定位**：定时器是网络服务器的核心组件之一，负责管理超时连接关闭、心跳检测、周期任务调度等功能。高性能定时器需要支持海量定时任务的 O(1) 增删以及精确到毫秒级的触发精度。
- **技术栈与依赖**：C++17、`std::priority_queue` / `std::set`、`std::chrono`、智能指针（shared_ptr/weak_ptr）、Linux timerfd。
- **模块边界**：定时器不关心任务类型（连接销毁/心跳/周期业务），只负责"在指定时刻执行指定回调"。上层（如连接管理）负责决定何时添加/刷新/取消定时器。

## 二、架构设计

### 三种定时器方案对比

| 方案 | 数据结构 | 添加 | 删除 | 执行 | 适用场景 |
|------|----------|------|------|------|----------|
| 优先队列 | `std::priority_queue` | O(log n) | O(log n) | O(log n) | < 10万定时器，实现简单 |
| 红黑树 | `std::set` | O(log n) | O(log n) | O(log n) | muduo 方案，支持随时取消任意任务 |
| 分层时间轮 | 多层数组 | O(1) | O(1) | O(1) | > 10万定时器，精度可配置 |

### 时间轮核心原理

```
┌───────────────────────────────────────────────┐
│  时间轮（单层 8 槽示例）                        │
│                                               │
│   tick →  [0]  [1]  [2]  [3]  [4]  [5]  [6]  [7]
│            │    │         │                   │
│            ▼    ▼         ▼                   ▼
│         任务A 任务B     任务C               任务D
│                                               │
│  tick 每秒向前走一步，走到哪个槽就执行该槽任务    │
│  添加 3s 后的任务 → 放入 (tick+3) % 8 槽      │
└───────────────────────────────────────────────┘

分层时间轮（如 4 层 × 256 槽）：
  第0层：1 tick = 10ms，支持到 2.56s
  第1层：1 tick = 2.56s，支持到 655s
  第2层：1 tick = 655s，支持到 46h
  第3层：1 tick = 46h，支持到 ~490 天
  层级间逐级降级（cascade）
```

### muduo 方案：timerfd + 红黑树

```
EventLoop::poll()  ←─ timerfd 可读事件
        │
        ▼
TimerQueue::handleRead()
        │
        ├─ getExpired(now)      // 红黑树 lower_bound 查找到期任务
        ├─ for each: timer->run() // 执行回调
        └─ reset(expired, now)    // 重复任务重新插入，一次性任务删除
```

## 三、核心实现

### 3.1 优先队列定时器（TimerScheduler）

```cpp
class TimerScheduler {
    std::priority_queue<shared_ptr<TimerTask>,
                        vector<shared_ptr<TimerTask>>,
                        TimerTaskComparator> taskQueue_;
    unordered_map<TimerId, shared_ptr<TimerTask>> activeTimers_;
    unordered_set<TimerId> cancelledTimers_;

    // 核心逻辑：工作线程 wait_until 最早到期时间
    void workerLoop() {
        while (running_) {
            unique_lock<mutex> lock(mutex_);
            auto now = steady_clock::now();

            // 执行所有到期任务
            while (!taskQueue_.empty() && taskQueue_.top()->getExpiry() <= now) {
                auto task = taskQueue_.top(); taskQueue_.pop();
                if (cancelledTimers_.count(task->getId())) continue;

                lock.unlock(); // 执行回调时释放锁，防止死锁
                task->execute();
                lock.lock();

                if (task->isRepeating()) {
                    task->updateExpiry();
                    taskQueue_.push(task);
                }
            }
            // 精确等待到下一个任务到期时间
            if (taskQueue_.empty())
                cv_.wait(lock);
            else
                cv_.wait_until(lock, taskQueue_.top()->getExpiry());
        }
    }
};
```

### 3.2 分层时间轮（TimeWheelScheduler）

```cpp
class TimeWheelScheduler {
    static constexpr size_t WHEEL_SIZE = 256;
    static constexpr size_t WHEEL_COUNT = 4;
    vector<vector<shared_ptr<TimerTask>>> wheels_[WHEEL_COUNT];
    Duration tickDuration_{10ms};

    // 添加定时器：计算 ticks，逐层查找适合的层级
    void addToWheel(shared_ptr<TimerTask> task, uint64_t ticks) {
        for (size_t level = 0; level < WHEEL_COUNT; ++level) {
            if (ticks < WHEEL_SIZE) {
                size_t slot = (currentTick_ + ticks) % WHEEL_SIZE;
                wheels_[level][slot].push_back(task);
                return;
            }
            ticks /= WHEEL_SIZE; // 降级到更高层
        }
    }

    // 级联降级：高层时间轮向低层转移任务
    void cascadeTimers(size_t level) {
        size_t slot = (currentTick_ / (1ULL << (8 * level))) % WHEEL_SIZE;
        for (auto& task : wheels_[level][slot]) {
            uint64_t remaining = (task->getExpiry() - now) / tickDuration_;
            addToWheel(task, remaining); // 重新分配到下层
        }
        wheels_[level][slot].clear();
    }
};
```

### 3.3 muduo 方案：timerfd + set

```cpp
class TimerQueue {
    using Entry = pair<Timestamp, Timer*>;
    using TimerList = set<Entry>; // 红黑树，按 Timestamp 排序
    TimerList timers_;
    int timerfd_;                 // Linux timerfd 文件描述符
    Channel timerfdChannel_;      // 纳入 EventLoop 事件循环

    // 获取到期定时器
    vector<Entry> getExpired(Timestamp now) {
        Entry sentry(now, reinterpret_cast<Timer*>(UINTPTR_MAX));
        auto end = timers_.lower_bound(sentry); // 二分查找
        vector<Entry> expired(timers_.begin(), end);
        timers_.erase(timers_.begin(), end);
        return expired;
    }
};
```

## 四、工程实践

- **timerfd 的优势**：文件描述符可纳入 epoll 统一调度，与 I/O 事件同一线程处理，无需额外线程。read 返回累积超时次数，可处理"追时间"问题。
- **时间精度与性能的权衡**：时间轮精度受 tick 粒度限制（如 10ms）。降低 tick → 更高精度但 CPU 唤醒更频繁。优先队列精度最高（纳秒级）。
- **取消定时器的三种策略**：(1) 标记取消（cancelledTimers_ 集合），执行时跳过；(2) 主动从数据结构中删除（set erase）；(3) shared_ptr 引用计数 + 析构延迟（TimerWheel 方案）。
- **异常安全**：单个定时器回调异常不应影响其他定时器。在 try-catch 中执行回调，记录错误后继续处理后续任务。
- **定时器数量监控**：activeTimers_.size() 过大（>100万）可能表示内存泄漏或业务逻辑问题，应加告警。
- **多线程环境下**：定时器触发和执行应在固定线程（EventLoop 线程），避免回调中的线程安全问题。

## 五、源码解析

### 5.1 timerfd 基础使用

```cpp
// 创建定时器
int timerfd = timerfd_create(CLOCK_MONOTONIC, TFD_NONBLOCK | TFD_CLOEXEC);

// 设置超时：首次 1s，之后每 1s 重复
struct itimerspec itime;
itime.it_value.tv_sec = 1;      // 首次过期时间
itime.it_value.tv_nsec = 0;
itime.it_interval.tv_sec = 1;   // 之后每次间隔
itime.it_interval.tv_nsec = 0;
timerfd_settime(timerfd, 0, &itime, NULL);

// 定时器到期后，read 返回累积超时次数（uint64_t）
uint64_t expirations;
read(timerfd, &expirations, sizeof(expirations));
```

### 5.2 muduo TimerQueue 完整流程

```cpp
// 1. 添加定时器
void TimerQueue::addTimer(TimerCallback cb, Timestamp when, double interval) {
    Timer* timer = new Timer(std::move(cb), when, interval);
    loop_->runInLoop(bind(&TimerQueue::addTimerInLoop, this, timer));
}

void TimerQueue::addTimerInLoop(Timer* timer) {
    bool earliestChanged = insert(timer); // 插入红黑树
    if (earliestChanged) {
        resetTimerfd(timerfd_, timer->expiration()); // 更新 timerfd 到期时间
    }
}

// 2. timerfd 可读 → 处理到期
void TimerQueue::handleRead() {
    Timestamp now = Timestamp::now();
    readTimerfd(timerfd_); // 读取累积次数（消费事件）
    vector<Entry> expired = getExpired(now);

    for (auto& entry : expired) {
        entry.second->run(); // 执行回调
    }
    reset(expired, now); // 重复任务重新插入
}

// 3. 重置 timerfd
void TimerQueue::resetTimerfd(int timerfd_, Timestamp expiration) {
    struct itimerspec newValue;
    int64_t diff = expiration.microSecondsSinceEpoch() - Timestamp::now().microSecondsSinceEpoch();
    if (diff < 100) diff = 100; // 最小 100μs，防止频繁触发
    newValue.it_value = toTimespec(diff);
    ::timerfd_settime(timerfd_, 0, &newValue, NULL);
}
```

### 5.3 TimerWheel：shared_ptr + 析构函数实现延迟取消

这是原笔记中最精彩的设计，利用 C++ 智能指针的引用计数特性实现"刷新即延迟"：

```cpp
class TimerTask {
    ~TimerTask() {
        if (!_canceled) {
            _cb();        // 析构时才执行回调！
        }
        _release();       // 从 TimerWheel 的 _timers map 中移除自己
    }
};

class TimerWheel {
    using PtrTask = shared_ptr<TimerTask>;
    using WeakTask = weak_ptr<TimerTask>;
    unordered_map<uint64_t, WeakTask> _timers; // ⚠️ 必须用 weak_ptr

    void AddTimer(uint64_t id, uint32_t delay, const TaskFunc& cb) {
        PtrTask pt(new TimerTask(id, delay, cb, _tick));
        pt->SetReleaser(bind(&TimerWheel::RemoveTimer, this, id));
        int pos = (_tick + delay) % _capacity;
        _wheel[pos].push_back(pt);          // 计数 = 1
        _timers[id] = WeakTask(pt);         // weak_ptr 不增加计数！
    }

    void RefreshTimer(uint64_t id) {
        auto it = _timers.find(id);
        PtrTask pt = it->second.lock();     // 获取 shared_ptr，计数 +1
        if (!pt) return;
        int pos = (_tick + pt->GetDelayTime()) % _capacity;
        _wheel[pos].push_back(pt);          // 计数再 +1
    }

    void RunTimerTask() {
        _tick = (_tick + 1) % _capacity;
        _wheel[_tick].clear();              // 清空槽位 → shared_ptr 析构
        // 如果被 Refresh 过，槽位内的 shared_ptr 只是其中之一
        // 引用计数 -1 但不归零 → 不会真正析构 → 不执行回调
    }
};
```

**关键机制**：
- 添加任务：`_wheel[pos]` 持有 shared_ptr（计数=1），`_timers` 用 weak_ptr（不增加计数）
- 刷新任务：通过 weak_ptr.lock() 获取 shared_ptr，再次放入新槽位（计数+1）
- 时间轮推进：旧槽 clear → 计数-1，但若不归零（曾被刷新）→ 不析构 → 回调延迟执行

## 六、面试准备

### 6.1 高频问法

**Q1：定时器有哪几种实现方案？各自优劣？**
优先队列（O(log n)，实现简单，适合小规模）、红黑树/Set（O(log n)，支持按需删除任意任务）、分层时间轮（O(1)，适合海量任务，精度受 tick 限制）。

**Q2：时间轮为什么是 O(1)？**
添加：计算目标槽位直接 push_back（不涉及排序），O(1)；删除：标记取消或从槽位链表移除，O(1)；执行：只处理当前 tick 指向的槽，槽内任务数通常很小，均摊 O(1)。

**Q3：timerfd 相比 sleep/usleep 有什么优势？**
timerfd 是文件描述符，可纳入 epoll 统一事件循环，与 I/O 事件同线程处理，无需额外线程。支持绝对时间、read 返回累积次数避免漏触发。

**Q4：shared_ptr 如何实现定时任务延迟？**
任务对象的析构函数执行回调。Refresh 时创建新的 shared_ptr 放入新槽位，引用计数+1。旧槽 clear 时计数-1，若不归零则不析构 → 回调延迟到所有引用释放后才执行。

**Q5：为什么 TimerWheel 用 weak_ptr 存 _timers 映射？**
如果用 shared_ptr，_timers 会永久持有引用（计数永远≥1），任务永远不会被析构。weak_ptr 不增加计数，只提供"能否访问"的能力。

**Q6：muduo 为什么用红黑树（set）存定时器？**
set 天然有序（按 Timestamp 排序），lower_bound 可快速找到所有到期任务（O(log n + k)）。且支持 O(log n) 删除任意任务，TimerQueue 只有一个 timerfd，每次重置到最早到期时间即可。

**Q7：分层时间轮的级联（cascade）是什么意思？**
高层时间轮粒度粗（如第2层每格=655s），当该层指针移动到某格时，该格任务需重新插入低层（计算剩余 tick，重新分配槽位）。逐层降级直到第0层（最细粒度）到期执行。

**Q8：如何处理定时器回调中的"死锁"风险？**
执行回调前释放锁（lock.unlock()），回调执行完毕再重新加锁。避免用户在回调中再次操作定时器（如添加/取消）导致死锁。

**Q9：定时器精度如何保证？**
优先队列/红黑树 → 天然高精度（纳秒级），依赖系统时钟。时间轮 → 精度 = tick 粒度（如 10ms），高精度场景需缩小 tick 或混合方案。

**Q10：大量定时器（>100 万）的内存占用如何优化？**
时间轮方案中空槽不占额外内存（仅指针数组）。减少 TimerTask 对象大小（POD 数据 + 函数指针）、使用对象池批量分配、intrusive list（任务嵌入槽位链表节点而非独立分配）。

### 6.2 反问点

- 你们的定时器方案是优先队列、时间轮还是红黑树？为什么选这个？
- 定时器精度要求是多少？毫秒级还是微秒级？
- 有没有遇到过定时器回调阻塞导致后续任务堆积的问题？
- timerfd 在高并发下的表现如何？有没有做过压测？
- 重复定时器的 drift 问题（执行耗时导致漂移）如何处理？

### 6.3 一句话答案

- 时间轮 O(1) = 添加直写槽位 + 执行只清当前槽
- timerfd = 文件描述符定时器，纳入 epoll 统一事件循环
- shared_ptr 延迟取消 = Refresh 增加引用计数，旧槽 clear 不归零不析构
- weak_ptr in _timers = 不增加引用计数，避免永久持有
- 红黑树 lower_bound = O(log n + k) 找到所有到期任务
- 级联 = 高层时间轮任务降到低层重新分配
- 执行回调前 unlock = 避免用户在回调中操作定时器时死锁
