# NAT 网络地址转换

## 概述

NAT（Network Address Translation，网络地址转换）通过修改 IP 数据包头部中的地址信息，实现私有网络与公网之间的通信。由 RFC 1631 定义，是缓解 IPv4 地址耗尽问题的关键技术。

## NAT 类型

**静态 NAT**：私有 IP 地址一对一固定映射到公网 IP，常用于对外提供服务的服务器，如 Web 服务器、邮件服务器等。配置简单，但公网 IP 利用率低。

**动态 NAT**：从地址池中动态分配公网 IP，连接结束后释放回地址池。多个内部主机共享地址池中的公网 IP，但同一时刻一个公网 IP 只能被一个内部主机使用。

**PAT（端口地址转换）**：最常见的 NAT 形式，将多个私有地址映射到同一个公网 IP 的不同端口上。家庭路由器使用的就是这种方式，通过端口号区分不同的内部连接。理论上一个公网 IP 可支持约 6 万个并发连接。

## 工作原理

内部主机发送数据包到公网时，NAT 设备将源 IP 地址和源端口替换为公网 IP 和新分配的端口号，并将映射关系记录到 NAT 转换表中。当响应数据包到达时，NAT 设备根据转换表中的记录还原目标地址和端口，将数据包转发到原始的内部主机。转换表通常维护定时器，长时间无活动的映射会被自动清除。

## 优缺点

**优点**：节省公网 IPv4 地址资源，一个公网 IP 可支撑整个局域网访问互联网。隐藏内部网络拓扑结构，外部无法直接访问内网主机，增强安全性。部署简单，现有网络无需改造。

**缺点**：破坏端到端通信原则，影响 IP 层的端到端透明性。对 P2P 应用不友好，外部主机无法主动发起连接。增加数据包处理延迟，NAT 设备成为性能瓶颈。某些应用协议（如 FTP）需要在应用层处理地址转换。

## NAT 穿透技术

STUN 协议帮助客户端发现自己的公网映射地址和端口类型。TURN 协议通过中继服务器转发数据，适用于对称 NAT 场景。ICE 综合使用 STUN 和 TURN，选择最优通信路径。UPnP 允许设备自动配置端口映射规则，简化穿透配置。
