# 模板元

#### **2.2.1****模版偏特化和递归方式来展开参数包**

可变参数模板类的展开一般需要定义两到三个类，包括类声明和偏特化的模板类。如下方式定义了一个基本的可变参数模板类：

```
//前向声明
template<typename... Args>
struct Sum;

//基本定义
template<typename First, typename... Rest>
struct Sum<First, Rest...>
{
enum { value = Sum<First>::value + Sum<Rest...>::value };
};

//递归终止
template<typename Last>
struct Sum<Last>
{
enum { value = sizeof (Last) };
};
```

这个Sum类的作用是在编译期计算出参数包中参数类型的size之和，通过sum<int,double,short>::value就可以获取这3个类型的size之和为14。这是一个简单的通过可变参数模板类计算的例子，可以看到一个基本的可变参数模板应用类由三部分组成，第一部分是：

template<typename... Args> struct sum

它是前向声明，声明这个sum类是一个可变参数模板类；第二部分是类的定义：

```
template<typename First, typename... Rest>
struct Sum<First, Rest...>
{
enum { value = Sum<First>::value + Sum<Rest...>::value };
};
```

它定义了一个部分展开的可变模参数模板类，告诉编译器如何递归展开参数包。第三部分是特化的递归终止类：

```
template<typename Last> struct sum<last>
{
enum { value = sizeof (First) };
}
```

通过这个特化的类来终止递归：

template<typename First, typename... Args>struct sum;

这个前向声明要求sum的模板参数至少有一个，因为可变参数模板中的模板参数可以有0个，有时候0个模板参数没有意义，就可以通过上面的声明方式来限定模板参数不能为0个。上面的这种三段式的定义也可以改为两段式的，可以将前向声明去掉，这样定义：

```
template<typename First, typename... Rest>
struct Sum
{
enum { value = Sum<First>::value + Sum<Rest...>::value };
};

template<typename Last>
struct Sum<Last>
{
enum{ value = sizeof(Last) };
};
```

上面的方式只要一个基本的模板类定义和一个特化的终止函数就行了，而且限定了模板参数至少有一个。

递归终止模板类可以有多种写法，比如上例的递归终止模板类还可以这样写：

```
template<typename... Args> struct sum;
template<typename First, typenameLast>
struct sum<First, Last>
{ 
enum{ value = sizeof(First) +sizeof(Last) };
};
```

在展开到最后两个参数时终止。

还可以在展开到0个参数时终止：

template<>struct sum<> { enum{ value = 0 }; };

还可以使用std::integral\_constant来消除枚举定义value。利用std::integral\_constant可以获得编译期常量的特性，可以将前面的sum例子改为这样：

```
//前向声明
template<typename First, typename... Args>
struct Sum;

//基本定义
template<typename First, typename... Rest>
struct Sum<First, Rest...> : std::integral_constant<int, Sum<First>::value + Sum<Rest...>::value>
{
};

//递归终止
template<typename Last>
struct Sum<Last> : std::integral_constant<int, sizeof(Last)>
{
};
sum<int,double,short>::value;//值为14
```

#### **2.2.2****继承方式展开参数包**

还可以通过继承方式来展开参数包，比如下面的例子就是通过继承的方式去展开参数包：

```
//整型序列的定义
template<int...>
struct IndexSeq{};

//继承方式，开始展开参数包
template<int N, int... Indexes>
struct MakeIndexes : MakeIndexes<N - 1, N - 1, Indexes...> {};

// 模板特化，终止展开参数包的条件
template<int... Indexes>
struct MakeIndexes<0, Indexes...>
{
typedefIndexSeq<Indexes...> type;
};

int main()
{
    using T = MakeIndexes<3>::type;
    cout <<typeid(T).name() << endl;
    return 0;
}
```

其中MakeIndexes的作用是为了生成一个可变参数模板类的整数序列，最终输出的类型是：struct IndexSeq<0,1,2>。

MakeIndexes继承于自身的一个特化的模板类，这个特化的模板类同时也在展开参数包，这个展开过程是通过继承发起的，直到遇到特化的终止条件展开过程才结束。MakeIndexes<1,2,3>::type的展开过程是这样的：

```
MakeIndexes<3> : MakeIndexes<2, 2>{}
MakeIndexes<2, 2> : MakeIndexes<1, 1, 2>{}
MakeIndexes<1, 1, 2> : MakeIndexes<0, 0, 1, 2>
{
    typedef IndexSeq<0, 1, 2> type;
}
```

通过不断的继承递归调用，最终得到整型序列IndexSeq<0, 1, 2>。

如果不希望通过继承方式去生成整形序列，则可以通过下面的方式生成。

```
template<int N, int... Indexes>
struct MakeIndexes3
{
using type = typename MakeIndexes3<N - 1, N - 1, Indexes...>::type;
};

template<int... Indexes>
struct MakeIndexes3<0, Indexes...>
{
typedef IndexSeq<Indexes...> type;
};
```

## 一、核心概念

- **定义**：模板元编程（Template Metaprogramming, TMP）是利用 C++ 模板在**编译期**执行计算、生成代码、进行类型变换的技术。本质是将类型系统作为图灵完备的语言，在编译阶段完成运行时才能做的决策
- **关键词**：可变参数模板 `Args...`、参数包展开、SFINAE、`enable_if`、`integral_constant`、`void_t`、fold expression、递归实例化、编译期常量、类型萃取
- **适用场景/边界**：编译期类型选择（`enable_if` / `conditional`）、类型属性查询（`is_pointer` / `is_same`）、编译期计算（阶乘、整数序列）、高性能数值库（Eigen/Blaze 表达式模板）、策略模式（policy-based design）。不适用：大型项目（编译时间爆炸）、需要简洁错误信息的场景（C++20 Concepts 替代）

## 二、详细解析（≥200字）

- **原理拆解（三层递进）**：
  - **第一层——编译期递归与模式匹配**：模板元编程的核心是**递归特化+偏特化匹配**。编译器看到 `Sum<int, double, short>` 时，剥出 `First=int`，`Rest={double, short}`，实例化 `Sum<First>::value + Sum<Rest...>::value`。每个中间类型都是独立类模板实例，注册到编译器实例化表。N 个参数生成 N+1 个类实例。终止条件通过偏特化达成（单参数 `Sum<Last>` 或零参数 `Sum<>`）
  - **第二层——SFINAE 与重载决议**：Substitution Failure Is Not An Error——模板参数替换失败时该重载被静默丢弃。`HAS_MEMBER` 宏利用这一点：`Check(int)` 版本用 `decltype(obj.member(args...), true_type())` 检测成员，成功则返回 `true_type`；失败则通过 SFINAE 丢弃该重载，让 `Check(...)`（C 风格可变参数，最低优先级）顶上返回 `false_type`
  - **第三层——现代替代方案（fold expression + Concepts）**：C++17 fold expression `(args + ...)` 一行替代数十行递归模板。C++20 Concepts 替代 90% 的 SFINAE/enable_if 场景，提供可读性更好的约束语法。`if constexpr` 在函数体内做编译期分支，`void_t` 简化成员检测。现代 TMP 趋势：少递归、多折叠、用 Concepts 表达意图
- **关键数据结构/接口**：`integral_constant<T, v>` 将值包装为类型（`::value` 获取，`operator T()` 隐式转换）；`true_type` / `false_type` 是其 bool 特化；`enable_if<B, T>::type` 条件类型开关；`index_sequence<0,1,...N>` 整数序列原语
- **关键公式**：递归深度限制 ≈ 1024 层（`-ftemplate-depth` 可调）；fold expression 复杂度 O(1) vs 递归 O(n) 深度；SFINAE 候选丢弃 → 重载决议继续 ≠ 编译错误

## 三、动手实践（代码案例）

```c++
#include <iostream>
#include <type_traits>
using namespace std;

// 1. 编译期阶乘（递归模板）
template<int N>
struct Factorial {
    static constexpr int value = N * Factorial<N - 1>::value;
};
template<>
struct Factorial<0> { static constexpr int value = 1; };

// 2. C++17 fold expression 替代递归
template<int... Ns>
constexpr int sum_v = (Ns + ...);  // 一行求和

// 3. SFINAE 检测成员函数
template<typename T>
auto has_size(int) -> decltype(declval<T>().size(), true_type{});
template<typename T>
false_type has_size(...);

template<typename T>
constexpr bool has_size_v = decltype(has_size<T>(0))::value;

// 4. enable_if 条件重载
template<typename T>
enable_if_t<has_size_v<T>, void> print(T const& t) {
    cout << "has size: " << t.size() << endl;
}
template<typename T>
enable_if_t<!has_size_v<T>, void> print(T const&) {
    cout << "no size member" << endl;
}

int main() {
    cout << Factorial<5>::value << endl;   // 120（编译期计算）
    cout << sum_v<1,2,3,4,5> << endl;      // 15（fold expression）
    print(string("hello"));                 // has size: 5
    print(42);                              // no size member
}
```

**运行**：
```bash
g++ -std=c++17 tmp_demo.cpp -o tmp && ./tmp

## 四、进阶应用（≥500字）

### void_t 检测技巧

```c++
template<typename, typename = void>
struct has_iterator : false_type {};
template<typename T>
struct has_iterator<T, void_t<typename T::iterator>> : true_type {};
// 比 decltype + declval 更简洁，C++17 的 is_detected 进一步简化
```

### index_sequence + fold 实现 tuple 遍历

```c++
template<typename Tuple, size_t... Is>
void print_tuple(Tuple const& t, index_sequence<Is...>) {
    ((cout << get<Is>(t) << ' '), ...);  // fold over comma
}
template<typename... Args>
void print(Args const&... args) {
    print_tuple(tie(args...), index_sequence_for<Args...>{});
}
```

### enable_if 位置选择策略

| 位置 | 语法 | 优点 | 缺点 |
|------|------|------|------|
| 返回值 | `enable_if_t<C, Ret> f()` | 可读性好 | 无法重载同签名不同约束 |
| 默认模板参数 | `template<..., enable_if_t<C,int>=0>` | 支持重载 | 签名噪音大 |
| 函数参数 | `f(enable_if_t<C,int>=0)` | 最灵活 | 侵入参数列表 |

### 编译期类型列表（TypeList）

```c++
template<typename... Ts> struct TypeList {};

// 编译期计算 TypeList 长度
template<typename List> struct Length;
template<typename... Ts>
struct Length<TypeList<Ts...>> : integral_constant<size_t, sizeof...(Ts)> {};

// 编译期拼接两个 TypeList
template<typename L1, typename L2> struct Concat;
template<typename... T1, typename... T2>
struct Concat<TypeList<T1...>, TypeList<T2...>> { using type = TypeList<T1..., T2...>; };
```

### C++20 Concepts vs SFINAE

```c++
// 旧式 SFINAE
template<typename T>
enable_if_t<is_integral_v<T>, T> gcd(T a, T b) { return b ? gcd(b, a%b) : a; }

// C++20 Concepts（等价但更可读）
template<integral T>
T gcd(T a, T b) { return b ? gcd(b, a%b) : a; }
// Concepts 给出清晰的错误信息，而非数百行模板回溯
```

**模板元编程的工程权衡**：模板元减少运行时开销（编译期决策），代价是编译时间膨胀和错误信息不可读。现代 C++ 趋势是用 `constexpr`/`consteval`（值计算）+ Concepts（约束）替代纯 TMP。保留 TMP 的场景：类型变换（无法用 constexpr 表达）、SFINAE 的重载决议控制、C++14/17 兼容性。

## 五、源码解析和实践感悟

### 5.1 源码解析

#### 可变参数模板展开的内部机制

编译器对可变参数模板的展开本质上是**编译期递归实例化**。以 Sum 为例，当写下 `Sum<int, double, short>` 时，编译器做的是：

1. **匹配偏特化版本**：参数包 `Args = {int, double, short}`，剥出 `First=int`，`Rest={double, short}`
2. **递归实例化**：`Sum<int>::value + Sum<double, short>::value`
3. **终止条件**：当参数包只剩一个时，匹配 `Sum<Last>` 特化版本，递归终止
4. **常量折叠**：所有中间结果被折叠为编译期常量 `14`

```c++
// 编译器视角的展开过程（伪代码）
Sum<int, double, short>
  → Sum<int>::value + Sum<double, short>::value
    → Sum<int>::value + (Sum<double>::value + Sum<short>::value)
      → sizeof(int) + (sizeof(double) + sizeof(short))
        → 4 + (8 + 2) = 14       // 全部在编译期完成
```

关键点：每个中间类型 `Sum<int, double, short>`、`Sum<double, short>`、`Sum<int>` 都是一个**独立的类模板实例**，都会被记录到编译器的模板实例化表中。对于 N 个参数，编译器会生成 N+1 个类实例（包含终止条件），这正是模板元编程编译开销的来源之一。

#### SFINAE 的核心原理

SFINAE（Substitution Failure Is Not An Error）依赖 C++ 重载决议的一条规则：**当模板参数替换导致无效类型/表达式时，该候选函数被静默丢弃，而非报错**。HAS_MEMBER 宏利用的就是这一点：

```c++
// 正常版本：如果 T 有 member(args...) 方法，decltype 推导成功
template<typename U> 
static auto Check(int) -> decltype(std::declval<U>().member(std::declval<Args>()...), std::true_type());

// 回退版本：如果替换失败，Check(int) 被丢弃，Check(...) 成为唯一候选
template<typename U> 
static std::false_type Check(...);
```

`Check<T>(0)` 调用时，`0` 精确匹配 `int`，编译器会优先选择 `Check(int)` 版本。如果替换失败（T 没有 member 方法），SFINAE 让该版本不参与重载，`Check(...)`（C 风格可变参数，优先级最低）顶上，返回 `false_type`。

#### integral_constant 与编译期值传递

```c++
template<class T, T v>
struct integral_constant {
    static constexpr T value = v;
    using value_type = T;
    using type = integral_constant;
    constexpr operator T() const noexcept { return v; }
    constexpr T operator()() const noexcept { return v; }
};
using true_type = integral_constant<bool, true>;
using false_type = integral_constant<bool, false>;
```

通过继承 `integral_constant`，Sum 的 `value` 成为静态成员常量，可直接在编译期使用。C++17 之后更推荐用 `inline constexpr` 变量模板替代枚举：

```c++
template<typename... Args>
inline constexpr size_t sum_v = Sum<Args...>::value;
```

### 5.2 实践经验

1. **递归深度限制**：模板递归默认深度在 Clang/GCC 约为 1024 层（`-ftemplate-depth=N` 可调）。对 1000+ 个参数的可变参数包做递归展开会触发编译错误，需要改用 fold expression（C++17）或分批处理
2. **编译时间与二进制膨胀**：每层递归生成一个类实例 + N 个符号，大型模板元程序可让编译时间呈指数增长。常用策略是为中间结果缓存（用 `using` 而非重复计算）
3. **SFINAE vs Concepts**：C++20 Concepts 可替代 90% 的 SFINAE 场景，代码更可读。但 SFINAE 在处理"检测成员存在性"方面仍然灵活
4. **逗号表达式的妙用**：`decltype(expr, std::true_type())` 中的逗号先执行 expr（可能触发 SFINAE），然后丢弃其结果，返回 `true_type`。若 expr 非法则整个 decltype 替换失败
5. **enable_if 的位置选择**：放在返回值类型（可读性好）、默认模板参数（不影响函数签名）、或函数参数（支持重载），三者有细微差异
6. **编译期整数序列生成**：`index_sequence` + fold expression 是现代模板元编程的核心原语，优于递归继承

## 六、面试准备

### 6.1 面试高频问答

**Q1：可变参数模板的递归终止条件有哪几种写法？**

A：三种常见方式：(1) 单参数特化——`template<typename Last> struct Sum<Last>`；(2) 零参数特化——`template<> struct Sum<>`，配合前向声明限定最少参数数；(3) 继承 `integral_constant` 终止——避免手动定义枚举。

**Q2：SFINAE 的全称是什么？核心机制是什么？**

A：Substitution Failure Is Not An Error。当模板形参替换实参时，如果产生了无效类型或表达式，编译器不会报错，而是将该候选从重载集合中移除。常用于编译期条件判断和 `enable_if`。

**Q3：什么是参数包展开的"模式"（pattern）？**

A：`f(args)...` 中的 `f(args)` 就是模式。编译器会为包中每个元素生成 `f(arg0), f(arg1), ...`。模式可以包含多个参数包（同时展开，要求包大小相同）和复杂表达式。

**Q4：enable_if 的实现原理是什么？**

A：`enable_if<true, T>::type` 定义为 `T`，`enable_if<false, T>` 没有 `type` 成员。当条件为 false 时访问 `::type` 触发替换失败，通过 SFINAE 丢弃该重载。通常放在返回值类型或默认模板参数位置。

**Q5：模板元编程中如何避免编译时递归过深？**

A：(1) 使用 C++17 fold expression 替代递归展开；(2) 用 `index_sequence` + 数组索引替代逐层递归；(3) 二分递归减少深度（logN vs N）；(4) 对已知类型集用预处理宏生成代码替代模板递归。

**Q6：`std::declval` 在 SFINAE 中的作用是什么？**

A：`std::declval<T>()` 将任意类型 T 转换为右值引用（`T&&`），允许在不求值上下文（如 `decltype`）中"假装"构造一个 T 对象以检测成员函数/运算符。它不能用于求值上下文（没有定义），专为 SFINAE 设计。

**Q7：模板元编程与 constexpr 函数的差异？**

A：模板元编程在**类型层面**操作（生成类型、改变类型），constexpr 在**值层面**操作；模板元在编译期执行且只能操作编译期常量，constexpr 函数既可在编译期也可在运行期执行；模板元更适合类型计算（如 `remove_const`），constexpr 更适合值计算（如阶乘）。

**Q8：C++17 fold expression 如何替代递归展开？**

A：`(args + ...)` 是二元左折叠，等价于 `((arg0 + arg1) + arg2) + ...`；`(... + args)` 是右折叠。可配合 `&&`、`||`、`,` 等运算符，一行代码替代原先数十行递归模板。

**Q9：`void_t` 技巧是什么？**

```c++
template<typename...> using void_t = void;
```
用于 SFINAE 检测：`void_t<decltype(expr)>` 如果 expr 合法则得到 `void`，否则替换失败。比传统的 `decltype(expr, std::true_type())` 更简洁。

**Q10：模板元编程的常见应用场景有哪些？**

A：类型萃取（`is_same`、`is_pointer`）、编译期计算（阶乘、斐波那契）、类型列表操作（`typelist`）、策略模式（policy-based design）、表达式模板（Eigen、Boost.Spirit）、序列化/反射框架。

### 6.2 陷阱与反问

**陷阱1**：可变参数模板递归未定义终止条件 → 编译器无限递归（通常报 `template instantiation depth exceeds maximum`）

**陷阱2**：参数包为空时前向声明 `template<typename... Args> struct S` 允许零参数，但体实现可能假设至少一个参数 → 运行时逻辑错误（如果能编译通过）

**陷阱3**：SFINAE 只能用于**替换失败**，不能用于函数体中的错误。函数体中的语法错误仍然是硬错误

**陷阱4**：`decltype` 中两个参数包的展开次序在不同编译器间可能不一致

**陷阱5**：过度使用模板元编程导致错误信息不可读（数百行模板展开回溯），C++20 Concepts 可大幅改善

**反问**：你觉得 `if constexpr` 能完全替代 SFINAE 吗？哪些场景 SFINAE 仍然不可替代？

*答案要点：不能完全替代。SFINAE 控制重载决议（多个候选函数的选择），`if constexpr` 控制单个函数内部的编译期分支。当需要根据类型特征选择**不同函数签名**时，SFINAE/enable_if 仍不可替代。*

### 6.3 一句话答案

1. **可变参数模板**：`template<typename... Args>` 可接收任意数量类型参数的模板，通过递归或fold展开处理
2. **SFINAE**：模板参数替换失败不报错，该重载被静默丢弃
3. **enable_if**：`enable_if<true, T>::type = T`，条件为 false 时 `type` 不存在，触发 SFINAE
4. **参数包展开模式**：`f(args)...` 对包中每个元素重复该模式
5. **void_t**：`template<typename...> using void_t = void`，SFINAE 检测的简洁工具
6. **integral_constant**：将值包装为类型的工具，`::value` 获取编译期常量
7. **fold expression**：C++17 引入，`(args + ...)` 一行展开参数包，取代递归模板
8. **declval**：在不求值上下文中"伪造"对象，用于检测成员存在性
