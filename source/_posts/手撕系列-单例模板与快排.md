# 手撕系列：单例模板 & 快排

> 适用范围：面试高频手写代码题，涵盖 C++ 单例模式的模板化实现（基于 `call_once` + `shared_ptr`）和快速排序的模板递归实现。

## 一、核心概念

- **定义**：本笔记收录两道面试中最常见的手撕代码题——通用单例模板类（Singleton Template）和快速排序（Quicksort），展示 C++ 模板编程在多线程安全和泛型算法中的应用。
- **关键词**：单例模式、`std::call_once`、`std::once_flag`、`std::shared_ptr`、模板类、快速排序、分治算法、`std::swap`
- **适用场景/边界**：
  - 单例模板：需要全局唯一实例且多线程安全的场景（如日志管理器、配置管理器、数据库连接池）
  - 快速排序：作为面试必考排序算法，展示分治思想和模板泛型编程能力

## 二、详细解析（≥200字）

### 原理拆解（三层递进）

**第一层：单例模板**

单例模式保证一个类只有一个实例。传统做法是在类内部静态创建实例，但这份代码更进一步——将单例做成模板类，让任意类型 T 都能复用单例逻辑：

```c++
template <typename T>
class Singleton {
protected:
    Singleton() = default;                          // 构造保护：只允许派生类调用
    Singleton(const Singleton<T>&) = delete;        // 禁止拷贝
    Singleton& operator=(const Singleton<T>&) = delete; // 禁止赋值
    static std::shared_ptr<T> _instance;            // 静态实例指针
public:
    static std::shared_ptr<T> GetInstance();        // 全局访问点
};
```

使用时，只需要让目标类继承 `Singleton<MyClass>`：

```c++
class ConfigManager : public Singleton<ConfigManager> {
    friend class Singleton<ConfigManager>;  // 允许基类访问构造函数
private:
    ConfigManager() = default;  // 私有构造
public:
    void LoadConfig(const std::string& path) { /*...*/ }
};

auto cfg = ConfigManager::GetInstance();
cfg->LoadConfig("app.conf");
```

**第二层：多线程安全的实现细节**

`GetInstance()` 使用了 C++11 的线程安全机制：

```c++
static std::shared_ptr<T> GetInstance() {
    static std::once_flag s_flag;           // 1. 静态标志位，全局唯一
    std::call_once(s_flag, [&]() {          // 2. call_once 保证 lambda 只执行一次
        _instance = std::shared_ptr<T>(new T); // 3. 线程安全地创建实例
    });
    return _instance;                        // 4. 返回 shared_ptr
}
```

- `std::once_flag`：静态局部变量，整个程序生命周期只会被初始化一次
- `std::call_once`：C++11 标准库提供的"只执行一次"保证，多线程同时调用时只有一个线程执行初始化代码，其他线程阻塞等待
- `std::shared_ptr<T>`：智能指针管理生命周期，避免手动 `delete`

这比"双重检查锁定（DCLP）"更简单且完全正确——DCLP 在 C++11 之前的内存模型下存在隐患。

**第三层：快速排序的分治原理**

快速排序的核心是"分区"（Partition）操作：
1. 选一个基准值（pivot），这里用 `arr[start]`
2. 将数组划分为两部分：左边全部 ≤ pivot，右边全部 ≥ pivot
3. 递归地对左右两部分排序

代码中的实现细节：

```c++
T key = arr[start];               // 选第一个元素为基准
int left = start, right = end;
while (left < right) {
    while (arr[right] >= key && left < right) right--;  // 从右向左找比 key 小的
    while (arr[left] <= key && left < right) left++;     // 从左向右找比 key 大的
    std::swap(arr[left], arr[right]);                    // 交换
}
if (arr[left] < key) {             // 相遇点可能和 key 相同
    std::swap(arr[left], arr[start]);
}
```

### 关键数据结构/接口

| 组件 | 作用 |
|------|------|
| `Singleton<T>` | 通用单例模板基类，任意继承它的 T 都获得单例能力 |
| `std::once_flag` | 配合 `call_once` 实现线程安全的一次性初始化 |
| `std::shared_ptr<T>` | 管理单例实例的生命周期，引用计数自动释放 |
| `quick_sort_recursive` | 快排递归实现，接收数组和起止索引 |
| `quick_sort` | 快排对外接口，隐藏递归细节 |

### 关键公式/复杂度

- 快速排序平均时间复杂度：\(O(n \log n)\)，最坏 \(O(n^2)\)（已排序数组且选第一个为 pivot）
- 快速排序空间复杂度：\(O(\log n)\)（递归栈深度）
- 单例模板：单例创建 O(1)（首次），后续获取 O(1)，空间 O(1)

## 三、动手实践（代码案例）

```c++
#include <iostream>
#include <memory>
#include <mutex>
#include <vector>
#include <string>

// ===== 单例模板 =====
template <typename T>
class Singleton {
protected:
    Singleton() = default;
    Singleton(const Singleton<T>&) = delete;
    Singleton& operator=(const Singleton<T>& st) = delete;
    static std::shared_ptr<T> _instance;
public:
    static std::shared_ptr<T> GetInstance() {
        static std::once_flag s_flag;
        std::call_once(s_flag, [&]() {
            _instance = std::shared_ptr<T>(new T);
        });
        return _instance;
    }
    void PrintAddress() {
        std::cout << _instance.get() << std::endl;
    }
    ~Singleton() {
        std::cout << "this is singleton destruct" << std::endl;
    }
};
template <typename T>
std::shared_ptr<T> Singleton<T>::_instance = nullptr;

// ===== 使用示例 =====
class Logger : public Singleton<Logger> {
    friend class Singleton<Logger>;
private:
    Logger() { std::cout << "Logger created\n"; }
public:
    void Log(const std::string& msg) {
        std::cout << "[LOG] " << msg << std::endl;
    }
};

// ===== 快速排序 =====
template<typename T>
void quick_sort_recursive(T arr[], int start, int end) {
    if (start >= end) return;
    T key = arr[start];
    int left = start, right = end;
    while (left < right) {
        while (arr[right] >= key && left < right) right--;
        while (arr[left] <= key && left < right) left++;
        std::swap(arr[left], arr[right]);
    }
    if (arr[left] < key) {
        std::swap(arr[left], arr[start]);
    }
    quick_sort_recursive(arr, start, left - 1);
    quick_sort_recursive(arr, left + 1, end);
}

template<typename T>
void quick_sort(T arr[], int len) {
    quick_sort_recursive(arr, 0, len - 1);
}

// ===== 测试 =====
int main() {
    // 单例测试
    auto logger1 = Logger::GetInstance();
    auto logger2 = Logger::GetInstance();
    logger1->Log("hello");
    std::cout << "Same instance? " << (logger1 == logger2) << std::endl;
    // 输出: 1 (true)

    // 快排测试
    int arr[] = {3, 1, 4, 1, 5, 9, 2, 6, 5, 3, 5};
    int n = sizeof(arr) / sizeof(arr[0]);
    quick_sort(arr, n);
    for (int i = 0; i < n; i++) {
        std::cout << arr[i] << " ";
    }
    std::cout << std::endl;
    // 输出: 1 1 2 3 3 4 5 5 5 6 9

    return 0;
}
```

## 四、进阶应用（≥500字）

### 与其他主题的关联

- **智能指针**：`Singleton` 使用 `shared_ptr` 管理生命周期。如果不想用 `shared_ptr`，也可以用 `static T _instance`（Meyers' Singleton），但那要求 T 的构造在 `GetInstance` 内部完成。
- **模板编程**：`Singleton<T>` 展示了 CRTP（Curiously Recurring Template Pattern）的变体——派生类通过继承获得单例能力，而非传统 CRTP 中的静态多态。
- **并发编程**：`std::call_once` + `std::once_flag` 是 C++11 提供的线程安全"只执行一次"原语，内部使用互斥锁或无锁机制实现。相比手动 `std::mutex` + double-check，代码更简洁且保证正确。

### 工程中的真实用法

**单例模板的适用场景**：
- 日志管理器（Logger）：整个进程只有一个日志输出流
- 配置管理器（ConfigManager）：全局配置只加载一次
- 数据库连接池：连接池实例全局唯一
- 对象工厂（ObjectFactory）：注册和创建特定类型对象的全局注册表

**注意事项**：
- 单例的析构顺序不确定：多个单例之间如果互相依赖，程序退出时可能出现"访问已析构对象"的问题。解决方案是使用 `std::shared_ptr`（引用计数保证最后一个释放）或避免单例间的析构依赖
- 单例不利于单元测试：全局状态使测试难以隔离。可考虑用依赖注入替代单例

**快速排序的工程变体**：
- **三向切分快排**：当数组中重复元素很多时，荷兰国旗问题优化——分成 < pivot、= pivot、> pivot 三部分
- **内省排序（Introsort）**：C++ `std::sort` 的实现方案——先快排，递归深度超过 \(2\log n\) 时切换为堆排序，防止退化到 \(O(n^2)\)

### 常见优化策略

- **快排基准选择优化**：选第一个元素为 pivot 在已排序数组上会退化为 O(n²)。改进：随机选择 pivot 或三数取中（median-of-three）
- **快排小数组优化**：当子数组长度小于阈值（如 10~15）时，切换到插入排序（常数因子更小）
- **单例的懒汉 vs 饿汉**：这份代码是懒汉式（Lazy）——首次调用 `GetInstance()` 才创建。优点：无初始化开销；缺点：首次调用有延迟。饿汉式在程序启动时创建，无并发问题但可能浪费资源

## 五、源码解析和实践感悟（≥1000字）

### 关键实现路径

**`std::call_once` 的底层实现**（简化版）：

```c++
// std::call_once 的简化实现思路
// 实际标准库实现更复杂，涉及 futex/atomic 等系统调用

void call_once(once_flag& flag, Callable&& func) {
    // 快速路径：如果已经执行过，直接返回
    if (flag._state == DONE) return;
    
    // 慢路径：需要加锁
    std::unique_lock<std::mutex> lock(flag._mutex);
    
    // 双重检查：获取锁后可能已执行
    if (flag._state == DONE) return;
    
    // 执行函数
    func();
    
    // 标记完成 + 唤醒所有等待线程
    flag._state = DONE;
    flag._cv.notify_all();
}
```

**快速排序分区过程的逐步推演**：

```
输入: [3, 1, 4, 1, 5]  key=3
初始: left=0, right=4
step1: right-- → arr[3]=1 < 3, right停在3
       left++  → arr[1]=1 < 3, left++; arr[2]=4 > 3, left停在2
       swap: arr[2]↔arr[3] → [3, 1, 1, 4, 5]
step2: right-- → arr[2]=1 < 3, right停在2
       left 在2, left < right 不成立, 退出while
       arr[left]=1 < key=3? yes → swap arr[0]↔arr[2]
结果: [1, 1, 3, 4, 5]
递归: [1,1] 和 [4,5]
```

**Singleton 模板的友元机制解析**：

```c++
class Logger : public Singleton<Logger> {
    friend class Singleton<Logger>;  // 关键：允许基类访问私有构造
private:
    Logger() {}  // 私有构造：外部不能直接 new Logger
};
```

`Singleton<Logger>::GetInstance()` 中 `new T` 需要调用 T 的构造函数。由于 Logger 的构造函数是 private 的，必须通过 `friend class Singleton<Logger>` 授予基类模板访问权限。这是 C++ 中模板基类访问派生类私有成员的经典模式。

### 难点与易错点

**陷阱1：`std::call_once` 中 lambda 捕获 `_instance`**

```c++
static std::shared_ptr<T> GetInstance() {
    static std::once_flag s_flag;
    std::call_once(s_flag, [&]() {       // [&] 按引用捕获
        _instance = std::shared_ptr<T>(new T);
    });
    return _instance;
}
```

这里 `[&]` 按引用捕获，lambda 中访问 `_instance` 是安全的——`s_flag` 是 static，`_instance` 也是 static（类静态成员），生命周期相同。如果用 `[=]` 按值捕获，lambda 会拷贝 `_instance`（此时为 nullptr），赋值操作只影响副本而非原变量。

**陷阱2：快排中 `left` 和 `right` 相遇后的处理**

```c++
if (arr[left] < key) {
    std::swap(arr[left], arr[start]);
}
```

为什么需要这个判断？因为 `left` 和 `right` 相遇时，相遇点的值可能 ≥ key（当 right 先到达 left 时）。如果相遇点值 ≥ key，则 key 已经在正确位置（相遇点左侧），不需要交换。这个细节容易被忽略。

**陷阱3：Singleton 的析构时访问**

假设有两个单例 A 和 B，A 的析构函数中访问了 B：

```c++
class A : public Singleton<A> { ~A() { B::GetInstance()->DoSomething(); } };
class B : public Singleton<B> { /*...*/ };
```

程序退出时，静态对象的析构顺序与构造顺序相反。如果 A 后构造（前析构），在 A 的析构中访问 B 是安全的；但如果 B 先析构，则 A 析构时 B 的 `shared_ptr` 已释放，可能导致 crash。解决方案：确保单例间无析构依赖，或使用 `weak_ptr`。

### 经验总结

1. **`call_once` 是 C++11 单例的最佳实践**：比 DCLP 简单、比 Meyers' Singleton 灵活（可做模板），且标准保证线程安全。唯一的代价是首次调用时的锁开销，但单例通常只在启动阶段创建。
2. **模板 + 友元 = 通用基础组件的钥匙**：通过 `friend class Singleton<T>` 让模板基类访问派生类的私有构造，是实现"非侵入式单例"的关键技术。
3. **快排的面试要点不在背诵代码，而在理解分区过程**：面试官更关心你是否理解 partition 的原理、边界条件处理、以及最坏情况的优化策略。能在白板上推演一轮分区过程比能默写出代码更有说服力。
4. **代码块必须标注语言**：原笔记的代码块缺少语言标注。C++ 代码必须用 `c++`（不可用 `cpp` 或 `c`），这既符合模板规范，也让 Markdown 渲染器正确高亮。

## 六、面试准备

### 6.1 高频问法（≥10个）

**单例相关：**

Q1：手写一个线程安全的 C++ 单例模式？

A：使用 `std::call_once` + `std::once_flag` + `std::shared_ptr`，比双重检查锁定更简洁且标准保证正确。核心代码：static once_flag s_flag; call_once(s_flag, []{ instance = make_shared<T>(); }); return instance; 私有化构造/拷贝/赋值。

Q2：C++ 单例的几种实现方式？优劣对比？

A：1）Meyers' Singleton（C++11 static 局部变量，最简洁但无法做模板）；2）DCLP（双重检查锁定，C++11 前不可靠）；3）`call_once` 方案（本笔记方案，标准保证，可模板化）。推荐 Meyers' 用于简单场景，`call_once` 模板用于需要复用单例逻辑的场景。

Q3：为什么要用 `shared_ptr` 而不是裸指针或 `unique_ptr`？

A：`shared_ptr` 引用计数避免悬空指针。如果多个地方持有同一个单例引用，`unique_ptr` 会导致所有权争议。裸指针需手动管理生命周期，容易 double-free 或 use-after-free。

Q4：`friend class Singleton<T>` 这行的作用是什么？

A：让模板基类 `Singleton<T>` 能访问派生类 T 的私有构造函数。`GetInstance()` 中的 `new T` 需要调用 T 的构造，但 T 的构造是 private 的（防止外部直接创建）。friend 声明授予基类访问权限。

**快排相关：**

Q5：手写快速排序？

A：选基准值（pivot）→ 分区（partition）：双指针从两端向中间扫描，交换逆序元素 → 递归排序左右子数组。时间复杂度 O(n log n) 平均，O(n²) 最坏，空间 O(log n)。

Q6：快排为什么最坏是 O(n²)？如何避免？

A：每次 pivot 都是最小/最大值时，分区极不均衡（一边 n-1，一边 0），退化为冒泡排序。避免方法：随机选 pivot、三数取中（median-of-three）。

Q7：快排是稳定排序吗？为什么不稳定？

A：不稳定。partition 过程中的 swap 可能改变相等元素的相对顺序。例：[5a, 1, 5b] pivot=5a → swap(5a, 1) → [1, 5a, 5b]，5a 和 5b 的相对顺序可能被改变。

Q8：快排和归并排序的对比？

A：快排原地排序（O(log n) 栈空间），但不稳定、最坏 O(n²)；归并排序稳定、保证 O(n log n)，但需 O(n) 额外空间。大多数标准库的排序实现基于快排变体（如 introsort）。

**综合：**

Q9：这段 Singleton 模板中 `static std::once_flag s_flag` 为什么写在函数内部？

A：C++11 保证 static 局部变量的初始化是线程安全的（Magic Statics）。写在函数内部有两个好处：1）懒初始化（首次调用时才创建）；2）线程安全由编译器/标准库保证，无需手动加锁。

Q10：Singleton 模板中为什么把构造/拷贝/赋值放在 protected/delete 中？

A：构造函数 `protected`：允许派生类构造（因为派生类继承自 Singleton），但不允许外部直接创建。拷贝和赋值 `= delete`：禁止拷贝单例实例，保证全局唯一。

### 6.2 反问点/陷阱点（≥5个）

**针对面试官的深度问题：**

贵公司在工程中是如何使用单例模式的？是直接用依赖注入框架管理还是手动实现单例？

对于单例的单元测试，贵团队有没有好的实践来隔离单例带来的全局状态？

**常见的陷阱问题：**

陷阱问题1：两个线程同时首次调用 `GetInstance()`，会不会创建两个实例？答案：不会。`std::call_once` 保证只有一个线程执行初始化 lambda，另一个线程阻塞等待。初始化完成后两个线程拿到的都是同一个 `shared_ptr`。

陷阱问题2：快排的 pivot 选 `arr[start]`，当输入数组已排序时会怎样？答案：每次分区极不均衡（左边 0 个、右边 n-1 个），退化为 O(n²) 时间 + O(n) 递归栈，可能爆栈。改进：随机选 pivot 或三数取中。

陷阱问题3：这段快排代码在数组中所有元素都相等时正确吗？答案：正确但效率低。所有元素等于 key，right 会一直左移到 left 位置，while 循环几乎遍历整个子数组，但每次分区大小只减 1，退化为 O(n²)。三向切分快排可解决此问题。

陷阱问题4：`Singleton<T>::_instance` 是 static 成员变量，什么时候析构？答案：程序退出时，静态对象按构造的逆序析构。析构 `shared_ptr` 会释放管理的 T 对象。问题：如果另一个单例的析构函数依赖 T 还存活，可能出问题（静态对象析构顺序不确定）。

### 6.3 一句话答案（≥5个）

线程安全单例的核心：`std::call_once` + `std::once_flag`，标准保证多线程只初始化一次。

快排的核心：选 pivot → 双指针分区（小于放左、大于放右）→ 递归左右子数组。

`friend class Singleton<T>` 的作用：让模板基类访问派生类私有构造，实现非侵入式单例。

快排最坏 O(n²) 的根源：pivot 选择不当导致分区极不均衡，退化为冒泡排序。

`shared_ptr` 管理单例优于裸指针的原因：引用计数自动释放、避免 use-after-free、支持多处持有引用。

当被问到"手撕单例"时，回答："用 `call_once` + `shared_ptr` 的模板实现，构造 protected/拷贝赋值 delete，派生类 friend 基类以允许私有构造。"

当被问到"手撕快排"时，回答："选第一个元素为 pivot，双指针从两端扫描交换，递归排序左右子数组。优化可用随机 pivot 或三数取中防退化。"

### 单例模板（多次使用单例类）

```c++
//为了让单例更加通用，可以做成模板类
template <typename T>
class Singleton {
protected:
    Singleton() = default;
    Singleton(const Singleton<T>&) = delete;
    Singleton& operator=(const Singleton<T>& st) = delete;
    static std::shared_ptr<T> _instance;
public:
    static std::shared_ptr<T> GetInstance() {
        static std::once_flag s_flag;
        std::call_once(s_flag, [&]() {
            _instance = std::shared_ptr<T>(new T);
            });
        return _instance;
    }
    void PrintAddress() {
        std::cout << _instance.get() << std::endl;
    }
    ~Singleton() {
        std::cout << "this is singleton destruct" << std::endl;
    }
};
template <typename T>
std::shared_ptr<T> Singleton<T>::_instance = nullptr;
```

### 快排

```c++
template<typename T>
void quick_sort_recursive(T arr[],int start,int end){
    if(start>=end)return ;
    T key=arr[start];
    int left=start,right=end;
    while(left<right){
        while(arr[right]>=key&&left<right) right--;
        while(arr[left] <= key && left < right) left++;
        std::swap(arr[left], arr[right]); // 左右指针都停下时，交换二者的值
    }
    if(arr[left]<key){ // 相遇点若比key小，交换（因为相遇点可能和key相同，所以需要判断一下）
        std::swap(arr[left], arr[start]);
    }
    quick_sort_recursive(arr, start, left - 1);
    quick_sort_recursive(arr, left + 1, end);
}
template<typename T>
void quick_sort(T arr[], int len) {
    quick_sort_recursive(arr, 0, len - 1);
}
```
