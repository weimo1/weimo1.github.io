# RingBuffer 环形缓冲区

## 概述

RingBuffer（环形缓冲区）是一种固定大小的循环 FIFO 数据结构，通过头指针（head）和尾指针（tail）实现高效的读写操作。初始化时 head 和 tail 指向同一位置，表示缓冲区为空。每次写入数据后 head 前进，每次读取数据后 tail 前进。当指针到达缓冲区末尾时自动回绕到开头，形成环形结构。

## 核心机制

判断缓冲区状态的常用方法：head 等于 tail 时为空；为保证区分空和满，通常预留一个元素位置，满的条件为 (head + 1) % size == tail。另一种方案是引入计数器记录元素数量，但会增加额外的维护开销。读取数据时从 tail 位置读取并将 tail 前进；写入数据时向 head 位置写入并将 head 前进。

## 无锁优化

Linux 内核的 kfifo 是无锁环形缓冲区的经典实现。通过保证 buffer size 为 2 的幂次，将取模运算优化为位与运算（取 size-1 的低位掩码），大幅提升性能。在单生产者单消费者场景下，kfifo 无需加锁即可安全使用，因为 head 只被生产者修改、tail 只被消费者修改，没有竞争条件。

## 应用场景

**日志系统**：spdlog 等高性能日志库使用异步环形缓冲区暂存日志消息，避免写日志阻塞业务逻辑线程。生产者线程快速入队后立即返回，消费者线程批量写入磁盘。

**网卡驱动**：DMA 环形队列管理网络数据包的发送和接收，网卡硬件直接操作环形缓冲区，无需 CPU 逐包处理。多个队列可分配到不同 CPU 核心上，实现负载均衡。

**音视频处理**：音视频采集和渲染线程通过环形缓冲区解耦，采集线程写入帧数据，渲染线程以固定帧率读取，应对帧率波动。FFmpeg 的 AVPacket 队列使用了类似设计。

**消息队列**：Redis 客户端的输出缓冲区、ZeroMQ 的内部消息传递均使用环形缓冲区实现高效的数据中转。

## 优缺点

RingBuffer 的优势在于固定大小无动态内存分配、O(1) 入队出队操作、优秀的缓存局部性。缺点是固定大小可能导致溢出或浪费，需要根据流量合理配置缓冲区大小。
