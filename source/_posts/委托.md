# 委托

> 适用范围：C++ 委托模式实现、成员函数指针、std::function 封装、多播委托、事件回调系统

## 一、项目/模块概述

- **模块定位**：委托（Delegate）是一种类型安全的函数指针封装，允许将成员函数、静态函数、lambda 等可调用对象统一存储和调用。在事件驱动架构中，委托是实现观察者模式、回调机制、信号槽系统的核心组件。
- **技术栈与依赖**：C++11/14/17、`std::function`、`std::bind`、成员函数指针、可变参数模板。
- **模块边界**：委托是回调机制的抽象层，不关心业务逻辑。上层（如 UI 框架、网络库、游戏引擎）通过委托注册事件处理器。

## 二、架构设计

### 委托的核心需求

```
┌────────────────────────────────────────────┐
│              委托（Delegate）               │
│                                            │
│  统一封装以下可调用对象：                     │
│  → 全局函数 / 静态函数                      │
│  → 成员函数（需要对象指针）                   │
│  → Lambda 表达式（捕获列表）                 │
│  → std::bind 绑定结果                       │
│  → 函数对象（operator()）                   │
│                                            │
│  核心能力：                                  │
│  → 类型安全的存储（编译期检查参数和返回值）     │
│  → 延迟调用（存储后稍后执行）                 │
│  → 多播（单个委托关联多个回调）               │
└────────────────────────────────────────────┘
```

### 委托 vs 其他回调机制

| 方案 | 类型安全 | 支持成员函数 | 支持 lambda | 多播 | 复杂度 |
|------|----------|-------------|-------------|------|--------|
| 函数指针 `void(*)()` | ✅ | ❌ | ❌ (无捕获) | ❌ | 低 |
| 虚接口 `ICallback` | ✅ | ✅ | ❌ | ❌ | 中 |
| `std::function` | ✅ | ✅ | ✅ | ❌ | 低 |
| 自实现多播委托 | ✅ | ✅ | ✅ | ✅ | 高 |
| C# `delegate` | ✅ | ✅ | ✅ | ✅ | 低（语言内置） |

## 三、核心实现

### 3.1 std::function 基础用法（单播委托）

```cpp
#include <functional>
#include <iostream>

class Button {
    using ClickHandler = std::function<void(int x, int y)>;
    ClickHandler onClick_;

public:
    // 注册回调（委托）
    void setOnClick(ClickHandler handler) {
        onClick_ = std::move(handler);
    }

    void click(int x, int y) {
        if (onClick_) onClick_(x, y);
    }
};

// 使用示例
Button btn;
btn.setOnClick([](int x, int y) {
    std::cout << "Clicked at (" << x << ", " << y << ")\n";
});
btn.click(100, 200); // 输出：Clicked at (100, 200)
```

### 3.2 成员函数绑定（关键技巧）

```cpp
class Window {
public:
    void onButtonClick(int x, int y) {
        std::cout << "Window received click at (" << x << ", " << y << ")\n";
    }
};

Window window;
Button btn;
// 将成员函数绑定为委托
btn.setOnClick(std::bind(&Window::onButtonClick, &window,
                         std::placeholders::_1, std::placeholders::_2));
// 或用 lambda 更直观
btn.setOnClick([&window](int x, int y) { window.onButtonClick(x, y); });
```

### 3.3 多播委托（Multicast Delegate）

```cpp
template<typename... Args>
class MulticastDelegate {
    using Handler = std::function<void(Args...)>;
    std::vector<Handler> handlers_;

public:
    // 添加监听器
    void add(Handler handler) {
        handlers_.push_back(std::move(handler));
    }

    // 移除监听器（简化版，实际需要 token/ID 机制）
    void remove(const Handler& handler) {
        // ⚠️ std::function 不可比较，实际项目用 ID 管理
        // handlers_.erase(std::remove(handlers_.begin(), handlers_.end(), handler));
    }

    // 广播事件
    void broadcast(Args... args) {
        for (auto& handler : handlers_) {
            handler(args...); // ⚠️ 异常安全：应 try-catch
        }
    }

    // operator() 语法糖
    void operator()(Args... args) { broadcast(std::forward<Args>(args)...); }
};

// 使用
MulticastDelegate<int, int> onEvent;
onEvent.add([](int a, int b) { std::cout << "Handler1: " << a+b << "\n"; });
onEvent.add([](int a, int b) { std::cout << "Handler2: " << a*b << "\n"; });
onEvent(3, 4);
// 输出：
// Handler1: 7
// Handler2: 12
```

## 四、工程实践

- **std::function 的性能开销**：`std::function` 内部使用类型擦除（小对象优化 SBO ≈ 16~32 bytes），超出则堆分配。高频调用路径（如游戏主循环）考虑用模板参数消除间接调用，或使用 `function_ref` 等轻量替代。
- **委托生命周期管理**：关键是**注册者不能比被注册对象活得更久**。方案：(1) 对象析构时主动注销所有委托；(2) 委托持有 weak_ptr，调用前 lock() 检查；(3) RAII Token 模式——注册返回 Token，Token 析构自动注销。
- **多播委托的异常安全**：逐个执行处理器时使用 try-catch，单个处理器异常不应阻止其他处理器执行。记录异常但继续广播。
- **多播委托的移除策略**：(1) Token/ID 模式——注册返回 ID，通过 ID 移除；(2) 生成连接对象（Connection），析构自动移除；(3) weak_ptr 自动清理——检测到 `lock() == nullptr` 则跳过。
- **线程安全**：多线程下 add/remove/broadcast 需要加锁或使用 Copy-on-Write（broadcast 遍历时在副本上操作）。
- **委托链（Chain of Delegates）**：多个委托串联，前一个返回 true 则停止传播（类似 DOM 事件冒泡）。

## 五、源码解析

### 5.1 带 Token 管理的多播委托

```cpp
template<typename... Args>
class SafeMulticastDelegate {
public:
    using Handler = std::function<void(Args...)>;
    using Token = uint64_t;

private:
    struct Entry {
        Token token;
        Handler handler;
    };
    std::vector<Entry> handlers_;
    std::atomic<Token> nextToken_{1};
    std::mutex mutex_; // 线程安全

public:
    Token add(Handler handler) {
        std::lock_guard<std::mutex> lock(mutex_);
        Token token = nextToken_++;
        handlers_.push_back({token, std::move(handler)});
        return token;
    }

    bool remove(Token token) {
        std::lock_guard<std::mutex> lock(mutex_);
        auto it = std::find_if(handlers_.begin(), handlers_.end(),
            [token](const Entry& e) { return e.token == token; });
        if (it != handlers_.end()) {
            handlers_.erase(it);
            return true;
        }
        return false;
    }

    void broadcast(Args... args) {
        // Copy-on-Write：锁内拷贝，锁外执行
        std::vector<Handler> snapshot;
        {
            std::lock_guard<std::mutex> lock(mutex_);
            snapshot.reserve(handlers_.size());
            for (auto& e : handlers_)
                snapshot.push_back(e.handler);
        }
        for (auto& handler : snapshot) {
            try {
                handler(args...);
            } catch (const std::exception& e) {
                // 日志记录，不中断其他处理器
            }
        }
    }
};
```

### 5.2 RAII 连接对象（自动注销）

```cpp
class DelegateConnection {
    using RemoveFunc = std::function<void()>;
    RemoveFunc remove_;
    bool valid_ = true;

public:
    explicit DelegateConnection(RemoveFunc remove)
        : remove_(std::move(remove)) {}

    ~DelegateConnection() {
        if (valid_) remove_();
    }

    // 禁止拷贝，允许移动
    DelegateConnection(const DelegateConnection&) = delete;
    DelegateConnection& operator=(const DelegateConnection&) = delete;
    DelegateConnection(DelegateConnection&& other) noexcept
        : remove_(std::move(other.remove_)), valid_(other.valid_) {
        other.valid_ = false;
    }

    void disconnect() {
        if (valid_) {
            remove_();
            valid_ = false;
        }
    }
};

// 使用示例
SafeMulticastDelegate<int> delegate;
{
    auto token = delegate.add([](int x) { /*...*/ });
    DelegateConnection conn([&delegate, token] { delegate.remove(token); });
    // conn 离开作用域时自动移除处理器
}
```

### 5.3 基于 weak_ptr 的自动清理

```cpp
template<typename... Args>
class WeakMulticastDelegate {
    using WeakHandler = std::weak_ptr<void>;
    struct Entry {
        std::weak_ptr<void> owner; // 关联对象
        std::function<void(Args...)> handler;
    };
    std::vector<Entry> handlers_;

public:
    template<typename T>
    void add(std::shared_ptr<T> owner, std::function<void(Args...)> handler) {
        handlers_.push_back({owner, std::move(handler)});
    }

    void broadcast(Args... args) {
        // 清理已过期的处理器
        handlers_.erase(
            std::remove_if(handlers_.begin(), handlers_.end(),
                [](const Entry& e) { return e.owner.expired(); }),
            handlers_.end());

        for (auto& e : handlers_) {
            e.handler(args...);
        }
    }
};
```

## 六、面试准备

### 6.1 高频问法

**Q1：什么是委托？C++ 中如何实现？**
委托是类型安全的函数指针封装，将可调用对象（函数/成员函数/lambda）统一存储和延迟调用。C++ 中通过 `std::function` + `std::bind` 实现单播，自定义容器实现多播。

**Q2：std::function 和函数指针的区别？**
函数指针只能指向自由函数/静态函数；`std::function` 可包装任何可调用对象（成员函数、lambda、函数对象），有类型擦除开销（SBO 小对象优化，超限则堆分配）。

**Q3：多播委托如何实现？**
用 `std::vector<std::function<...>>` 存储多个处理器。add 添加，broadcast 遍历执行。移除用 Token/ID 或 RAII Connection 自动注销。

**Q4：委托的生命周期问题如何解决？**
对象析构时其注册的委托可能仍被持有 → 悬垂指针。解决：(1) 析构时主动 remove；(2) weak_ptr 检查有效性；(3) RAII Token（连接对象析构自动移除）。

**Q5：为什么 broadcast 时要拷贝一份处理器列表？**
防止处理器在执行过程中修改委托（add/remove）导致迭代器失效。Snapshot 模式（Copy-on-Write）是最简单安全的方案。

**Q6：std::function 的内存开销多大？**
取决于实现。通常 SBO 为 16~32 bytes（可内联存储小函数对象），超出则在堆上分配。sizeof(std::function<void()>) 通常为 32~64 bytes。

**Q7：委托和观察者模式的区别？**
委托是观察者模式的 C++ 实现手段。观察者模式定义通知机制（Subject + Observer），委托是实现该机制的底层技术（存储和调用回调函数）。

**Q8：lambda 捕获 this 的陷阱？**
`[this]` 捕获裸指针：this 对象销毁后 lambda 仍可能被调用 → 悬垂指针。推荐使用 `shared_from_this()` 配合 `[weak = weak_from_this()]`。

**Q9：多播委托的异常如何处理？**
逐个处理器 try-catch，单个异常不应阻止其他处理器。记录异常后继续广播。C# 的 `Delegate.GetInvocationList()` 逐一调用的做法值得参考。

**Q10：委托链（返回值传递）如何实现？**
类似 DOM 事件冒泡：每个处理器返回 bool（true=已处理停止传播）。在 `broadcast` 中检查返回值，若为 true 则中断遍历。

### 6.2 反问点

- 你们的回调机制用的是 std::function 还是自实现委托？为什么？
- 多播委托的移除策略是什么？Token 还是 Connection 对象？
- 有没有遇到 lambda 捕获 this 导致的悬垂指针 bug？
- 高频回调（如每帧调用）有没有性能优化？用模板还是 function_ref？
- 事件系统的线程安全是怎么保证的？

### 6.3 一句话答案

- 委托 = 类型安全的函数指针封装，统一存储可调用对象
- std::function = 类型擦除包装器，SBO 优化，超限堆分配
- 多播 = vector<function>，遍历执行多个处理器
- 生命周期解决 = RAII Token / weak_ptr / 析构时主动 remove
- Snapshot 模式 = broadcast 前拷贝列表，防止迭代器失效
- lambda [this] 陷阱 = 对象销毁后仍调用，用 shared_from_this 替代
