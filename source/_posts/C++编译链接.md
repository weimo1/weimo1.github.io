# C++ 编译链接

> 参考：陈硕《Linux多线程服务端编程》第十章

## 一、核心概念

- **定义**：C++ 编译链接是将源码转换为可执行文件的四阶段流水线——预处理 → 编译 → 汇编 → 链接。C++ 继承 C 的单遍编译模型，同时引入模板实例化、ODR 等复杂链接语义
- **关键词**：单遍编译、前向声明、ODR（One Definition Rule）、name mangling、静态链接 vs 动态链接、`-Wshadow -Wconversion`
- **适用场景/边界**：理解编译模型是排查"多重定义"、"未定义引用"、模板链接错误的基础；边界：C++20 Modules 正在改变传统编译模型

## 二、详细解析（≥200字）

- **原理拆解（三层递进）**：
  - **第一层——四阶段流水线**：预处理（宏展开、头文件包含、条件编译）→ 编译（C++ → 汇编，单遍扫描）→ 汇编（汇编 → 可重定位目标文件 .o）→ 链接（合并 .o + 库，地址重定位，符号解析）
  - **第二层——单遍编译的历史根源**：C 语言设计时内存极小（无法在内存中保存整个源文件的 AST），采用"从头到尾扫描一遍，过眼即忘"的单遍策略。C++ 继承了这一模型——编译器只能看到当前位置之前的代码，所以需要前向声明
  - **第三层——链接的核心机制**：静态链接在编译时将库代码复制到可执行文件；动态链接在运行时通过 ld.so 加载 .so，使用 PLT/GOT 实现延迟绑定。C++ name mangling 将函数签名编码到符号名（如 `foo(int)` → `_Z3fooi`），使得同名重载函数在链接时能区分
- **关键数据结构/接口**：目标文件（.o/.obj）是 ELF/COFF 格式；`nm` 查看符号表；`objdump -d` 反汇编
- **关键公式**：单遍编译要求类定义在首次使用前完整可见（需前向声明）；ODR 规定每个非 inline 函数/全局变量在整个程序中只能有一个定义

## 三、动手实践（代码案例）

```bash
# 1. 观察编译四阶段
# 预处理
g++ -E main.cpp -o main.i        # 展开所有宏和头文件
# 编译（生成汇编）
g++ -S main.cpp -o main.s        # 查看汇编代码
# 汇编
g++ -c main.cpp -o main.o        # 生成目标文件
# 查看目标文件符号
nm -C main.o                     # 列出所有符号（含 mangling）

# 2. 前向声明减少编译依赖
# head.h 中只前向声明 + 用指针/引用，避免 #include "full_def.h"
# 编译时只需要前向声明，链接时才需要完整定义

# 3. 静态库 vs 动态库
# 创建静态库
ar rcs libfoo.a foo.o bar.o
g++ main.cpp -L. -lfoo -o static_app

# 创建动态库
g++ -shared -fPIC foo.cpp bar.cpp -o libfoo.so
g++ main.cpp -L. -lfoo -o dynamic_app  # 运行时需 LD_LIBRARY_PATH

# 4. 排查链接错误
nm -C --undefined-only main.o   # 列出未定义符号
ldd ./dynamic_app               # 查看运行时动态库依赖
readelf -d ./app | grep NEEDED  # 更安全的依赖查询
```

- **预期**：掌握编译四阶段、前向声明、静态/动态链接区分、符号排查
- **补充**：Muduo 的编译选项 `-Wall -Wextra -Werror -Wconversion -Wshadow`——将警告当错误，杜绝隐式类型转换和变量遮蔽

## 四、进阶应用（≥500字）

- **与其他主题的关联**：与链接原理（ODR、强/弱符号）、构建系统（CMake 目标驱动）、性能优化（-O2/-O3 优化等级）、跨语言交互（extern "C" 禁用 name mangling）强相关
- **工程中的真实用法**：
  - **前向声明减少编译时间**：头文件中只前向声明类 + 使用指针/引用，在 .cpp 中才真正 `#include` 完整定义。大型项目可减少 30-50% 编译时间
  - **模板的链接特殊性**：模板代码必须在头文件中定义（或在显式实例化的 .cpp 中）——因为编译器在实例化模板时必须看到完整定义
  - **符号可见性控制**：`-fvisibility=hidden` + `__attribute__((visibility("default")))` 控制 .so 导出符号，减小符号表、加速加载
  - **ODR 违规检测**：`-Wodr`（GCC）或 LTO 能在链接时发现多个编译单元中同一符号的定义不一致

## 五、源码解析和实践感悟

### 1. 单遍编译 vs 多遍编译

```c++
// 单遍编译的典型表现：前向声明是必须的
class B;  // 前向声明（否则 A 中无法使用 B*）

class A {
    B* b_ptr;        // OK：指针仅需前向声明
    // B b_value;    // 错误：值类型需完整定义（sizeof 未知）
    void foo(B* b);  // OK：函数参数仅需前向声明
};
```

### 2. Name Mangling 示例

```c++
// C++ 编译后符号名（可通过 nm 查看）
int foo(int, double);       // _Z3fooid
int foo(double, int);       // _Z3foodi   （不同参数顺序，不同符号）
extern "C" void bar();      // bar        （C 链接，无 mangling）
```

### 实践经验

1. **头文件最小化**：能用前向声明就不用 `#include`，能用指针/引用就不用值类型
2. **`-Wshadow` 必开**：局部变量遮蔽全局/成员变量是常见 bug，此选项强制暴露
3. **ODR 陷阱**：inline 函数在不同 .cpp 中定义不同 → UB。应确保所有翻译单元看到完全一致的定义
4. **动态库 RPATH**：编译时用 `-Wl,-rpath,'$ORIGIN'` 让程序在当前目录查找 .so，免去设置 `LD_LIBRARY_PATH`
5. **编译耗时优化**：ccache 缓存编译中间结果；预编译头（PCH）加速 std 库头文件包含；用 Ninja 替代 Make（并行构建更快）

## 六、面试准备

### Q&A（8题）

**Q1: C++ 编译分为哪几个阶段？**
A: 预处理（宏/头文件/条件编译）→ 编译（C++→汇编，单遍）→ 汇编（汇编→目标文件）→ 链接（合并目标文件+库）

**Q2: 什么是单遍编译？**
A: 编译器从头到尾扫描一遍源码，只能看到当前位置之前的代码，因此需要前向声明

**Q3: 前向声明的作用是什么？**
A: 减少编译依赖（免去 `#include` 完整头文件）、解决循环引用、加快编译速度

**Q4: 静态链接和动态链接的区别？**
A: 静态链接编译时复制库代码（体积大，不需外置 .so）；动态链接运行时加载 .so（节省空间，可热更新）

**Q5: name mangling 是什么？**
A: C++ 编译器将函数名+参数类型编码为唯一符号名，以支持函数重载、命名空间。extern "C" 禁用

**Q6: ODR（One Definition Rule）是什么？**
A: 每个非 inline 函数/全局变量在程序中必须有且仅有一个定义。多个定义是 UB

**Q7: 如何排查"undefined reference"链接错误？**
A: `nm -C --undefined-only file.o` 查看缺失的符号，确认对应的 .o/.a/.so 已链接

**Q8: 为什么模板代码通常放在头文件中？**
A: 编译器在实例化模板时必须看到完整定义。隐式实例化发生在使用点所在的编译单元

### 陷阱与反问（5个）

1. **陷阱**：多个 .cpp 中定义同名非 inline 函数→链接器报多重定义
2. **反问**：为什么需要 `#include` 而不是自动导入？→ 单遍编译模型的产物，C++20 Modules 正改变这点
3. **陷阱**：头文件中定义非 inline 非模板函数→被多个 .cpp 包含时 ODR 违规
4. **反问**：`-Werror` 值得开吗？→ 值得！将警告视为错误强制团队修复潜在 bug
5. **陷阱**：动态链接版本不匹配→运行时 `GLIBC_2.34 not found`，需匹配目标系统的 libc 版本

### 一句话答案（5个）

1. **编译四阶段**：预处理 → 编译 → 汇编 → 链接
2. **单遍编译**：只能看到当前位置之前的代码，需要前向声明
3. **前向声明**：`class Foo;`，减少编译依赖
4. **name mangling**：C++ 函数重载的底层实现
5. **ODR**：每个非 inline 符号只能有一个定义

## 附录（原内容收纳）

C++语言的三大约束是：与C兼容、零开销（zero overhead）原则、值语义

每个编译步骤的作用：
1. preprocessor：预处理。处理以#开头的预处理指令，如宏定义、文件包含、条件编译等。
2. compiler：编译。将预处理后的代码转换成汇编语言。
3. assembler：汇编。将汇编代码转换成可重定位机器码。
4. linker：链接。合并目标文件，解决地址引用，生成最终可执行文件。

### 静态链接 vs 动态链接

| 特性 | 静态链接（.a/.lib） | 动态链接（.so/.dll） |
|:---:|:---:|:---:|
| 链接时机 | 编译时 | 运行时 |
| 文件大小 | 较大（包含库代码） | 较小（仅引用） |
| 内存占用 | 每个进程独立拷贝 | 共享库代码 |
| 更新维护 | 需重新编译 | 替换库文件即可 |
| 性能 | 函数调用更快 | 首次调用有开销（PLT） |

### 常用分析工具

| 工具 | 用途 | 示例命令 |
|:---:|:---:|:---:|
| `nm` | 查看目标文件符号表 | `nm -gC a.out` |
| `objdump` | 反汇编查看代码 | `objdump -dS a.out` |
| `readelf` | 分析ELF文件结构 | `readelf -d lib.so` |
| `ldd` | 查看动态库依赖 | `ldd app` |
| `ar` | 管理静态库 | `ar -t libmath.a` |
