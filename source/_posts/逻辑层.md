## c++11 单列模板

```
#pragma once
#include <memory>
#include <mutex>
#include <iostream>
using std::cout;
using std::cin;
using std::endl;
 
template <typename T>
class Singleton;
 
template<typename T>
class SafeDeletor
{
public:
    void operator()(Singleton<T>* st)
    {
        cout << "this is safe deleter operator()" << endl;
        delete st;
    }
};
 
template <typename T>
class Singleton {
    template<typename T>
    friend class SafeDeletor;
protected:
    ~Singleton() {
        cout << "this is singleton destruct" << endl;
    }
    Singleton() = default;
    Singleton(const Singleton<T>&) = delete;
    Singleton& operator=(const Singleton<T>&st) = delete;
private:
    static std::shared_ptr<T> _instance;
public:
    static std::shared_ptr<T> GetInstance() {
        static std::once_flag s_flag; // C++11新特性，懒汉模式在多线程下也不会生成多个实例，不用进行加锁操作
        std::call_once(s_flag, [&]() { // call_once内部有锁
            _instance = std::shared_ptr<T>(new T, SafeDeletor<T>());
            });
        return _instance;
    }
 
    void PrintAddress() {
        cout << _instance->get() << endl;
    }
};
 
// 初始化
template <typename T>
std::shared_ptr<T> Singleton<T>::_instance = nullptr;
```

## 逻辑类LogicSystem

```
typedef  function<void(shared_ptr<CSession>, short msg_id, string msg_data)> FunCallBack;
class LogicSystem:public Singleton<LogicSystem>
{
    friend class Singleton<LogicSystem>;
public:
    ~LogicSystem();
    void PostMsgToQue(shared_ptr < LogicNode> msg);
private:
    LogicSystem();
    void DealMsg();
    void RegisterCallBacks();
    void HelloWordCallBack(shared_ptr<CSession>, short msg_id, string msg_data);
    std::thread _worker_thread;
    std::queue<shared_ptr<LogicNode>> _msg_que;
    std::mutex _mutex;
    std::condition_variable _consume;
    bool _b_stop;
    std::map<short, FunCallBack> _fun_callbacks;
};
```

1   `FunCallBack`为要注册的回调函数类型，其参数为绘画类智能指针，消息id，以及消息内容。

2   `_msg_que`为逻辑队列

3   `_mutex` 为保证逻辑队列安全的互斥量

4   `_consume`表示消费者条件变量，用来控制当逻辑队列为空时保证线程暂时挂起等待，不要干扰其他线程。

5   `_fun_callbacks`表示回调函数的map，根据id查找对应的逻辑处理函数。

6   `_worker_thread`表示工作线程，用来从逻辑队列中取数据并执行回调函数。

7   `_b_stop`表示收到外部的停止信号，逻辑类要中止工作线程并优雅退出。

工作线程的处理函数`DealMsg`逻辑

```
void LogicSystem::DealMsg() {
    for (;;) {
        std::unique_lock<std::mutex> unique_lk(_mutex);
        //判断队列为空则用条件变量阻塞等待，并释放锁
        while (_msg_que.empty() && !_b_stop) {
            _consume.wait(unique_lk);
        }

        //判断是否为关闭状态，把所有逻辑执行完后则退出循环
        if (_b_stop ) {
            while (!_msg_que.empty()) {
                auto msg_node = _msg_que.front();
                cout << "recv_msg id  is " << msg_node->_recvnode->_msg_id << endl;
                auto call_back_iter = _fun_callbacks.find(msg_node->_recvnode->_msg_id);
                if (call_back_iter == _fun_callbacks.end()) {
                    _msg_que.pop();
                    continue;
                }
                call_back_iter->second(msg_node->_session, msg_node->_recvnode->_msg_id,
                    std::string(msg_node->_recvnode->_data, msg_node->_recvnode->_cur_len));
                _msg_que.pop();
            }
            break;
        }

        //如果没有停服，且说明队列中有数据
        auto msg_node = _msg_que.front();
        cout << "recv_msg id  is " << msg_node->_recvnode->_msg_id << endl;
        auto call_back_iter = _fun_callbacks.find(msg_node->_recvnode->_msg_id);
        if (call_back_iter == _fun_callbacks.end()) {
            _msg_que.pop();
            continue;
        }
        call_back_iter->second(msg_node->_session, msg_node->_recvnode->_msg_id, 
            std::string(msg_node->_recvnode->_data, msg_node->_recvnode->_cur_len));
        _msg_que.pop();
    }
}
```

1   `DealMsg`逻辑中初始化了一个unique\_lock，主要是用来控制队列安全，并且配合条件变量可以随时解锁。lock\_guard不具备解锁功能，所以此处用unique\_lock。  
2   我们判断队列为空，并且不是停止状态，就挂起线程。否则继续执行之后的逻辑，如果\_b\_stop为true，说明处于停服状态，则将队列中未处理的消息全部处理完然后退出循环。如果\_b\_stop未false，则说明没有停服，是consumer发送的激活信号激活了线程，则继续取队列中的数据处理。

LogicSystem的析构函数需要等待工作线程处理完再退出，但是工作线程可能处于挂起状态，所以要发送一个激活信号唤醒工作线程。并且将\_b\_stop标记设置为true。

```
LogicSystem::~LogicSystem(){
    _b_stop = true;
    _consume.notify_one();
    _worker_thread.join();
}
```

因为网络层收到消息后我们需要将消息投递给逻辑队列进行处理，那么LogicSystem就要封装一个投递函数

```
void LogicSystem::PostMsgToQue(shared_ptr < LogicNode> msg) {
    std::unique_lock<std::mutex> unique_lk(_mutex);
    _msg_que.push(msg);
    //由0变为1则发送通知信号
    if (_msg_que.size() == 1) {
        _consume.notify_one();
    }
}
```

## 一、核心概念

- **定义**：逻辑层（Logic Layer）是服务器架构中与网络层分离的业务处理层，通过消息队列和回调映射表解耦网络 I/O 与业务逻辑，使得网络线程不被耗时业务阻塞
- **关键词**：单例模板（Singleton）、消息队列（`queue<LogicNode>`）、回调注册（`map<short, FunCallBack>`）、条件变量（`condition_variable`）、工作线程（worker thread）、生产者-消费者模型
- **适用场景/边界**：所有需要网络层与业务层分离的服务器架构。网络线程负责收发数据并投递消息，逻辑线程负责处理业务逻辑并回调

## 二、详细解析

- **原理拆解（三层递进）**：
  - **第一层——线程安全的单例模板**：`Singleton<T>` 用 C++11 `std::call_once` + `std::once_flag` 实现线程安全的懒汉单例，内部用 `shared_ptr<T>` 管理生命周期，通过 `SafeDeletor` 自定义删除器保证析构安全。禁用拷贝/赋值防止多实例
  - **第二层——消息队列驱动的逻辑系统**：`LogicSystem` 继承 `Singleton<LogicSystem>`，核心组件：`queue<LogicNode>` 消息队列 + `mutex` 互斥锁 + `condition_variable` 条件变量。网络层通过 `PostMsgToQue()` 投递消息（生产者），工作线程 `DealMsg()` 循环消费（消费者）。队列为空时 `condition_variable::wait()` 挂起线程避免 CPU 空转
  - **第三层——回调映射表的注册-分发机制**：`map<short, FunCallBack>` 按消息 ID 映射回调函数。`RegisterCallBacks()` 在初始化时注册所有业务处理函数。收到消息后 `DealMsg()` 根据消息 ID 查找回调并执行，实现命令模式的分发
- **关键数据结构/接口**：`FunCallBack = function<void(shared_ptr<CSession>, short msg_id, string msg_data)>`；`LogicNode` 封装 session + msg_id + msg_data；`PostMsgToQue()` 加锁入队 + `notify_one()` 唤醒工作线程
- **关键公式**：生产者-消费者吞吐量 = min(网络线程投递速率, 逻辑线程处理速率)；单工作线程保证消息顺序处理，多工作线程需按 session 分片避免乱序

## 三、动手实践

```c++
#include <queue>
#include <mutex>
#include <condition_variable>
#include <thread>
#include <functional>
#include <map>
#include <iostream>
using namespace std;

struct LogicNode {
    int msg_id;
    string data;
};

class SimpleLogic {
    queue<LogicNode> q_;
    mutex mtx_;
    condition_variable cv_;
    map<int, function<void(string)>> callbacks_;
    bool stop_ = false;
    thread worker_;
public:
    SimpleLogic() {
        worker_ = thread([this]{
            while (true) {
                unique_lock<mutex> lk(mtx_);
                cv_.wait(lk, [this]{ return !q_.empty() || stop_; });
                if (stop_ && q_.empty()) break;
                auto node = q_.front(); q_.pop();
                lk.unlock();
                if (callbacks_.count(node.msg_id))
                    callbacks_[node.msg_id](node.data);
            }
        });
    }
    void post(LogicNode n) {
        { lock_guard<mutex> lk(mtx_); q_.push(n); }
        cv_.notify_one();
    }
    void reg(int id, function<void(string)> cb) { callbacks_[id] = cb; }
    ~SimpleLogic() {
        { lock_guard<mutex> lk(mtx_); stop_ = true; }
        cv_.notify_one();
        worker_.join();
    }
};
```

### 多工作线程模型

### 背压控制（Backpressure）

```c++
void PostMsgToQue(shared_ptr<LogicNode> msg) {
    unique_lock<mutex> lk(_mutex);
    if (_msg_que.size() > MAX_QUEUE_SIZE) {
        // 队列满时丢弃或阻塞，防止内存爆炸
        return;  // 或 _consume.wait(lk, ...);
    }
    _msg_que.push(msg);
    lk.unlock();
    _consume.notify_one();
}
```

### 逻辑层与 asio 的协调退出

```c++
void Stop() {
    _b_stop = true;
    _consume.notify_all();  // 唤醒工作线程
    _worker_thread.join();  // 等待线程退出
    // io_context 也需 stop() 关闭网络层
}
```

**工程经验**：(1) 网络线程禁止做业务逻辑——哪怕一次数据库查询也会拖垮事件循环；(2) 条件变量使用 `wait(lock, predicate)` 而非 `wait(lock)` 防止虚假唤醒；(3) 优雅退出时先停止投递 → 等待队列消费完毕 → 通知线程退出 → join 等待。

## 五、源码解析和实践感悟

### 5.1 源码解析

#### 单例模板的线程安全实现

```c++
template <typename T>
std::shared_ptr<T> Singleton<T>::GetInstance() {
    static std::once_flag s_flag;
    std::call_once(s_flag, [&]() {
        _instance = std::shared_ptr<T>(new T, SafeDeletor<T>());
    });
    return _instance;
}
```

`std::call_once` + `std::once_flag` 保证初始化函数**精准执行一次**，多线程同时调用 `GetInstance()` 时其他线程会阻塞等待初始化完成。这是 C++11 后推荐的懒汉单例实现，比 DCLP（Double-Checked Locking Pattern）更安全简洁。

#### 条件变量的生产者-消费者模型

```c++
// 生产者：网络层投递消息
void LogicSystem::PostMsgToQue(shared_ptr<LogicNode> msg) {
    std::unique_lock<std::mutex> lk(_mutex);
    _msg_que.push(msg);
    if (_msg_que.size() == 1) {
        _consume.notify_one();  // 仅当队列从空变为非空时通知
    }
}

// 消费者：逻辑线程处理
void LogicSystem::DealMsg() {
    for (;;) {
        std::unique_lock<std::mutex> lk(_mutex);
        _consume.wait(lk, [this]{ return !_msg_que.empty() || _b_stop; });
        // 处理消息...
    }
}
```

关键优化：只在队列 `size() == 1` 时 `notify_one()`（从 0→1），避免每次 push 都通知（消费者正忙时不需要唤醒）。

#### FunCallBack 的回调注册表

```c++
std::map<short, FunCallBack> _fun_callbacks;
// 注册
_fun_callbacks[MSG_HELLO_WORD] = std::bind(&LogicSystem::HelloWordCallBack, this, _1, _2, _3);
// 分发
auto iter = _fun_callbacks.find(msg_id);
if (iter != _fun_callbacks.end()) iter->second(session, msg_id, data);
```

通过 `msg_id` 映射到处理函数，实现了消息动态路由。新增业务只需注册新的 id-function 对，无需改动核心循环。

### 5.2 实践经验

1. **逻辑层和网络层的解耦是通过消息队列实现的**，队列是性能瓶颈点——大量消息时需考虑无锁队列
2. **`unique_lock` 优于 `lock_guard`**：需要配合条件变量 `wait()` 时必须使用 `unique_lock`（支持解锁/重锁）
3. **优雅停机三件套**：设置 `_b_stop` → `notify` 唤醒线程 → `join` 等待线程退出
4. **回调注册在构造函数中**：确保线程启动前所有回调已就绪，避免工作线程查不到回调
5. **消息处理中的 `shared_ptr` 传递**：`LogicNode` 持有 `shared_ptr<CSession>`，防止 session 在处理前被销毁
6. **条件变量的虚假唤醒**：`while` 循环判断条件而非 `if`，应对虚假唤醒

## 六、面试准备

### 6.1 面试高频问答

**Q1：逻辑层和网络层为什么要分开？**

A：网络层处理高频 I/O 事件（微秒级），逻辑层可能涉及数据库查询、计算等耗时操作（毫秒~秒级）。不分离会导致逻辑处理阻塞 I/O 线程，影响其他连接的收发。

**Q2：`std::call_once` 如何保证线程安全？**

A：内部使用互斥锁+原子标志位。第一个线程获取锁执行初始化并设置标志，后续线程检查标志后跳过锁获取。C++ 标准保证异常安全。

**Q3：条件变量 `wait` 中为什么用 `while` 而非 `if`？**

A：条件变量可能被虚假唤醒（spurious wakeup）——线程被唤醒但条件未满足。`while` 循环确保唤醒后重新检查条件，防止错误的消费行为。

**Q4：`notify_one()` 只在 `size==1` 时调用的优化原理？**

A：消费者一次消费所有队列消息，只有当队列从空变非空时才需要唤醒消费者。如果消费者已在忙，额外通知是浪费（CPU 不会响应通知）。

**Q5：`unique_lock` 和 `lock_guard` 的区别？**

A：`lock_guard` 构造加锁析构解锁，不可手动控制。`unique_lock` 支持 `lock()`/`unlock()`/`try_lock()`，可与条件变量 `wait()` 配合（`wait` 需要临时解锁）。

**Q6：`LogicNode` 为什么持有 `shared_ptr<CSession>`？**

A：防止消息处理期间 session 被释放（如连接断开时从 map 中移除）。`LogicNode` 持有一份引用，处理完后自然释放。

**Q7：`_b_stop` 的作用？**

A：停机标志。析构时设为 true，配合条件变量唤醒工作线程，线程处理完残余消息后退出循环。

**Q8：如果消息队列无限增长怎么办？**

A：设置队列容量上限，达到上限时采用背压策略：阻塞生产者、丢弃旧消息、或淘汰低优先级消息。

### 6.2 陷阱与反问

**陷阱1**：条件变量 `wait` 用 `if` → 虚假唤醒导致访问空队列
**陷阱2**：停机时只设 `_b_stop` 不 `notify` → 工作线程永久阻塞
**陷阱3**：回调 map 在线程启动后动态注册 → 多线程数据竞争
**陷阱4**：`FunCallBack` 用裸函数指针而非 `std::function` → 不支持成员函数绑定
**陷阱5**：消息处理中异常未捕获 → 工作线程崩溃，逻辑队列停止消费

**反问**：如果逻辑处理速度跟不上网络层投递速度怎么办？
*答案：消息队列堆积 → 背压机制（让网络层暂停投递或拒绝新连接）、业务降级（丢弃非关键消息）、扩容逻辑线程（多消费者并行处理）。*

### 6.3 一句话答案

1. **网络层/逻辑层分离**：消息队列解耦，I/O 线程投递，业务线程消费
2. **std::call_once**：C++11 线程安全的一次性初始化原语
3. **条件变量**：生产者-消费者模型的核心同步原语，配合 `unique_lock` 使用
4. **虚假唤醒**：线程被系统唤醒但条件未满足，必须 `while` 循环检查
5. **FunCallBack 注册表**：`map<id, function>` 实现消息动态路由
6. **LogicNode**：封装 session + 消息的中间对象，防止 session 提前析构
7. **背压**：队列满时限制生产速率，防止内存无限增长
